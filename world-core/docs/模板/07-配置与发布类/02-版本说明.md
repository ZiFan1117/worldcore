> **文档编号**：`<项目代号>-RN-<版本号>-V<主版本>.<次版本>`

> - `docs/04-配置与版本/配置管理与版本化.md`——本仓库版本号与基线约定的落地细则；
> - GB/T 12505-90《计算机软件配置管理计划规范》——**1990 年老标准**，仅采其五要素框架（配置项标识、基线管理、变更控制、状态记录、配置审计），实现方式按现代工程实践。

## 2 版本类型与递增理由

### 2.1 语义化版本递增规则

| 位 | 名称 | 递增条件 | 示例 | 兼容性含义 |
|---|---|---|---|---|
| **MAJOR** | 主版本 | **不兼容**的接口 / 数据 / 行为变更 | `1.4.2` → `2.0.0` | ⚠️ 使用方**必须**适配 |
| **MINOR** | 次版本 | **向后兼容**的功能新增 | `1.4.2` → `1.5.0` | ✅ 可直接升级 |
| **PATCH** | 修订号 | **向后兼容**的缺陷修复 | `1.4.2` → `1.4.3` | ✅ 可直接升级 |

预发布后缀：`-alpha.N`（内测）→ `-beta.N`（公测）→ `-rc.N`（候选发布）。
构建元数据：`+build.NNN`（不参与版本比较）。

### 2.2 版本递增决策核对

| 变更性质 | 产品版本 | 框架版本 | 本次是否命中 | 说明 |
|---|---|---|---|---|
| 修 bug，契约不变 | PATCH | 不变 | ☐ | |
| 新增模块（不改既有契约） | MINOR | 可能 MINOR | ☐ | |
| 契约扩展字段（兼容） | MINOR | MINOR | ☐ | |
| 契约语义变更（不兼容） | **MAJOR** | **MAJOR** | ☐ | |
| 数据模型不兼容变更 | **MAJOR** | 可能 MAJOR | ☐ | |
| 仅文档 / 日志 / 配置默认值 | PATCH | 不变 | ☐ | |

> **框架版本与产品版本分离**：框架版本从 `v0` 起，用 `vMAJOR.MINOR` 两位。
> **不要过早宣布框架 v1.0**——一旦 v1.0 即意味着契约冻结，此后任何破坏性变更
> 都必须走完整变更流程并通知全部使用方。

## 10 填写指引（常见错误）

1. **版本类型与实际变更性质不符**——修了个 bug 却发 MINOR、加了新功能却发 PATCH，会让使用方无法判断升级风险。**每一次"契约语义变更"都必须是 MAJOR**，并逐条列出不兼容点。判定依据填在第 2.2 节的决策核对表。
2. **已知问题章节留空或只写"无"**——遗留缺陷与已知限制**必须如实列出**。交付后暴露的未声明问题会被视为质量缺陷，责任归属产生争议。P0/P1 若需带病发布，必须有甲方/产品**书面确认**，口头同意不构成批准。
3. **回滚方案只写"如有问题则回滚"**——这不是方案。必须写明**触发条件、回滚步骤、数据回滚处置、预计耗时、验证方式与决策人**。涉及**不可逆数据迁移**的变更，回滚可行性必须在发布前给出明确结论。
4. **制品记录缺哈希**——只写文件名与下载链接无法证明制品与其源代码的对应关系，也无法在部署后校验一致性。**每个制品必须记录 SHA-256 哈希**（容器镜像记录 digest）。
5. **变更列表缺少关联编号**——每项变更必须关联**变更编号 + 需求编号（或缺陷编号）**。缺少关联会导致追溯矩阵断裂，"这个版本到底改了什么"将无法回答。填完请跑 `python tools/trace_matrix.py` 验证。
6. **升级注意事项漏写配置与数据迁移**——新增/修改/废弃的配置项、是否需要数据迁移、是否可逆，这三项是最常被漏掉且最容易导致升级失败的内容。**迁移前必须先备份**，并写入升级步骤。
7. **文档漂移未核对**——若本版本包含框架变更，必须确认 HLD 与模块接口契约已同步更新。**代码改了文档没改**是配置管理失效的头号征兆，一旦文档不可信，整套追溯体系归零。

| 项 | 保守处理方式 | 原因 |
|---|---|---|

| **配置管理计划条目引用** | 第 8 章以**条目名称 + 占位章节号**的形式引用（如 `§<序号>`），**不预设具体章节编号** | 配置管理计划的章节结构由项目自行定义；预填编号会与项目实际文档不符 |
| GB/T 12505-90 | 明确标注为 **1990 年老标准**，仅采其五要素框架（配置项标识、基线管理、变更控制、状态记录、配置审计） | 该标准实质内容已过时（无持续集成、无制品仓库概念），实现方式按现代工程实践 |

| 制品哈希算法 | 统一采用 SHA-256（容器镜像用 digest） | 作为最低要求；若项目制品库另有约定可替换，但**不得省略哈希** |
