## 零、使用说明（填完全文后请删除本章）

### 0.1 本模板解决什么问题

接口是**最容易在集成阶段爆炸**的地方。原因几乎总是同一个：**接口只在"成功路径"上被定义过。**

本模板要求每个接口都必须写清 8 件事：**编号 · 类型 · 协议 · 数据格式 · 字段表 · 错误码表 · 幂等性 · 超时与重试 · 版本兼容策略**。
少写任何一项，S5 集成测试就会替你补课。

## 1 引言

### 1.1 编写目的

定义 `<项目名称>` 全部外部接口与关键内部接口的需求，作为接口设计、实现、联调、集成测试的**唯一基准**。

- **预期读者**：架构师、开发、测试、第三方系统对接人、运维；
- **用途**：接口基线化后，任何接口变更（含字段增减、错误码调整、超时调整）**必须走变更控制流程**，并同步更新本文档与需求追溯矩阵。

### 1.2 范围

| 项 | 内容 |
|---|---|
| 覆盖的接口类型 | 外部系统接口 / 系统与模块间内部接口 / 用户接口 |
| 覆盖的交互方式 | 同步调用（REST/RPC/SQL）、异步消息（MQ/事件）、文件交换（批量导入导出） |

## 2 接口通则需求（适用于全部接口）

| 编号 | 类别 | 需求内容 | 验证方式 |
|---|---|---|---|
| `IF-REQ-01` | 定义完整性 | 每个接口必须定义：编号、名称、类型、协议、数据格式、字段表、错误码表、幂等性、超时与重试、版本兼容策略 | 本文档自查表 |
| `IF-REQ-02` | 错误码 | 所有错误必须返回**业务错误码 + 可读消息**，禁止只返回 500 与堆栈 | 集成用例 |
| `IF-REQ-03` | 幂等 | 所有**写类**接口必须声明幂等性；非幂等接口必须提供幂等键（`Idempotency-Key`） | 集成用例（重复提交） |
| `IF-REQ-04` | 超时 | 每个接口必须定义**调用方超时**与**服务方处理上限**，且服务方上限 < 调用方超时 | 设计核查 |
| `IF-REQ-05` | 重试 | 重试策略必须显式声明（次数、间隔、退避），且**重试必须幂等** | 集成用例（注入超时） |
| `IF-REQ-06` | 兼容 | 接口变更必须声明兼容级别：兼容扩展 / 破坏性变更（需并行期与弃用通告） | 变更评审（R5） |
| `IF-REQ-07` | 安全 | 所有跨信任域接口必须鉴权与加密（HTTPS/TLS ≥ 1.2）；敏感字段传输与日志中必须脱敏 | 安全用例 |
| `IF-REQ-08` | 可观测 | 每个接口必须有唯一 `trace_id` 贯穿调用链，日志可关联 | 日志抽样 |
| `IF-REQ-09` | 限流 | 对外接口必须定义限流阈值与超限行为（`429` + `Retry-After`） | 压测用例 |
| `IF-REQ-10` | 时间与编码 | 时间统一 `ISO 8601` + 时区（如 `2026-02-14T10:00:00+08:00`）；字符集统一 UTF-8 | 契约测试 |

#### 3.2.1 `<IF-001>` 统一认证登录

##### 3.2.1.1 基本信息

| 项 | 内容 |
|---|---|
| **接口编号** | `<IF-001>` |
| **接口名称** | 统一认证登录 |
| **类型** | 外部接口（同步） |
| **方向** | 入（本系统调用统一认证平台） |
| **提供方 / 消费方** | `<外部系统 A>` / `<M20>`（业务层-认证服务） |
| **协议** | HTTPS / REST（`POST /api/v1/auth/login`） |
| **数据格式** | JSON（`Content-Type: application/json; charset=utf-8`） |
| **认证方式** | 服务间：双向 TLS + 应用凭证（`X-App-Id` + `X-App-Secret`）；本接口不涉及终端用户令牌 |
| **版本策略** | URL 版本号 `/v1/`；当前 v1，见 §3.2.1.8 |
| **支撑需求** | `<REQ-F-001>`、`<REQ-N-013>` |
| **关联设计模块** | `<M20>`（消费）、`<M60>`（适配层封装） |
| **状态** | 已定义 / 已确认（`<YYYY-MM-DD>`，与 `<第三方>` 联调确认） |

##### 3.2.1.2 请求定义

| 字段编号 | 字段名 | 类型 | 必填 | 取值范围/长度 | 说明 | 脱敏 |
|---|---|---|---|---|---|---|
| `IF-001-F01` | `account` | string | 是 | 6–32，`^[A-Za-z0-9_]+$` | 用户账号 | 否 |
| `IF-001-F02` | `password` | string | 是 | 8–64 | 用户口令（明文传输，靠 TLS 保护） | **是（日志掩码）** |
| `IF-001-F03` | `client_ip` | string | 否 | IPv4/IPv6 | 终端 IP，用于风控 | 否 |
| `IF-001-F04` | `captcha_token` | string | 否 | ≤ 256 | 连续失败 3 次后必填 | 否 |

**请求示例**

```json
{
  "account": "zhangsan",
  "password": "********",
  "client_ip": "10.20.30.40"
}
```

##### 3.2.1.3 响应定义

**成功响应（HTTP 200）**

| 字段编号 | 字段名 | 类型 | 必返 | 说明 |
|---|---|---|---|---|
| `IF-001-F10` | `token` | string | 是 | 会话令牌（JWT，HS256） |
| `IF-001-F11` | `expires_in` | integer | 是 | 有效期（秒），当前 7200 |
| `IF-001-F12` | `user.id` | string | 是 | 用户唯一标识 |
| `IF-001-F13` | `user.name` | string | 是 | 显示名 |
| `IF-001-F14` | `user.roles` | array[string] | 是 | 角色码列表，可为空数组 |

**失败响应（HTTP 4xx/5xx）**

| 字段编号 | 字段名 | 类型 | 必返 | 说明 |
|---|---|---|---|---|
| `IF-001-F20` | `code` | string | 是 | 业务错误码，见 §3.2.1.4 |
| `IF-001-F21` | `message` | string | 是 | 面向用户的可读消息（中文） |
| `IF-001-F22` | `trace_id` | string | 是 | 链路追踪 ID |
| `IF-001-F23` | `retry_after` | integer | 否 | 秒；仅在限流/锁定时返回 |

##### 3.2.1.4 错误码表

| 错误码 | HTTP | 含义 | 触发条件 | 调用方期望处置 | 是否可重试 |
|---|---|---|---|---|---|
| `AUTH-4001` | 400 | 入参格式错误 | 账号/口令长度或字符集不合规 | 修正入参，不重试 | 否 |
| `AUTH-4011` | 401 | 凭证无效 | 账号不存在**或**口令错误（**不区分**，防账号枚举） | 提示"账号或口令错误" | 否 |
| `AUTH-4012` | 401 | 令牌过期 | 会话超时 | 重新登录 | 否 |
| `AUTH-4231` | 423 | 账号锁定 | 连续 5 次失败，锁定 15min | 读 `retry_after`，等待 | 是（延时后） |
| `AUTH-4291` | 429 | 触发限流 | 单 IP > 100 次/分钟 | 读 `Retry-After` 退避 | 是（指数退避） |
| `AUTH-5001` | 503 | 认证服务不可用 | 下游超时/熔断 | 重试 1 次；仍失败则返回业务侧 503 | 是（≤ 1 次） |
| `AUTH-5002` | 500 | 服务内部错误 | 未预期异常 | 记录 `trace_id` 并报障 | 否 |

> **错误码规则**：错误码一经发布即为**对外契约**，不得改语义、不得复用。废弃错误码保留行并标注"已废弃"。

##### 3.2.1.5 幂等性

| 项 | 内容 |
|---|---|
| **是否幂等** | **否**（登录会刷新会话与失败计数） |
| **幂等键** | 不适用 |
| **重复调用影响** | 重复成功登录：生成新令牌，旧令牌仍有效至过期；重复失败：失败计数继续累加（**这是有意设计**，用于锁定策略） |
| **调用方约束** | 严禁对登录接口做**盲目自动重试**；仅在 `AUTH-5001`（服务不可用）时重试 1 次 |

##### 3.2.1.6 超时与重试

| 项 | 取值 | 说明 |
|---|---|---|
| 调用方连接超时 | 1s | |
| 调用方读超时 | 3s | **必须 > 服务方处理上限** |
| 服务方处理上限 | 2s | 由 `<外部系统 A>` 承诺 |
| 重试次数 | ≤ 1 | 仅对 `AUTH-5001` / 网络超时 |
| 重试间隔 | 500ms | 固定间隔（本接口无幂等键，不做指数退避堆积） |
| 熔断阈值 | 10s 内失败率 > 50% 且请求数 ≥ 20 → 熔断 30s | 熔断期间快速失败返回 `AUTH-5001` |
| 超限处置 | 超时即返回业务侧 `503`，**不得**无限等待 | |

##### 3.2.1.7 性能与容量要求

| 指标 | 要求 | 度量条件 |
|---|---|---|
| 响应时间 | P95 ≤ 500ms（含下游） | 50 并发，持续 10min |
| 吞吐 | ≥ 50 TPS | 同上 |
| 限流 | 单 IP 100 次/分钟；单账号 20 次/分钟 | 网关配置 |
| 可用性 | ≥ 99.9% | 月度统计 |

##### 3.2.1.8 版本兼容策略

| 项 | 内容 |
|---|---|
| 版本标识 | URL 路径版本 `/api/v1/` |
| **兼容扩展**（不升版本） | 新增**可选**请求字段；新增响应字段（消费方必须**忽略未知字段**）；新增错误码 |

#### 3.2.2 `<IF-007>` `<接口名称>`（异步接口填写示例骨架）

> 异步接口与同步接口的字段差异在「投递语义」「消费幂等」「死信处理」三项，其余字段相同。

| 项 | 内容 |
|---|---|

| **接口名称** | 任务状态变更通知 |
| **类型** | 外部接口（异步） |
| **方向** | 出（本系统发布，对端订阅） |
| **协议** | MQ（`<产品名>`）/ Topic `task.status.changed` |
| **数据格式** | JSON（消息体），Schema 见下 |
| **投递语义** | **至少一次（at-least-once）** —— 消费方必须幂等 |
| **分区键** | `task_id`（保证同一任务的状态变更有序） |
| **消息字段表** | 见下 |
| **幂等键** | `event_id`（UUID，全局唯一）；消费方须以 `event_id` 去重 |
| **重试与死信** | 消费失败自动重试 3 次（间隔 1s/5s/30s）；仍失败入死信队列 `task.status.changed.dlq`，告警并人工处置 |
| **积压告警** | 消费延迟 > 1000 条或 > 5min 触发告警 |
| **顺序保证** | 同一 `task_id` 内有序；跨 `task_id` 不保证 |
| **版本策略** | 消息体带 `schema_version`；兼容扩展不升主版本；破坏性变更需新旧双发并行期 ≥ 90 天 |

| 字段编号 | 字段名 | 类型 | 必填 | 说明 |

## 7 填写指引

1. **最常见错误：只定义成功响应。** 每个接口的「错误码表」至少覆盖四类：入参错误（4xx）、权限/认证错误（401/403）、依赖故障（503）、限流（429）。**没有错误码表的接口 = 没定义完的接口。**
2. **最常见错误：把幂等性写成"应该幂等"。** 必须明确二选一：**是/否幂等**；非幂等接口必须给出幂等键字段或明确写出"禁止自动重试"的约束。含糊表述在集成期必然引发重复扣款/重复创建一类事故。
3. **最常见错误：超时值拍脑袋，且调用方超时 ≤ 服务方上限。** 必须满足 `调用方超时 > 服务方处理上限`，否则调用方先超时重试，服务方还在处理，直接产生重复请求。
4. **最常见错误：接口改了不通知消费方、不改 RTM。** 任何破坏性变更必须走 R5 变更评审，提供 ≥ 90 天并行期，并同步更新本文档 §3.2.x.9、§3.1 清单表与 `03-需求追溯矩阵.csv`。
5. **最常见错误：接口清单表与详细定义不同步。** 清单表是总账，详细定义是明细；新增接口**必须先登记编号**，废弃接口**必须保留行并标注替代接口**，编号永不复用。
6. **最常见错误：把内部接口排除在外。** 模块间内部接口同样要定义错误码与契约，其落地形态是 `../03-设计类/03-模块接口契约.md`；本文档与契约文件的接口编号必须一一对应。
