# 第二、三章 · 逐节落点（调查结论）

> **与机抽四源分开**：本文件只写"逐节调查"的结论。**"提到过"不算落点**；**没做的写"没有"**。
> 调查员声明：引文逐字取自合订本，**原文自带的加粗标记一律去掉**（只去标记、不改字），**他自己没加任何强调**。
> 检索面＝`openspec/`、`world-core/src|tests|tools|docs|cap.d`、`agentd`（仓根 `refs/`、`omarchy/` 是上游参考，不计入"本项目"）。

### 2.1 那个位置
- **书里说什么**（逐字 `:195`）：「这三条合起来，就是这一层在最简形式下的样子：一个除了承载说法以外什么都不做的位置。」（第三条特征 `:193`：「它不居中调停，只承载」）
- **登记**：书内。
- **落点**：**一处规格级同义对应**——`ledger-integrity` spec 逐字「它不主张结果正确，只主张"当时写的是什么"可以核。」（对上第三条特征；**性质是同义，不是逐字落点**）；
  **一处流程文档**——`WC-HLD-001` 逐字「不是应用，是地基…」（**但那句内容属 2.2**）＋ `WC-SRS-001` 同口径。
  **代码／断言：零**。正面定义那一半（"由各方共同依赖、人/agent/机器都写进同一处的那一处"）：**规格树零落点**——`rg -F 共同依赖 openspec/specs` ⇒ **rc=1（0 命中）**。
- **判定**：**部分落点**——缺"这一处＝各方共同依赖的位置"这个**正面定义**本身。`共同依赖` 全仓非书命中**只有 5 处，全在书的派生件**（`openspec/generated/specmap.json`／`docs/理论/尺子-理念条目.md`）。

### 2.2 它为什么不能是库、协议、应用
- **书里说什么**（逐字 `:215`）：「这一层不能是一个库、不能是一套协议、也不能是一个应用。…它们都活在使用者的边界以内，而这个位置必须在所有使用者之下。」（`:217`「它只能落在系统层」）
- **登记**：书内。
- **落点**：**流程文档（唯一有实体）**——`WC-HLD-001` 逐字「不是应用，是地基：世界核心是载体上的一个一等组件（与 systemd 同层），不是"跑在应用里的一个库"。」（**一句同时覆盖"不能是应用"与"不能是库"**）；`WC-SRS-001` ／`WC-FSR-001` 逐字「部署形态：载体上的一个一等组件（系统服务层，与 systemd 同层），**非应用层**」。
  **规格要求：零**（`系统层`／`使用者`／`不能是一个库` 在 `openspec/specs` 全 **rc=1**）。**断言：零**（"不是应用层"是文档定位声明，**没有任何会红的检验盯着它**）。
  **"不能是一套协议"这一半：项目侧无此主张**——只有三处**同词异义**（拒绝把 MCP/A2A/varlink 当世界协议／"不是协议级"＝配对字段层级／把世界协议列入范围外）。
- **判定**：**部分落点**（缺"协议"那一半；且落点**全在流程文档层**，规格树与断言面为空）。

### 2.3 三个名字
- **书里说什么**（逐字读出三个名字）：`:223`「**世界**是这一层本身：那个各方共同依赖、由它承担说法的地方。」／`:225`「**语义事件**是世界里的一条记录。…某家软件自己记的日志行是它之外的东西。」／`:227`「**语义系统**是接进来的那些软件系统的统称。…这个名字划的是接口」＋`:229`「三者是同一个东西的三个面」；另有两个"差一点"的名字（`总线`／`平台`）。
- **登记**：书内。
- **落点（三个名字分开判）**：
  1. **世界** → **只有名字、没有定义**。名字遍布（`ontology.json` 的 `"world": 1`、信封必填 `world`、`World::commit`），但**定义零落点**：`WC-SRS-001` §1.3 术语表**无"世界"行**（rc=1）。
  2. **语义事件** → **有落点（四类都在）**：`ledger-integrity` spec 逐字「系统 SHALL 把每一条语义事件按 `seq` 升序追加进同一本账…」；`WC-SRS-001` 术语表逐字「世界的唯一真相载体，`change`/`act`/`notice` 三家族之一」；`src/common/event.rs`／`src/ontology_instance/readmodel.rs`；断言 `acceptance.rs::t1_append_then_read_back`／`contract.rs::c05`。**但 `:225` 那半句"某家软件自己记的日志行是它之外的东西"零落点**。
  3. **语义系统** → **零落点**：全仓非书**仅 1 命中**，且在**书的派生尺子**里；`openspec/specs` 下 **rc=1**。
- **判定**：**部分落点**（逐名分开：语义事件＝有；世界＝"提到"级、无定义；语义系统＝零）。**不把"世界这个名字遍地用"当成它的定义落了点。**
- **★ 附带（命名冲突，不是落点）**：**"总线"项目侧在用**——`WC-SRS-001` 逐字「本项目负责**存（账本+本体）· 传（总线）· 显（投影）· 管（门禁）**」、`WC-FSR-001` 逐字「**账本** | 语义事件的只追加持久化形态（= 主线 = **总线**）」等；而书 `:235` 把"总线"点名为**"差一点"的名字**。**"平台"** 的项目侧 21 处非书命中**全是"非 Linux 平台"异义**。

### 3.1 多方同时在场时，意思只能由共同依赖的那一层承担
- **书里说什么**（逐字 `:423`）：「**命题**：这种时候，"同一件事是什么意思"只能由各方共同依赖的那一层承担。」
- **登记**：书内。
- **落点**：**零**——规格（`共同依赖`／`同时在场`／`多方` 在 `openspec/specs` **全 rc=1**）／代码／断言**三面全零**；流程文档只有"多方在场"的**事实陈述**（`WC-FSR-001` 的"状态被多方读取"／"并发用户数 人 1 + agent 1…无并发"），**没有那个命题**。
- **判定**：**零落点**。⚠ 分寸：按书 3.3 自己的规矩"前提不成立时不表态"，**零落点在这里不等于缺陷**，但**读数本身成立**。

### 3.2 什么情况下这一层不必要
- **书里说什么**（逐字 `:475`）：「于是失效条件可以写得很短：各方共享同一套来源时，这一层不必要。」
- **登记**：书内。
- **落点**：**零**——规格（`不必要`／`规范` 在 `openspec/specs` **rc=1**）／代码／断言**三面全零**；流程文档也**不谈**这条失效条件（`WC-FSR-001` 的四个备选方案 A/B/C/D **全是架构路线之别**，没有一条是"各方共享同一套来源"）。`同一套来源` ⇒ **8 命中全在书里（非书 0）**。
- **判定**：**零落点**。⚠ 射程：`规范` 一词在项目侧命中太多，调查员**只核了 `openspec/specs` 的 0 命中**与 `同一套来源`（非书 0），**没有穷举同义改写**——所以这条"零落点"的强度是"按书的用词与近义串搜过、无命中"，**不是"全部同义改写都排除了"**。

### 3.3 这一条今天有几分分量
- **书里说什么**（逐字 `:487`）：「**本书最强的那条论证，在今天这个形态里处于不表态状态。**」／`:489`「**这一条今天挡不住"多方共用的规范"这一路，得记下来。**」
- **登记**：书内；项目侧**前半句有落点、后半句零**。
- **落点（前半句"前提不成立／必要性未证"）**：**全在 change／评审层，规格树零落点**——`冲突总账` 是**唯一按节号点名"书 3.3"的对齐行**（逐字「**必要性（书 3.3）** | **处处自设警戒，未被当成已证**」，⚠ 它引的 `review.md:40` **已漂**、实际在 `:46`）；`baseline-verified-doctrine` 的 `review.md` 逐字「尤其：**不得被引用为"语义已核"，也不得被引用为"必要性已证"。**」＋ `design.md` 逐字「**本基线不含"必要性"**…规格不得被引用为"必要性已证"。」＋ `tasks.md` 逐字「…规格文件里检索 `必要性|必须存在|应当存在` 命中 0 处」；形态声明＝`WC-SDP-001` 把「④ 联邦 / 多机 / 多用户」列进「**明确不包含**」栏；**现取**：`rg -F 必要性 openspec/specs` ⇒ **rc=1（0 命中）**。
- **落点（后半句"挡不住多方共用的规范"）**：**零**（`多方共用` 非书仅 1 命中，就是尺子）。
- **判定**：**部分落点（弱）**——前半句是**文档/流程侧警戒语**（可核，但**不是承诺、不是断言**：**没有任何检验会因"有人把基线当必要性已证"而变红**）；后半句零。
