# worldcore · 语义世界 / Semantic World

> **一个世界，说法只有一份。** / **One world, one vocabulary.**

本仓的**前门只讲理念**：这件事为什么做、主张什么、结构长什么样。实现、进度、判据读数，不写在这里。

---

## 一、为什么会有这件事

今天的操作系统只认「**进程、文件、权限**」。它不认「**谁**、**能干什么**、**干了什么**、**长什么样**」。

于是每接一个新东西——一个智能体、一个应用、一台机器——都要重新谈一遍「我们怎么说话」。

**每接一次，谈一次。**

## 二、主张

把「说法」这一层单独做出来：

- 一个世界里，**说法只有一份**，谁接进来都按它说；
- 谁说了什么、谁允许的、排在第几笔，**记在一本账上**，事后查得到；
- **正式结论与签字只有人能下**，机器只出发现。

**不是又一个系统**，而是所有系统都得照着说的那一层：语义核（本体）＋ 一条唯一写路径 ＋ 一本只增不改的账。

## 三、本体只做四件事

**认 · 盖章 · 转 · 记。** 它自己不执行、不渲染、不碰机器。

## 四、四条不许破的线

1. **换掉载体，说法不变**：换一种启动方式、换一种运行环境，法与账应逐字节不变；
2. **依赖单向**：应用可以依赖这一层；**这一层不许依赖任何应用**；
3. **接入只有一个入口**：外部接进来只有「口 ＋ 翻译」一条路，不许另开写路径；
4. **因果与许可不许用载体机制表达**：因果落在账本，许可落在法律。

前两条合起来：**它在下面，不在上面。**

**两个中心**：交互面（对人怎么说）＋ 能力接口（谁能做什么、记没记）。  
**三种模式**是两条并联的线；**Agent 是并联客户端**，不是第三层。  
**GUI 是三种模式共用的操作、监督与交接面**——不是人类模式专属。

## 六、与老系统的分工

老系统把「机制」做得很好，但它们各管一段：

- **D-Bus**：接口在服务侧自描述，总线只路由——**没有受理、没有版本/风险、没有审批**；
- **polkit**：能力名带命名空间、按名字授权——**只决定不强制、主体只有本地用户**；
- **portal**：应用不直连底层、统一走门——**只对沙箱应用成立**。

**没有一家把「名册 ＋ 授权 ＋ 凭证 ＋ 账」连成一条线。**

我们**不自造机制**：执行、传输、约束、日志，尽量复用它们；
我们做的是那根线：**把说法与凭据收拢到一处**——动作名册、一次性凭证、一本只增不改的账。

## 七、不做什么

- **不替换内核**，不重写进程、文件、权限；
- **不「懂」意思**：只固定形式，理解在各方；
- **不判断好坏**：只记下这件事是什么；
- **不补领域知识**：订单、告警、工序这类概念各自在命名空间里长；
- **不要求一次搬进来**：旧的一套不动；新的一套可选。

## 八、怎么判它做对了

1. **同一件事只有一种写法**：写完不回头改；要改就再写一条；撤销也是再写一条；
2. **只拿它，就能在别处算出同一份状态**：把它单独搬到另一处，「现在是什么样」必须一致；
3. **七问出得来**：谁做的 · 对什么做的 · 从什么变成什么 · 因为什么才发生 · 排在第几位 · 谁允许的 · 什么单位。

出不来，即该格仍空着。
