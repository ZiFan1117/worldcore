## §4 C 效果·转移派（效果／转移写在动作或方程里）

### §4.1 PDDL（含 STRIPS／ADL）

- **它把操作叫什么**：`action`——`(:action <名> :parameters (...) :precondition (...) :effect (...))`。
- **必备构件**：参数 ＋ **前置条件** ＋ **效果**；STRIPS 给最基本的加删效果，ADL 加条件效果／量词／类型。
- **权限写不写进模型**：**不写**（PDDL 没有主体、许可一类构件；`requirements` 声明的是语言特性，如 `:strips`／`:adl`／`:typing`）。
- **「算」与「改」**：**不分家**——效果就是动作声明的一部分；规划器**离线预测**动作效果来搜解。
- **出处**：Kovacs, *Complete BNF description of PDDL 3.1*, 2011，<https://helios.hud.ac.uk/scommv/IPC-14/repository/kovacs-pddl-3.1-2011.pdf>；STRIPS：Fikes & Nilsson, IJCAI-71，DOI `10.5555/1622876.1622939`；ADL：Pednault, KR'89，<https://cir.nii.ac.jp/crid/1573105975815283200>。**核对**：三个 URL／题录已核（可达）；**PDDL 3.1 的 BNF 正文未逐字读** ⇒ 语法行标**部分核**。

### §4.2 fUML／SysML

- **它把操作叫什么**：`Action`（动作，落在 `Activity` 里）；fUML 是 UML 的**可执行子集**。
- **必备构件**：Activity／Action ＋ 控制流与对象流 ＋ fUML 的执行语义（token 流与动作执行规则）。
- **权限写不写进模型**：**不写**——访问控制不在 fUML／SysML 射程（**未逐字通读规范 ⇒ 扫描面内未见**）。
- **「算」与「改」**：**不分家**——执行即改（执行语义把动作与状态变化绑在一起）。
- **出处**：OMG, *Semantics of a Foundational Subset for Executable UML Models (fUML) 1.4*，<https://www.omg.org/spec/FUML/1.4/>；OMG, *Systems Modeling Language (SysML) 1.6*，<https://www.omg.org/spec/SysML/1.6/>。**核对**：两规范页 URL 已核；**正文未逐字读** ⇒ 标**部分核**。

### §4.3 DEVS

- **它把操作叫什么**：**转移**（transition）——原子模型由内部转移／外部转移 ＋ 时间推进（time advance）定义。
- **必备构件**：状态集合 ＋ 内部转移 δint／外部转移 δext／输出函数 λ／时间推进 ta；耦合模型把它们连起来。
- **权限写不写进模型**：**不写**（不在形式化里）。
- **「算」与「改」**：**不分家**——状态转移函数本身就是"改"，事件驱动。
- **出处**：DEVS 形式化的书面依据（Carleton 大学论文 PDF，逐字"The Discrete Event System Specification (DEVS) formalism invented by Bernard Zeigler"）<https://cell-devs-02.sce.carleton.ca/publications/2018/Oye18/oyelowo-modelingandsimulationforassessingtheriskof_compressed.pdf>；书：Zeigler, *Theory of Modelling and Simulation*, 1976。**核对**：该 PDF 已核（逐字读到上句）；**1976 年原书题录本席未从书目面核到** ⇒ 书那一格标**未校验**（DEVS 名称与作者由上面那句支撑）。

### §4.4 Petri 网

- **它把操作叫什么**：**变迁**（transition）——结构 `(P, T, F)` 里 `t ∈ T` 在 enabled 时 firing。
- **必备构件**：place／transition／arc（流关系 F）＋ marking（托肯分布）；行为＝marking 的变迁序列。
- **权限写不写进模型**：**不是语言构件**（可以用托肯当"权标"编码，那属建模技巧）。
- **「算」与「改」**：**不分家**——点火即改 marking。
- **出处**：C. A. Petri, *Kommunikation mit Automaten*（1962 学位论文；作者履历页 <https://www2.ae-info.org/ae/Member/Petri_Carl_Adam/CV>）；网结构记法（P/T/F、preset／postset）<https://www.sciencedirect.com/topics/computer-science/petri-net>。**核对**：两个 URL 已核（可达）；**1962 学位论文原件的书目题录本席未核到** ⇒ 该格标**未校验**（"Petri 网"名称与作者由履历页支撑）。

### §4.5 Modelica

- **它把操作叫什么**：**没有"操作"这个一等概念**——模型是**方程**（equation）与**算法**（algorithm）；离散事件落在 `when` 子句里。
- **必备构件**：变量／参数／方程 ＋ `when` 事件子句 ＋ 求解器语义（陈述式、非因果）。
- **权限写不写进模型**：**不写**（不在语言里）。
- **「算」与「改」**：**不分家**——解方程即得状态；事件触发即改。
- **出处**：*Modelica Language Specification 3.6*，<https://specification.modelica.org/maint/3.6/MLS.html>；`when` 参考页 <https://doc.modelica.org/Modelica%203.2.3/Resources/helpWSM/ModelicaReference/ModelicaReference.'when'.html>。**核对**：两个 URL 已核；**规范正文未逐字读** ⇒ 标**部分核**。

### §4.6 FMI／FMU

- **它把操作叫什么**：接口调用（如 `doStep`）——FMU 暴露**变量**与仿真控制；"操作"是接口，不是本体构件。
- **必备构件**：模型变量（输入／输出／参数）＋ 仿真控制函数 ＋（3.0 起）时钟（clocks）等。
- **权限写不写进模型**：**不写**（不在标准里）。
- **「算」与「改」**：**不分家**——推进仿真即改 FMU 内部状态。
- **出处**：*Functional Mock-up Interface Specification 3.0.1*，<https://fmi-standard.org/docs/3.0.1/>；发布记录 <https://fmi-standard.org/news/2023-10-07-fmi-3.0.1-released/>。**核对**：规格页与发布记录已核；**正文未逐字读** ⇒ 标**部分核**（"3.0 起有时钟"按发布面写，**未逐字核条款号**）。

## §5 三个判据的横向读数

| 体系 | ① 操作＝可调用单元？ | ② 权限写进模型？ | ③「算」与「改」分家？ |
|---|---|---|---|
| Foundry Action Type | 是（动作类型） | **写**（Permissions／提交条件） | 不分（函数可改本体） |
| OPC UA Method | 是（Method／Call） | **写**（`UserExecutable` 必备属性） | 不分（调用既可算也可改） |
| TOVE | 是（activity） | **写，但分列**（Authority/Empowerment 一节） | 分（本体答问、执行在外） |
| BFO | 否（occurrent／realizable） | 不写（核心无） | 不适用（无执行语义） |
| OBI | 否（planned process） | 不写 | 不适用 |
| PSL | 否（activity） | 不写（不在射程） | 不适用 |
| OPM | 否（process） | 不写 | 不适用 |
| DOLCE | 否（perdurant） | 不写（核心无；D&S 未校验） | 不适用 |
| PROV-O | 半（Activity 是事件，不是可调用单元） | 不写（有 Role，但不判能力） | 半（记录与过程分家，但不只追加） |
| BPMN 2.0 | 是（Activity／Task） | 不写（扫描面内未见） | 分（模型 vs 引擎状态） |
| PDDL／STRIPS／ADL | 是（action） | 不写 | **不分**（效果写在动作上） |
| fUML／SysML | 是（Action） | 不写 | **不分** |
| DEVS | 否（transition） | 不写 | **不分** |
| Petri 网 | 否（transition） | 不写 | **不分** |
| Modelica | 否（方程／事件） | 不写 | **不分** |
| FMI／FMU | 半（接口调用） | 不写 | **不分** |

> 表里的"不写"受该体系自己的核对程度限制：凡正文未逐字读者，一律按**扫描面内未见**读（**未校验 ≠ 没有**）。
