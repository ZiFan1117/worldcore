## §2 总体设计

### 2.1 架构分层（L1–L4）

> ⚠ **层号提醒**：本节 `L1`–`L4` 是**实现分层**（法律与事实／状态／治理与机制／出口），
> **与《语义世界》书里的 `L1`–`L6` 判别线（问题／规格／命题／机制／兑现／未定）不是同一套编号**。
> 两套里 `L2` 正面错位（本表的 `L2`＝状态层，书的 `L2`＝规格层）⇒ 跨文档引用时必须写明是哪一套。

```text
L4 出口        M06 语言投影      M07 视觉投影        ← 只读；彼此不交互
L3 治理与机制   M04 运行时（唯一写入口）· M05 门禁 · M09 通道  ← 唯一写入通道
L2 状态        M03 读模型        M08 检查点          ← 由 L1 算出；不得写 L1
L1 法律与事实   M01 本体 · 门禁策略 · M02 账本        ← 最终依据
```

出处：`设计-WC-MODREG-001-v0.1.md` §2.1（层的含义与允许依赖）、§二（`M01`–`M09` 逐模块的「层」列）；
分层图的同源表述见 `设计-WC-HLD-001-v0.1.md` §2.3。
层间**硬约束**（违反即设计级缺陷，逐条出处 `设计-WC-MODREG-001-v0.1.md` §三）：

1. **L2/L4 不得写 L1**：读模型与投影都不能改账本（`REQ-F-012`）；
2. **L3 是唯一写入通道**：`World::commit` 之外没有第二条写路径（`REQ-F-006`，类型级保证见 `src/lib.rs:57-62`、`src/ledger/mod.rs:286` 的 `pub(crate)`）；
3. **L4 之间不交互**：两个投影只接受 `(&State, world, vocab)`，无共享可变状态（`REQ-F-020`，`src/gui_projection/language.rs:22`、`src/gui_projection/visual.rs:29`）；
4. **M05 不得依赖 L4**：门禁不关心"谁会看到"，只关心"能不能做"。

### 2.4 模块依赖与「无循环依赖」

**判据命令**（只读，可复算）：

```bash
rg -n '^\s*(pub |pub\(crate\) )?use (crate|super)::|crate::[a-z_]+' src --glob '*.rs'
# 2026-09-27 补：上一条对**裸模块路径**与 **`world_core::`（bin→lib）全盲**，须并跑下一条（两条合起来才覆盖全部生产跨模块引用）
rg -n 'use (world_core|gate|ledger|ontology|readmodel|event|guard|checkpoint|channel|project)::' src --glob '*.rs'
```

**观察所得的生产代码依赖边**（`#[cfg(test)]` 模块内的 `use` 不计；文档注释里的 `crate::` 链接不计）：

**结论（可复算的拓扑序见证）**：把上表当作有向图（边＝调用方 → 被调方）做 Kahn 剥层，得到
`{M03, M05} → {M01, M02, M06, M07, M08} → {M04} → {M09}`（**2026-09-27 复算值**：9 个模块全部剥离 ⇒ 无环），九个模块全部被剥离
⇒ **不存在循环依赖**（`M05` 无出边，是汇聚点；`M03` 在生产代码中无出边）。
**一处须登记的差异**：`设计-WC-MODREG-001-v0.1.md` §二 把 `M05` 的依赖模块记为「`M01`（家族/字段）」、
§三 记「`M01` → `M05`：无」，而源码的实际方向是 **`M01` → `M05`（静态墙）**，且 `src/gate/mod.rs` 未引用本体。
该差异**不构成环**（两个方向都不是双向边），但登记表与代码的方向需对齐。

### 3.1 边界为什么划在这里（只补理由，不复述登记表）

| 边界 | 划在这里的理由 | 出处 |
|---|---|---|
| 本体 ↔ 账本 | 一个管"什么算合法"，一个管"发生过什么"。合在一起会变成"账本自己解释自己"，回放历史时无法判断当时用的哪版法律 | `设计-WC-HLD-001-v0.1.md` §三 |
| 读模型 ↔ 账本 | 读模型是派生物。若允许它写账本，它就从投影升格成第二个真相 | 同上（`REQ-F-012`） |
| 门禁 ↔ 本体 | 本体管**形状**，门禁管**权限**。混在一起会让"字段合法但无权执行"无处安放 | 同上 |
| 两个投影各自成模块 | 输出格式是**独立契约**，合号会掩盖变更影响面 | `设计-WC-MODREG-001-v0.1.md` §一 理由 1 |
| 检查点独立成模块 | 它是**性能缓存**而非真相派生；边界清晰才能查"缓存有没有偷偷变成第二真相" | `设计-WC-MODREG-001-v0.1.md` §一 理由 2 |
| 通道独立成模块 | 通道面对的是**本机其他进程**，与进程内装配不是一件事；合号会掩盖安全边界的变更 | `设计-WC-MODREG-001-v0.1.md` §一 理由 3 |

### 二、总体设计

#### 2.1 定位

**不是应用，是地基**：世界核心是载体上的一个**一等组件**（与 systemd 同层），
不是"跑在应用里的一个库"。载体只知道启动它，不知道它是什么。

#### 2.2 设计目标与四条纪律

| # | 纪律 | 设计落点 |
|---|---|---|
| 1 | **一个进程** | 本体/账本/读模型/运行时/门禁同进程（`M01`–`M05`），不拆 |
| 2 | **一个写入口** | `World::commit` 是唯一写入路径；`Ledger` 的落笔能力字段私有（现为 `sink`，`Box<dyn Sink>`，`src/ledger/mod.rs:79`），**类型级**保证；`Ledger::append` 亦为 `pub(crate)`、不再是公开 API（`src/ledger/mod.rs:286`） |
| 3 | **法律在前、落笔在后** | `commit` 内顺序固定：取号→造事件→**法律校验**→**门禁裁决**→落笔 |
| 4 | **状态是算出来的** | 读模型自身**零持久形态** ⇒ 结构上不存在"读模型与账本不一致"；**唯一的持久缓存是 `M08` 快照**，其"不是第二真相"的地位由 §4.5 的不变量（带 `base_seq`、可核验、删掉可重算）保证，不由约定保证 |

第四条是**用"慢"换"不可能错"**：每次读状态都从头折叠账本。
在 v1 的数据规模下这是划算的（见 §4.5）。

#### 2.3 分层（L1–L4）

```text
L4 出口        M06 语言投影      M07 视觉投影        ← 只读；彼此不交互
L3 治理与机制   M04 运行时（唯一写入口）· M05 门禁 · M09 通道  ← 唯一写入通道
L2 状态        M03 读模型        M08 检查点(已实现)  ← 由 L1 算出；不得写 L1
L1 法律与事实   M01 本体 · 门禁策略 · M02 账本        ← 最终依据
```

> `M09` 通道是**跨进程入口**，其写入一律经 `M04` 的 `World::commit`（§6.3），
> 故与 `M04`/`M05` 同层（L3）。模块号与层的完整登记见 `WC-MODREG-001` §二/§2.1。

层间硬约束见 `WC-MODREG-001` §三。**这四条约束的违反方式都是"看起来更省事"**，
所以它们必须由测试与静态墙来守，不能靠自觉。

#### 2.4 运行形态

| 项 | 设计 |
|---|---|
| 进程模型 | 单进程、单可执行文件；`main.rs` 只做参数解析与子命令分发 |
| 配置来源 | 三个**显式路径**：`ontology.json` / `policy.json` / `ledger.jsonl`（无隐藏默认） |
| 交互方式 | CLI 子命令（`check` / `kinds` / `policy` / `append` / `read` / `state` / `project`） |
| 退出码 | `0` 成功 / `1` 用法错误 / `2` 法律、账本、门禁、读模型或投影错误 |
| 对外协议 | **纯文本**（JSON Lines / JSON）；不引入二进制序列化（`REQ-N-001`） |

### 三、模块划分

九个模块及职责见 `WC-MODREG-001` §二（本文件不重复登记表，避免两处维护）。
本节只补**模块边界为什么划在这里**：

| 边界 | 划在这里的理由 |
|---|---|
| 本体 ↔ 账本 | 一个管"什么算合法"，一个管"发生过什么"。合在一起会变成"账本自己解释自己"，**回放历史时无法判断当时用的哪版法律** |
| 读模型 ↔ 账本 | 读模型是**派生物**。若允许它写账本，它就从投影升格成第二个真相（`REQ-F-012` 用测试锁死"折叠不改账本一个字节"） |
| 门禁 ↔ 本体 | 本体管**形状**（字段对不对），门禁管**权限**（这件事能不能做）。混在一起会让"字段合法但无权执行"这类情形无处安放 |
| 两个投影各自成模块 | 见 `WC-MODREG-001` §一 理由 1：输出格式是**独立契约**，合号会掩盖变更影响面 |
| 检查点独立成模块 | 它是**性能缓存**而非真相派生；边界清晰才能查"缓存有没有偷偷变成第二真相" |

### 四、关键设计决策

#### 4.1 门禁默认拒绝 + 按不可逆性加摩擦

- **决策**：`policy.json` 的 `capabilities` 里**没有**的能力一律不放行；
  可逆动作免检但留痕；**不可逆动作只允许 `irreversible_actors` 白名单主体执行**，白名单外的主体拿到 `AwaitApproval`（加摩擦；理由明说 v1 无审批通道——见 `DEBT-07`）。
- **理由**：默认允许的系统，其安全性等于"没人写错规则"——而规则一定会写错。
  加摩擦则针对真正不可挽回的事（如压缩账本、换密钥），
  而不是给所有动作统一上枷锁（那会让人绕过门禁）。
- **被否方案**：① 默认允许 + 黑名单——漏写一条就是永久漏洞；
  ② 所有动作都要批准——摩擦过大会逼出"批量批准"这种反模式。
- **代价**：新能力上线必须显式登记，初期会觉得"麻烦"。这是**有意为之的麻烦**。

#### 4.2 静态墙同时看**文件**与**目录**，不合格即拒绝启动

- **决策**：`policy.json` 与账本，各自要求"文件不可被 group/other 写"
  **且**"所在目录不可被 group/other 写"；任一条不满足 → 拒绝启动。
- **理由**：只锁文件挡不住"删掉再放一个新的"——**目录权限才是
  『这条法律能不能被整体换掉』的真正答案**（`WC-CON01-001` §二 ② 是实测证据）。
  拒绝启动而非告警：一个"以为自己有门禁"的世界比一个明确拒绝启动的世界危险得多。
- **被否方案**：① 只查文件；② 仅打印警告继续运行——警告会被忽略，
  而代价不可逆。
- **代价**：部署时目录权限必须正确（如 `/var/lib/world` 需 0755 且属主为世界核心的 uid）。
  这构成一条**部署要求**，已写入 §7.3。

#### 4.3 法律与真相的路径必须显式传入

- **决策**：`World::open(ontology, ledger, policy)` 三个参数全部必填，**不设隐藏默认值**。
- **修订（依评审 F-03，2026-09-26）**：**库 API** 不设默认；**CLI 入口层**保留三个文档化默认路径
  （`./ontology.json`、`./ledger.jsonl`、`./policy.json`），**但每次启动必须把生效路径打印出来**
  （`check` 已打印本体/门禁/账本三行），使"实际读的是哪一份"当场可见。
  否则原文的"命令行更长"这一代价无法兑现——因为实现里根本没有取掉默认值。
  ⚠️ 仍存的不一致（**已就地核对实现，逐处给行号**）：`check` 打印本体/门禁/账本三行
  （`src/main.rs:123-142`）、`policy` 打印策略路径（`:169-173`）、`state` 打印账本路径（`:212`）、
  `project check` 打印词表身份（`:326-333`）；而 **`append`（`:252-286`）、
  `project language|visual`（`:313-319`）不打印任何生效路径**，
  且 `read`（`:349-371`）与 `kinds`（`:235-250`）亦不打印——
  即"每次启动必须把生效路径打印出来"这句话**对 4 个子命令（`append`/`read`/`kinds`/`project`）不成立**。
  另注：本项目**没有 `--version`**（`src/main.rs:45-78` 只认
  `--ontology/--ledger/--policy/--owner-uid/--require-chain/-h/--help`），
  故"版本自证"只能靠 `check` 的第一行本体路径。
  此项已登记为 **§十 待定项 6**（含责任人、判据与关闭时点），故 §4.3 的 `F-22` 指向**不再是悬空引用**。
- **理由**：门禁的全部强度都建立在"法律来自哪里"之上。
  若提供隐式默认路径，就可能出现"我改了 `/etc/world/policy.json`，
  但它其实读的是 `./policy.json`"这类**看起来生效、实际没生效**的事故。
- **被否方案**：默认 `./policy.json` 并在缺失时内置一份"宽松默认"。
  这是最危险的一种方便——**它让门禁在最需要它的时候静默失效**。
- **代价**：命令行更长。可接受。

#### 4.4 词表身份内容寻址（"同源"可机器判定）

- **决策**：`Ontology::vocab_hash()` 对**规范化 JSON**（解析后紧凑序列化、键有序）
  且**剔除 `_` 开头说明键**后求指纹；两份投影的首行都必须携带它。
- **理由**：`REQ-F-020` 要求"两投影同源"。若各自读一份词表副本，
  "同源"只能靠人比对文件——那不叫证明。内容寻址让"换了词表"成为**可检出事件**。
  剔除说明键是为了避免**假警报**：改一句注释就报"换词表"，
  会训练人忽略这个信号（比没有信号更糟）。
- **被否方案**：① 用文件字节哈希——空格改动即报警；
  ② 不设身份，只比对渲染结果——两投影渲染不同内容时无法区分"渲染差异"与"词表不同"。
- **代价**：指纹是 FNV-1a（**非加密**），可能碰撞。它只用于"是不是同一份"，
  不用于安全判断——此局限已写进代码文档。
  另有一条**使用边界**（上游明文要求）：本体身份**不得用于安全判断**——
  `2-依据/14-总线词表v0.md` 的待批判项 6 把"词表内容寻址的编码"列为未定，
  且本项目已把该指纹用于 `A-09` 时声明为"非安全用途"。

##### 4.4.1 本体的"极小核心 + 命名空间扩展"（**上游要求进 SRS/HLD**）

`ontology.json` 的形状**刻意分三层，扩展点各不相同**（实测）：

| 层 | 出厂内容 | 扩展方式 | 判定行为 |
|---|---|---|---|
| `envelope`（信封） | `required` 8 项 + `optional` 2 项（原文 "required": ["world", "kind", "id", "seq", "at", "actor", "flags", "body"]） | 加**可选**字段不破坏旧读方 | `src/ontology_definition/mod.rs:160-167` 只查 `required` 存在性 |
| `families`（家族） | 3 个：`change`/`act`/`notice` | 加家族**不必改代码**（`Ontology::validate` 按 `families` **动态查**，`:178-183`） | **未知家族 → 拒绝**（`UnknownKind`） |
| `flags`（能力旗标） | **空数组**（`ontology.json` 的顶层 `"flags": []`） | 加旗标**只加不改** | **未知旗标 → 必须忽略**（前向兼容） |
| `concepts`（实体概念） | 2 个：`notice`/`job`，各带字段 | **扩展走账本里的词表定义事件**——这是 `ontology.json` `concepts` 的 `_comment` 原文口径（"最小集；扩展走账本里的词表定义事件"） | 读模型不解释 `concepts`（实测：`readmodel.rs` 不含 `concepts`） |

> ⚠️ **本节是处置要求"`极小核心+命名空间扩展`须进 SRS/HLD"在 HLD 侧的落点**，
> 但**只写了 HLD 这一半**：SRS 侧的需求条目（`REQ-F-008` 的"三个家族"是否改为
> "v1 最小集 = 3、可扩展"）属 `WC-SRS-001`，**本轮不在本文件授权范围内**，须由 SRS 的
> 处置执行员落笔（`WC-SCMP-001` §8.4 **`G-24`** 的处置②：R2 在 HLD 增"家族演进与向前兼容"一节）。
> 本条与 `G-24` 的三个未规定点一一对应：① 词表升版规则未写（"加家族算不算要升 `world`"）→
> 见 §十 待定项与 `G-24`；② 读模型遇未知家族是**硬拒绝**（`src/ontology_instance/readmodel.rs:110-115`
> `ReadModel.UnknownKind`），"旧二进制读含新家族的账本会拒绝折叠"——**安全但脆弱**，
> 策略未定；③ "谁能加家族、走什么 CR"未定。

##### 4.4.2 担保边界（**本条只说它担保什么，不含什么**）

`T-20`/`B-10` 要求把"同源可机器判定"的文案**收窄**（`SRS`/`FSR`/`UT`/`TS` 与本文件
五处此前都是强口径）。据此明确边界，**"同源: ✅"这一判定仅蕴含下列三项，多一项都不蕴含**：

| 判定成立 ⇒ **担保** | 判定成立 ⇏ **不担保** |
|---|---|
| 两份投影首行相等，即 **同 `world`**（词表版本）、**同 `vocab`**（词表身份 `vocab_hash`）、**同 `(last_seq, state 指纹)`** | ① **不担保账本身份**（两份投影读的是同一本账，是"同一进程同一路径"这一前提，不是本判定检出的）；② **不担保正文**（只比对**首行**那四项，投影正文不参与比对）；③ **不担保渲染过程**（两份投影各自渲染，共用 `project/mod.rs::group_by_subject` 这一纯函数，**渲染步骤不同**是有意的） |

- **单进程路径下，本判定不可能失败**：`project check` 在同一次调用里折叠**同一个读模型**、
  取**同一个** `vocab_hash`（`src/main.rs:296-333`）⇒ 首行必然相等。
  故它证明的是"**两个出口读的是同一份东西**"，**不是**"跨进程/跨时刻也能一致"；
  后者需要 `IF-003a` 的跨进程比对规程（`WC-TS-001`，属测试层）。
- 真正会被这个判定检出的是**换词表**（`vocab_hash` 变化）——那是 `REQ-F-020` 的原意。

#### 4.5 读模型不持久化；快照只能是带 `base_seq` 的缓存

- **决策**：v1 读模型**零持久形态**（无缓存文件、无内存缓存跨调用复用）；
  `M08` 快照今后若实现，必须带 `base_seq`，且"从快照续算"必须与"从头重算"结果相同。
- **现状订正（2026-09-27 实测）**：`src/ontology_instance/checkpoint.rs`（176 行）**已实现**（`WC-MODREG-001` §二 记
  "✅ 已实现（项目 Step 3）"），但**尚未接入任何 CLI 子命令**：`main.rs` 的 `check`/`state`/`project`
  都直接 `read_model()` 全量折叠，**不读快照**。故"v1 读模型零持久形态"对**运行路径**仍成立，
  而"`M08` 今后若实现"这句话已**过期**——实现已在，只是没接进启动/读取路径。
- **理由**：一旦有持久形态，就出现"读模型与账本不一致"这一经典故障类；
  而本项目的地基命题是"账本是唯一真相"。**删掉一个不存在的东西，
  比修复一个不一致的东西便宜得多。**
- **被否方案**：v1 就加快照以"提升性能"——在数据规模未知时优化，
  是用复杂度换一个尚未发生的收益，同时提前引入一整类一致性风险。
- **代价**：大账本上每次读状态都是 O(n)。触发条件（何时必须上快照）
  列入 §十 待定项 **1b**（阈值）与 **1a**（格式归属），配合 `WC-SQAP-001` 的 **QG-05**
  （重放性能，度量规程 M-05；数值仍为【候选】待人工确认）。

##### 4.5.1 坏快照：拒启还是降级重算（**裁决**）

- **裁决**：**降级重算，不拒启**。理由与"账本是唯一真相"一致——
  快照是**可丢弃的缓存**，把它当成"坏了就拒绝整个世界启动"的东西，
  等于给了缓存一票否决权，**恰好把它升格成第二真相**。
- **判据（三件套，逐条可判）**：① 快照只是**优化**、不是启动前提；
  ② 删掉快照后 `check`/`state`/`project` 必须**照常成功**且结果与带快照时**逐字节相同**；
  ③ 拒绝只发生在**显式**使用快照的调用面上（`Checkpoint::verify` 失败即拒绝续算，
  调用方须回落到全量折叠），**不得**沉默地用坏快照继续。
- **实现现状（实测）**：`Checkpoint::verify` 要求 `base_seq` 存在
  （`src/ontology_instance/checkpoint.rs:100-101`，错误码 `ext.world.Checkpoint.MissingBaseSeq`）、
  账本里不晚于 `base_seq` 的条数必须**恰好等于**它（`:128-132`，`ext.world.Checkpoint.Stale`）、
  重算前缀指纹必须相符；**未核验**的续算被刻意命名为 `resume_unverified`（`:152`）。
  ⚠️ 由于快照**尚未接入启动路径**，"坏快照会不会拒启"在**当前实现里不可能发生**；
  一旦接入，须按上面的裁决实现，**不得**改成拒启。
- **与上游 `07/2-依据/15` 的关系（实测，2026-09-27）**：上游文档 `2-依据/15-世界核心的组成与职责.md`
  **:314** 把 `base_seq` 用在**读者侧**的未决问题上——原文是
  "**读模型的新鲜度**：投影取带 `base_seq` 的快照，还是常驻订阅增量？混用时怎么判断『我落后了』？"
  （同文件 **:287** 另记"坏了能回滚（不用载体快照）"为缺口）。
  故本项目把 `base_seq` 定为**服务于读者**的字段，**与上游一致**，不是自创；
  但上游**没有**定义"续算 ≡ 全量重算逐字节相同"这条更严的判据，
  也**没有**"未核验续算"这一档——这两条是本项目的**加固**，方向是**收紧**（符合处置原则 §一.2）。
  另：处置表提到的"上游 **14 篇**"指同目录 `01`–`14` 共 **14** 个兄弟文档（`:314` 的上下文涉及
  投影/订阅），其与本条的逐篇关系**本轮未逐篇核对**，登记为【待验证】，验证方法见下。

#### 4.6 零外部依赖纪律（含"指纹用非加密实现"的选择）

- **决策**：直接依赖仅 `serde_json`；项目自用的指纹（读模型 digest、词表 hash）
  用 FNV-1a 自行实现，不引入哈希库。
- **理由**：世界核心是地基——**依赖链是攻击面也是移植成本**。
  地基每多一个依赖，将来换语言重建世界的代价就高一截（`REQ-N-001` 语言无关的精神）。
- **被否方案**：引入 `sha2` 等成熟库以获得加密强度指纹。
  本项目当前不需要加密强度（不用于安全判断）。
- **代价**：指纹弱；一旦将来把它用于安全用途就是**误用**——
  已在代码与文档两处写明"非加密用途"。

#### 4.7 回滚 = 追加补偿事件（不提供"撤销"API）

- **决策**：不实现 `undo`/`revert`；回滚由调用方追加一条普通 `change`
  （旧值/新值互换）完成，读模型对其无特殊逻辑。
- **理由**：`REQ-F-014` 的实质是"历史不可改"。若提供 `undo` API，
  它迟早会被实现成"抹掉最后一条"——那一刻账本就不再是证据。
- **被否方案**：`undo` 命令内部追加补偿事件（形式上安全）。
  否掉它是因为**命名会塑造理解**：叫 `undo` 就会有人以为历史被动过。
- **代价**：调用方要自己写补偿事件。这是把"回滚是内容问题"这件事摆在明面上。

#### 4.8 投影是出口节点（不交互、不持状态）

- **决策**：两个渲染函数只接受 `(&State, world, vocab)`，返回 `String`；
  不共享缓存、不互相调用。
- **理由**：`07/2-依据/15` §三 的"投影之间不交互"。若允许投影持有状态，
  它们就会各自演化出"自己那份真相"——同源随即失效。
- **被否方案**：视觉投影复用语言投影的输出再美化。
  否掉是因为这会让视觉投影**依赖另一个投影**，形成隐式流水线。
- **代价**：两个投影**共用** `project/mod.rs::group_by_subject` 这一**纯函数**（评审 F-10 指出：原文『少量重复换解耦』与实现相反）。共享纯函数是**有意**的——它是『同源』在代码层的体现；被否的是共享**状态**与『一个投影复用另一个的输出』。
  这份重复买的是"两边不可能因复用而耦合"。

#### 4.9 账本与投影一律纯文本 + 明确退出码

- **决策**：JSON Lines（账本、语言投影）、JSON（本体、策略）、可读文本（视觉投影）；
  退出码 `0/1/2` 三档含义固定。
- **理由**：`REQ-N-001`"语言无关"——账本必须能被 `awk`/`jq`/Python/Go 直接读，
  换语言重建世界不需要解码器。退出码三档让脚本能区分"用法错"与"世界有问题"。
- **被否方案**：二进制/`bincode`/自定义紧凑格式。空间收益在小规模下不值一提，
  代价是**把世界锁死在一种语言上**。
- **代价**：体积大、无索引（将来若需要，索引必须可重建，属 `M08` 范畴）。

#### 4.10 折叠**报错而不猜**（坏账本拒绝折叠）

- **决策**：读模型在三种情形下报错：序号断裂、事件声称的旧值与折叠出的当前值不符、
  未知事件家族。
- **理由**：`REQ-F-013`。"账本是唯一真相"若允许读模型默默容忍坏数据，
  就成了一句空话——真相的权威性由**拒绝**来维持，不由信任维持。
- **被否方案**：遇到坏行就跳过并记录警告（"尽力而为"）。
  否掉是因为那会让"账本被改过"这件事**永远不被发现**。
- **代价**：一条坏事件会让整个读模型不可用。这是**故意的 fail loud**：
  宁可停在那，也不要带着不可信的过去继续走。

### 五、数据设计

#### 5.1 事件信封

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `world` | ✅ | `integer` | 词表版本；不符即拒（`BadVersion`）。出厂值 `1`（`src/common/event.rs:16`） |
| `kind` | ✅ | `enum(change, act, notice)` | 三个家族；**未知 `kind` → 校验拒绝**（`ext.world.Ontology.UnknownKind`，`src/ontology_definition/mod.rs:181`） |
| `id` | ✅ | `string` | 事件身份，形如 `e<纳秒>-<进程内计数>`（`src/common/event.rs:40-43`，不引 uuid 库） |
| `seq` | ✅ | `integer` | **由账本分配**，全局单增 |
| `at` | ✅ | `integer`（Unix 秒） | **顺序由 `seq` 决定，`at` 只作辅助**（`src/common/event.rs:73-78`，非负） |
| `actor` | ✅ | `string` | 世界内身份，如 `world://user` |
| `flags` | ✅ | `array` | 能力旗标；**未知旗标必须忽略**（前向兼容）。出厂已定义旗标集**为空**（`src/common/event.rs:19`，`FLAGS: [&str; 0]`） |
| `body` | ✅ | `object` | 家族信纸（类型为对象，`src/ontology_definition/mod.rs:185-191` 强校验） |
| `to` / `trace` | ⬜ | `string` / `string` | 目的地（空=广播）/ 因果链（引发本条的那条事件 `id`）。类型出处：`ontology.json` 的 `envelope.fields` 中这两个键（原文 `"to": "string  # 目的地；空 = 广播"`、`"trace": "string  # 因果：引发本条的那条事件的 id"`） |

> **类型来源与口径**：信封各字段的类型出自 `ontology.json` 的 `envelope.fields` 映射
> （键为字段名、值为**带 `#` 注释的类型串**，如 `"seq": "integer  # 在账本中的位置，全局单增，由世界分配"`）
> ——**那是唯一的类型声明处**；`src/common/event.rs` 是构造侧的事实对照。
> ⚠️ **本体不校验字段的 JSON 类型**：`Ontology::validate`（`src/ontology_definition/mod.rs:157-201`）
> 只做四件事——信封必填存在性、`world` 版本、家族存在、信纸必填存在性；
> **不含任何类型断言**（写 `"world": "1"` 会在 `:169` 取 `as_u64` 失败而落到 `got=0` →
> 被 `BadVersion` 拒绝，属**间接**检出；`seq`/`at` 同理无独立断言）。
> 这一缺口登记为【待验证】事项：验证方法 = 构造 `{"world":"1",...}` 与 `{"seq":"x",...}`
> 各一条跑 `append`，看是否被拒；若拒，则真正生效的判据是 `BadVersion` 而非类型校验。

> **上游差异登记 ①（`trace` 的同口径对偶）**：与"未知 `kind` 必须拒绝"相反，
> **未知 `flags` 必须忽略**（`ontology.json` 的 `envelope.fields.flags` 原文
> `"flags": "array  # 能力旗标；未知旗标必须忽略"`、`src/common/event.rs:19`）——
> 这两条是**对偶**的：家族是**结构**（认不出就不能解释），旗标是**能力声明**（认不出不影响解释）。
> 本文件此前只写了旗标那一半，现补齐另一半。

> ⚠️ **待人工裁定（§三 E-1）：`to` / `trace` 的地位**。
> 本处按 `WC-R4-DISP-001` §二 C 组的**倾向**落笔为"**本版可选、语义按本体定义照录**"，
> 即：`to` **写入方** = 造事件的调用方，**读取方** = 将来的通道投递（`M09`）与投影，
> **不填的后果** = 视为广播（`to` 缺省）/ 无因果链（`trace` 缺省），**不报错、不留痕**；
> 二者**当前都无门禁、无校验、无消费方**（实测：`src/**/*.rs` 全文对
> `"to"` 与 `"trace"` **零命中**，`main.rs` 的 7 个子命令均不读它们）。
> **另一选项的代价（已实测，不再是假设）**：若人工裁定"显式降级并登记"，须补一条降级记录，
> 因为上游**确实**把 `trace` 列为"语义"的**定义性判据**——
> `2-依据/14-总线词表v0.md`（**§四 或"待批判项"前的字段缺失后果表**）原文写
> "**`trace`** ｜ **无法回答『为什么会变成这样』**；常设验收退化成时间线，不是因果"，
> 同文件 **§六 待批判项 2** 又写"**`trace` 链的长度与截断**：24 小时可能几千条，
> 全链回溯成本未估；超过上限降级成什么？"。
> 故显式降级会使 `REQ-F-018`"与历史"的删除从**设计取舍**变成**需求缺口**，
> 须回到 SRS 层补条目；若裁定"本版不实现"，则须在 `ontology.json` 与格式说明里
> **一并**撤掉 `to`/`trace`，否则"可选字段"会长期扮演"以为有、其实没人读"的角色。

#### 5.3 账本格式

- **一行一条事件**的 JSON Lines，UTF-8，LF 结尾；**只追加**；
- **行分隔约定（上游差异登记 ③）**：**任何字段的内容都不得在行内出现真实的 `0x0A` 字节**。
  这是**分帧**的前提——账本读回以字节 `0x0A` 切分（`src/ledger/mod.rs:198` 用
  `rposition(|b| *b == b'\n')` 定位最后一条完整行、`:213` 用
  `split(|b| *b == b'\n')` 逐条切），一条事件的字节里只要有一个未转义的 `0x0A`，
  就会被读成两条、双双解析失败（`read_from` 在 `:403` 以 `BufReader::lines()` 逐行读）。
  口径落在**编码层**：`serde_json::to_string` 序列化时把 `U+000A` 转义为两个字符 `\` `n`
  （写侧 `src/ledger/mod.rs:315-316`：先 `to_string` 再 `push('\n')`），
  故"正文里的换行"**合法**——它不以真实 `0x0A` 出现。
  ⚠️ **须在 `WC-ONT-001-v0.1`（本体说明）与账本格式说明里同样写死**——本文件不是它的唯一出处。
  ⚠️ **当前无任何门禁或测试断言这条**（实测：`scripts/test/*.rs` 里
  `t3`/`perf.rs:216-229` 只测"末尾半行/无换行"，**没有一条测"值内含 `0x0A`"**），
  且 `serde_json` 的转义行为本身**未被本项目的一条测试固定住**。
  登记为【待验证】：验证方法 = 构造一条 `after` 含真实 `0x0A` 的事件直接写进 `ledger.jsonl`，
  分别跑 `read` 与 `state`，确认是否被拒；再补一条**值含 `\n` 的往返测试**（`append` → `read` →
  `state`），把"转义 ⇒ 不破坏分帧"从约定变成有测试的事实。
  另注：读侧按 `0x0A` 切分 ⇒ **CRLF 文件会有问题**（每行尾多一个 `\r`），
  而本项目自己的规范要求 LF（`§4.9`、`.gitattributes`）；此点登记为【待验证】，
  验证方法 = 把一份账本转成 CRLF 后跑 `read`，看是否报解析错而不是静默吞掉 `\r`。
- 启动时**丢弃末尾半行**（崩溃遗留）并复用该号；
- `seq` 必须从 1 连续递增，**缺号即拒绝启动**；
- **摘要链（`chain` 字段，`WC-CR-003` D1）**：每条事件在落笔时被写入一个 `chain` 值，
  算法为 `fnv1a64(前值 + "\n" + 去除 chain 后的规范形式)`，创世种子为常量 `"genesis"`
  （`src/ledger/mod.rs:423-441`）。**三态语义**（`src/ledger/mod.rs:451-484`，用例 `c16`/`c17`/`c18`/`c21`）：
  | 账本状态 | 行为 |
  |---|---|
  | **全部事件都有 `chain`** | **逐环核验**；任一环断裂 → `ChainMismatch` → **拒绝启动**（用例 `c20`） |
  | **全部都没有 `chain`**（v1 之前的旧账本） | 放行 + **警告**"局部篡改不可检出"；加 `--require-chain` 且有事件时 → 拒绝启动 |
  | **部分有、部分没有** | `MixedChain` → 拒绝（半链账本不可信） |
  ⚠️ **能力边界（不夸大）**：链只能检出**局部**篡改（改一行而不重算后续所有链值）；
  **整本重写**（连链一起重算）**检不出**——用例 `c18` 专门锁死这一点。
  另：链是链、旧值核对是旧值核对——读模型的 `before` 比对**仍是自洽检查**，
  它**不**依赖链（见 §14.3 `DEBT-05` 行的订正）；
- 账本**不入库**（运行态数据、会无限增长、可能含个人痕迹，见 `WC-SCMP-001` §4.4.2）。

> 这是**静默收紧**，比拒载更难排查。

#### 5.5 读模型与规范形式

- `state = fold(events[0..seq])`；主体与路径用**有序映射**（`BTreeMap`），
  于是同样的账本必然渲染出**同样的字节**；
- 状态字段**私有**，只能由 `fold`/`apply` 产生（类型级封死"绕过账本改状态"）；
- **规范形式** = `{last_seq, seen, acts, notices, objects}` 的紧凑 JSON；
- **指纹** = 规范形式字符串的 FNV-1a（非加密，仅用于"两次折叠是否同一结果"）；
- 旧值核对：`path` 已有值时，事件的 `before` 必须等于折叠出的当前值（§4.10）。

### 七、运行与部署设计

#### 7.1 启动顺序（固定）

1. 加载本体（法律·形状）→ 校验版本；
2. 加载门禁策略（法律·权限）→ 校验版本、能力表、白名单、**`writes`/`irreversible_actors`**、**静态墙**；
3. 打开账本（事实）→ **取单写者锁**（`acquire_lock`）→ **静态墙** → 丢半行 → 校验 `seq` 连续 → 恢复 `next_seq`
   → **核验摘要链**（`load_chain`，`src/lib.rs:78`；无链按 v1 放行并警告）；
4. **词表版本一致性自检**：`event::WORLD_VERSION` 必须等于本体声明的 `world`，否则 `VersionMismatch` 拒启
   （`src/lib.rs:85-92`，防"能启动却一条都写不进"的自伤性故障）；
5. 任一步失败 → **拒绝启动**，退出码 `2`。

> 顺序不可交换：**先在脑子里装上法律，再去碰事实**。
> 第 3 步里的子顺序也固定：**先取锁**（`Ledger::open` 的第一件事，`src/ledger/mod.rs:168`）
> 再读文件——否则两个进程会同时读改写（§12 `A-01`）。

**启动是否载入检查点（`M08`）——裁决**：**不载入**。
- **裁决**：`v1` 启动**不读快照**，一切由账本全量折叠；快照只在**显式**（`Checkpoint::verify` /
  `resume_unverified`）被调用时才参与。
- **理由**：`WC-CR-006` **§三 技术线 A 的 `M-4`「规模实测」条**的「最小补丁」原文写
  "**再给 checkpoint 接 CLI 面并只在显式要求时核验**"——即"**接 CLI 面 + 仅显式核验**"。
  ⚠️ 该条**没有**说"启动不得载入"，故"启动不载入"是本文件**据其方向作出的裁决**，不是 CR 的原文。
- **实测依据（可复现）**：`src/main.rs` 与 `src/ontology_instance/readmodel.rs` 对 `checkpoint`/`Checkpoint`
  **零命中**；全仓只有 `src/lib.rs:20` 的 `pub mod checkpoint;` 一处声明。
  ⇒ 当前**没有任何启动或读取路径会碰到快照文件**，"坏快照拒启"在现实现里不可能发生。
- ⚠️ **待人工裁定（上下游冲突）**：与上游 `2-依据/15` 的方向可能相反
  （上游把快照用于"投影取快照 / 常驻增量"的选择，见 §4.5.1 引的 `:314`）。
  本处按 `CR-006` 的"仅显式核验"落笔，
  **另一选项的代价**：若改为"启动载入"，则 §4.5.1 的"坏快照降级重算"必须同时生效，
  否则一个坏快照会变成**拒启开关**（把缓存升格成第二真相）；
  另须在 `WC-SQAP-001` 的 QG-02/QG-05 口径里交代"带快照路径"的性能与恢复语义。
  **本条在人工裁定前不得被引用为"启动语义已定案"。**
- **启动不折叠**：启动只做"丢半行 + 校验 `seq` 连续 + 恢复 `next_seq`"，
  **不折叠账本**⇒ **折叠错误不会在启动时暴露**，只在 `state` / `project` 被调用时才报
  （`ext.world.ReadModel.*`，退出码 `2`）。
  这消除了此前 §7.1 与 §7.2 的**互斥**：§7.2 列的"读模型折叠遇到坏账本"**不属于拒绝启动的情形**
  （启动不折叠），它是**读取期错误**。见 §7.2 的分档说明与 §15.1 的新增档。

#### 7.3 权限与 uid 编排（**部署要求**，非建议）

| 对象 | 要求 | 理由 | 代码落点（实测） |
|---|---|---|---|
| `policy.json` | 属主=世界核心的 uid（通常 root），mode `0644` 或更严 | 被管者不得能写（法律之墙） | `src/gate/mod.rs:211` |
| `ontology.json` | 同上 | 词表即契约 | `src/ontology_definition/mod.rs:81` |
| 账本文件 | 属主=世界核心的 uid，mode `0600` | 真相不得由被管者写 | `src/ledger/mod.rs:190` |
| **本体/策略/账本所在目录** | 属主=世界核心的 uid，mode `0755`（**不得** group/other 可写） | 防止"删掉再放一个新的" | `src/gate/guard.rs:69-88`（三个调用点共用同一段目录检查） |
| **通道 socket 目录** | **不得** group/other 可写 | 否则套接字可被替换，与法律/账本同理 | `src/bus/mod.rs:172`（`assert_not_other_writable(dir, "通道目录")`；⚠ **无专属用例**，登记） |
| **通道 socket 文件** | bind 后**立刻** `chmod 0600` 并 `chown` 给该身份的目标 uid | **权限即身份**：只有那个 uid 能 `connect`，内核在连接时就挡住别人 | `src/bus/mod.rs:181-187` |
| **`channel.json`** | 属主=世界核心的 uid，**不得** group/other 可写 | ⚠️ **当前未纳入静态墙**（`channel.rs:73` 的 `load` 只读文件，**未调任何 `guard::` 断言**）。而它决定"哪个 socket 对应哪个 `uid → actor`"——能改它就能**改身份映射**，与法律同级。**本表把它列为要求**；实现侧补一条 `guard::assert_not_other_writable(path, "通道配置")` 即可（登记为 §十 待定项 6 的同类缺口） | ⚠️ **缺**（要求在此，实现未做） |
| **检查点快照文件** | 由创建路径自行过静态墙（v1 未接 CLI，故当前无生产调用点） | 缓存也要过墙（`assert_after_create` 检查文件+目录），否则"改缓存"成为绕过路径 | `src/ontology_instance/checkpoint.rs:81`（`assert_after_create(path, "检查点（缓存）")`） |
| agent 进程 | **不同 uid**（如 `agent`），且不在上述文件的属主之列 | 静态墙只挡"非属主"；被管者若恰是属主，mode 再严也没用 | `--owner-uid` 断言：`src/main.rs:111-121`、`guard::assert_owned_by`（`src/gate/guard.rs:132`），用例 `c10` |

> ⚠️ 最后一行是本设计**最大的部署依赖**：静态墙查的是 **mode 位**，不查属主身份
> （见 `WC-CON01-001` §五 遗留 2）。属主编排必须在部署时落实，
> 否则"不可绕过"在真实环境里不成立。

#### 14.1 日志与审计

### 十五、出错处理与补救措施

#### 15.1 出错信息（错误码表见 `WC-IC-001` §三）

| 层 | 形态 | 用户可见 |
|---|---|---|
| 启动期 | `[FAIL] <原因>` → **退出码 2** | 明确到"哪一份文件的哪一个字段" |
| 写入期 | `[FAIL] <原因>` → **退出码 2** | 法律/门禁/账本三类原因可区分 |
| **读取/投影期**（**新增档**） | `[FAIL] 读模型拒绝折叠：<原因>` → **退出码 2** | 序号断裂(`SeqGap`)/旧值不符(`BeforeMismatch`)/未知家族(`UnknownKind`) 三类可区分（`src/main.rs:306`） |
| 用法错误 | 用法说明 → **退出码 1** | 子命令与参数 |
| 门禁拒绝 | `门禁拒绝…/加摩擦…/拒绝写入…` | 理由 + 能力名/主体名；**并留 `notice`** |

> **为什么要单列"读取/投影期"**：它**不属于启动期**——`v1` 启动**不折叠账本**（§7.1 的裁决），
> 故坏账本不会在启动时暴露，只在 `state`/`project` 被调用时报错。
> 此前四档口径会让读者以为"坏账本 = 拒绝启动"，与 §7.1/§7.2 的实现事实冲突。
> **失败形态与退出码实测**：`cmd_state`（`src/main.rs:206-234`）与 `cmd_project`（`:303-309`）
> 在 `read_model()` 失败时打 `[FAIL] 读模型拒绝折叠：<原因>` 到 **stderr**（`:306`），
> 随后返回 `ExitCode::from(2)`（`:307`）。
> **`§4.10` 的 fail-loud 是否传导到投影层——结论：是，但只传导到"拒绝渲染"为止**：
> 投影函数本身接收的是**已经折叠好的 `&State`**（`src/main.rs:303-310` 先 `read_model()` 再 `render`），
> 故折叠失败时**投影根本不会被调用** ⇒ 表现为 `project` 子命令退出码 `2` + stderr 的折叠原因；
> 而"渲染函数内部失败"在当前实现里**不存在**（两个 `render` 都返回 `String`，不返回 `Result`）。

#### 15.2 补救措施

| 故障场景 | 检测方式 | 补救 | 恢复目标 |
|---|---|---|---|
| 账本末行残缺（崩溃遗留） | 启动时"截到最后一个 `\n`" | 自动丢弃并复用该号 | 无需人工 |
| 账本**行粘连**（写入中途失败） | 启动读到坏 JSON → 拒启 | 人工核查；v0.2 起写入失败即回滚，**从源头避免** | 人工 |
| 账本 `seq` 缺号 | 启动 `SeqGap` → 拒启 | 人工核查（可能被外部改写） | 人工 |
| 写入 `fsync` 失败 / 回滚失败 | `Ledger.SyncFail` / `Poisoned` | **停止写入**，人工检查后重启 | 人工 |
| 规则被改宽（policy 0666 等） | 启动静态墙 → 拒启 | `chmod go-w` 后重启 | 无需人工改数据 |
| 误改状态（需要回退） | 查账本 | **追加补偿事件**（不提供 `undo`） | 状态回退，历史保留 |
| 换词表 | `vocab_hash` 变化 | 两投影同源判定会**失败**并指出是词表不同 | 停线排查 |

> **RTO/RPO**：均**无实测值**，属【候选】（`WC-SQAP-001` QG-02 口径待人工裁定）。
> 本表**不编造**恢复时间承诺。

#### 16.1 运行场景（`RUN-01`–`RUN-04`）

#### 16.2 运行控制

- **启动顺序固定**（§7.1）：法律（本体→策略）→ 事实（账本）；不可交换；
- **只读子命令的例外**：`kinds`、`policy` 只加载**单一**法律文件、不打开账本、不做 `seq` 校验
  （`kinds` 只读本体 `src/main.rs:236`；`policy` 只读策略 `:166`）；
- **停机**：v1 **无优雅停机协议**——进程被终止时最多留下一个残缺末行，
  由下次启动丢弃；**没有"收到 SIGTERM 后 flush"的语义**。
  且**随进程结束自动释放**（`LockGuard::Drop` 删锁文件，`src/ledger/mod.rs:112-116`）。
  仍成立的是：被 `SIGKILL` 时不跑 `Drop`、留下陈旧锁，靠下次启动回收（用例 `c08`）。
  ⚠️ 这是**已知缺口**，随 `A-01` 的**锁竞态**一并设计。

### 二、测试环境与数据纪律（**硬约束**）

1. **一律用一次性沙箱账本**（`mktemp -d`，退出即删）：**绝不触碰真实账本**
   ——依 `06-swe-gb` 幂等口径修订：命令幂等，**数据操作天然不幂等**；
2. **确定性**：不依赖 sleep / 网络 / 外部服务；不断言墙钟（`at`/`id` **不进** `State`、不进指纹）——
   教训来自 `07-agent-native-os` 的"完工铃丢铃"竞态；
3. **执行顺序无关**：测试名在输出中的次序由并行执行决定，结论不得依赖顺序；
4. **两类环境都要跑**：VM（`cargo test --locked` + `check.sh`）与 CI（GitHub Actions）；
   二者结论不一致时**以 CI 为准**，并把差异登记为环境类风险。

### 三、通过/不通过准则

| 判据 | 内容 |
|---|---|
| **阻断式** | 任一层失败即不通过；CI 五个作业**严禁 `continue-on-error`**（`ci_self_check.py` 专责检查） |
| **失败路径必须有反例** | 每道门禁都要有"**会失败**"的证据：`scope`（PR 正/反例）、`traceability`（5 类错误数据）、`gate`（越权/摩擦/静态墙）、`readmodel`（3 类坏账本）、错误码契约（`c15`） |
| **反假测试** | 关键等价性断言必须附"若实现是常量则必须失败"的对照（如 `t7` 的前缀对照、`c15` 的散文反例） |
| **未校验要说出来** | 工具未生效时必须显式打印（如"模块登记表尚未建立"），**不得静默通过** |
| **证据四要素** | 命令 + 原始输出 + **代码提交号** + 用例编号 ↔ 需求映射（见 `WC-RE09-003`） |
