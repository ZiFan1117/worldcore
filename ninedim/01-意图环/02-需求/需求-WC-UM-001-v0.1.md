# 初步的用户手册（`WC-UM-001-v0.1`）

> **本文档是什么**：需求分析阶段应编写的文档之一（**标准依据的条款号、逐字原文与核验信息一律在本文档附录 A 就地给出**）。
> **形态**：**初步版**——只写"这个系统是什么、怎么跑起来、最基本怎么用、坏了怎么办"；
> **正式版在实现阶段完成后形成**（承本手册附录 A 所引条款；届时并入交付物）。
> **性质**：**给人看的主文**；一切依据、判据的反例与实测输出、证据索引在本文档的**附录**里。

## 一、这个系统是什么

**世界核心（World Core）** 是一个**本地单机**程序：它把发生过的每一件事，**按顺序追加**写进一个文本账本；
世界的当前状态**不另行保存**，而是**从账本重算**得到。程序是**单个可执行文件**，**不需要安装任何额外运行时**
（不需要 Python / Java / Node，也不需要数据库）。

## 二、怎么跑起来

1. 取得**单个可执行文件**。**取得途径（可复算）**：在本仓库的 `` 目录下执行
   `cargo build --locked --release`，产物为 **`target/release/world-core`**；
   或用发布方提供的构建产物。（**注意**：本版仓库内**尚无发布包**，故第一条途径是可复算的那一条。）
2. 在**一个空目录**中放好两个文件：`ontology.json`（词表）与 `policy.json`（策略）。
   ⚠ **权限前提（必须满足）**：这两个文件**及其所在目录**都**不得对 group/other 可写**；
   否则程序会**拒绝启动**并点名路径与当前权限位。最省事的做法是 `chmod go-w <目录> <两个文件>`。
   ⚠ **路径用法提醒**：程序对"账本所在目录"做静态墙检查，而**相对路径与绝对路径给出的"所在目录"可能不同**
   （实测：同一 777 目录下，用相对路径 rc=0，用绝对路径 rc=2）。**建议一律用绝对路径**并在启动前 `chmod go-w`。
3. 执行**一条命令**（`world-core check`）——**打印 `READY`** 即表示：词表、门禁、账本三项都开得起来。

> **判据（可机械核对）**：上面第 3 步**必须打印 `READY`**，且**退出码为 0**。
> **「应当失败」的反例**：把 `ontology.json` 换成内容被破坏的版本 ⇒ **必须报错退出，且不得打印 `READY`**。
> （实测：`world=2` ⇒ `ext.world.VersionMismatch`，无 `READY`，`rc=2`。）

### 2.1 全部子命令与全部开关（照 `--help` 照录，**不要只背三个**）

| 子命令 | 作用 |
|---|---|
| `check` | 加载本体 ＋ 门禁策略 ＋ 账本 → 打印 `READY`（冒烟判据） |
| `kinds` | 列出本体已知的**家族** |
| `policy` | 打印门禁策略（能力表 ＋ 主体白名单） |
| `append <kind> <json-body> [actor] [--trace <id>] [--flag <名>]...` | 追加一条事件（法律校验 → 门禁裁决 → 通过才落笔）。**`<json-body>` 是信纸本身，不要再包一层 `body`**；`[actor]` 省略时缺省 `world://user`（**该缺省是入口层约定，库 API 不设隐藏默认**） |
| `read [from_seq]` | 按序打印事件（JSON Lines） |
| `state [--json]` | 从账本**重算**状态（读模型；**不缓存、不写盘**） |
| `project language` | 语言投影（结构化出口，给程序读） |
| `project visual` | 视觉投影（渲染出口，给人看） |
| `project check` | 渲染两份投影并**核对同源**（词表与状态必须一致） |

**开关**：`--ontology <路径>`／`--ledger <路径>`／`--policy <路径>`／`--owner-uid <uid>`／`--require-chain`。
**退出码**：`0` 成功 ／ `1` 用法错误 ／ `2` 法律、账本、门禁或读模型错误。
失败信息一律走 **stderr** 且以 `[FAIL] ` 开头；正常结果走 stdout。

## 三、最基本的三件事

| 我想…… | 怎么做 | 怎么知道做成了 | 「应当失败」的反例 |
|---|---|---|---|
| **能跑** | 见 §二 第 3 步：`world-core check` | 打印 `READY` 且 `rc=0` | 破坏 `ontology.json` ⇒ 必须报错退出且**不得**打印 `READY` |
| **能用**（记录一件事） | `world-core append notice '{"type":"done","subject":"world://user"}'`，再用 `world-core read` 读回 | 读到该事件，且它在**重启（新进程）后仍在** | 用**未声明**的能力追加 ⇒ 必须 `rc=2`（`ext.world.Gate.Rejected`），且**只落一条拒绝流水**，原事件**不落笔** |
| **能查**（确认没被改过） | `world-core check`；**先看账本条数** | **账本非空时**：打印 `✅ 有摘要链（局部篡改可检出）`；**账本为空时**：打印 `⚠️ 无摘要链——局部篡改不可检出`（**这是如实报告，不是故障**：空账本没有东西要保护） | **账本非空**时手工改一条事件的 `body` ⇒ 必须 `rc=2` 且理由含 `ChainMismatch`；加了 `--require-chain` 时**空账本不算违规**，但**一旦存在无链事件必须拒绝** |

> **⚠ 关于"能查"的一句实话**：摘要链是**首条事件写入之后**才出现的。因此**在"空目录刚 `check` 完"这一刻，看到的必然是「⚠️ 无摘要链」**——
> 本手册此前那句"打印有摘要链"在该状态下**是假的**，2026-09-27 已按**状态分叉**改写。

## 四、出问题了怎么办

| 现象 | 先做什么 | 不要做什么 |
|---|---|---|
| 启动报 `ext.world.VersionMismatch` | 用**本体的 `world` 版本**与事件构造器的版本对齐后重启 | **不要**手工改账本或词表去"凑" |
| 启动报 `ext.world.Ontology.BadJson` | 用备份的本体替换；确认 `python -c "import json;json.load(open('ontology.json'))"` 能过 | **不要**在坏本体上反复重试 |
| 启动报 `ext.world.Ledger.Locked: 账本已被另一个世界核心占用（…持有者 pid=… 仍存活）` | 先确认**没有第二个进程**在用同一个账本；确认持有者 pid **确已死亡**后再处理锁文件 | **不要**在持有者还活着时强删锁文件。**注意**：程序在检测到持有者已死时会**自动回收陈旧锁**并重试，故"删锁"通常**不必手工做** |
| 想"回到过去" | **追加补偿事件**（世界只追加） | **不要**恢复账本文件——那等于删除历史 |

> **一条最重要的使用纪律**：**账本只追加**。"世界回退"的正确做法是**追加补偿事件**，不是恢复旧文件。
>
> **⚠ 本版没有的两件事（不假装有）**：
> ① **没有"读模型文件"可删**——v1 的读模型**不写盘**。想重算就执行 **`world-core state`**（它每次都从账本重算）。
> ② **没有一条命令印出 `vocab_hash`**——账本里也**不记**词表 hash（只记 `world=N`）。因此"确认 `vocab_hash` 与预期一致"这一步，
> 在**本体被拒启动时无法执行**；能看 hash 的场合是 `world-core project language | head -1`（首行含 `vocab=`）。
> 另需知道：**同一 `world` 版本下改动词表语义，`check` 仍会 `READY`**——要发现它，必须比对 `vocab=` 的值。

## 五、我拿不到帮助怎么办

- 本手册是**初步版**：它覆盖"能跑、能用、能查"三件事；**高级用法与运维细节在正式版**（实现阶段完成后形成，依据见附录 A）。
- 命令行的 `--help` 输出是**权威的使用入口**；任何与本手册不一致处，**以 `--help` 与正式版手册为准**。
- **但请注意**：`--help` **不打印**链状态、`vocab_hash`、锁的处置细则与退出码语义——本手册 §二.1／§三／§四 给出的正是那些内容，
  故"以 `--help` 为准"**不构成对本手册缺项的补偿**。

## 六、本手册不能证明的事

不证明性能达标、不证明门禁强度足够、不证明所有错误路径都已覆盖——**这些由 S5/S6 的度量与评审判定**。
