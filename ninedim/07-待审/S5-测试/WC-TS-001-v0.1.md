### 3.2 跨进程/跨时刻同源比对规程（`IF-003a`）

**为什么需要它**：`project check`（`cli05`）在原子里比对两份字符串——
`render` 读的是**同一个** `State`、**同一份** `vocab`（`src/gui_projection/mod.rs::assert_same_source`）。
也就是说，**在单进程路径下这个判定不可能失败**——它证明的是"函数接线正确"，不是"两个进程看到的世界一致"。
`WC-R4-DISP-001` §二 G 组第 5 行（M06-D05/D06）指出的正是这个缺口。

**`IF-003a`（规程，不是新接口实现）**——**跨进程/跨时刻比对**，四步：

1. **A 进程**：`world-core --ledger <L> project language > a.lang`、`... project visual > a.vis`；
   **A 退出**（进程结束 ⇒ 内存里的 `State` 与 `vocab` 都消失）；
2. **B 进程**：对**同一账本 L、同一本体文件**再跑一次，得 `b.lang` / `b.vis`；
3. **比对对象**（**不是**"看起来一样"）：
   - **四元组**：两份输出的首行里 `world=` / `vocab=` / `last_seq=` / `state=` **必须逐字节相同**；
   - **投影体**：用 §3.1 的**独立提取器**分别从 `a.lang`/`a.vis`/`b.lang`/`b.vis` 取出
     `(主体, 路径, 值)` 的**扁平三重集合**，按"主体升序 → 路径升序"排序后比较；
   - `a.lang` vs `a.vis`：**同一进程内的两投影**必须一致（即 `REQ-F-020` 的原口径）；
   - `a.lang` vs `b.lang`、`a.vis` vs `b.vis`：**跨进程**必须逐字节相同；
4. **反例（必须会红的那一半）**：把本体文件的**语义字段**改一处（换词表）后再跑 C 进程 ⇒
   `vocab=` **必须不同**，且第 3 步的比对**必须判"不同源"**。若换了词表仍判同源 ⇒ **用例失败**。

**用例**：`crossproc01`（第 1–3 步，正向）／`crossproc02`（第 4 步，反向）。
**归属**：L0/CLI（跑真实二进制），与 `cli07`/`cli08` 同面；`cli07` 是它的**最小形态**。
**用例编号**：`crossproc01`/`crossproc02` 是**用例级编号**；`WC-SRS-001` §五 本轮（2026-09-26）**未为跨进程同源分配 `TC-0xx`**（新增的 `TC-042`–`TC-051` 中无对应项）⇒ **编号待 SRS 分配**，在此之前不得写入 `WC-RTM-001`。
⚠️ **状态：尚未实现**；`IF-003a` 的**编号载体**（`WC-IC-001` §2.5/§2.5.1）**不属本次执行员所有** ⇒

### 3.3 `M-03` 度量规程的可判定化（**判据改写的落点在别处**）
