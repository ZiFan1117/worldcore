## 2 总体描述

### 2.1 产品前景

本系统为通用订单受理服务的参考实现，领域中立，可替换为任意"提交—校验—落库—查询"业务。

### 2.2 产品功能概览

| 功能 | 关联需求 |
|---|---|
| 订单提交 | REQ-F-001 |
| 金额上限校验 | REQ-F-012 |
| 订单查询 | REQ-F-019 |
| 响应性能 | REQ-N-004 |

### 2.3 用户特征

单一角色：业务操作员，具备基本计算机操作能力。

### 2.4 约束

- 运行环境：单机部署，无需分布式协调；
- 语言与依赖：Python 3.10+，标准库优先。

### 2.5 假设与依赖

| 编号 | 假设 | 验证时点 | 状态 |
|---|---|---|---|
| A-01 | 订单号生成器与校验器使用同一套规则 | M80 实现时 | 已验证 |
| A-02 | 单机部署，无需分布式锁 | S5 压测时 | 待验证 |

## 3 具体需求

### 3.1 外部接口需求

| 接口编号 | 名称 | 类型 | 说明 |
|---|---|---|---|
| IF-001 | 提交订单 | 同步 | 入参金额与日期，出参成功标志与订单号 |
| IF-002 | 查询订单 | 同步 | 入参订单号，出参订单详情 |

### 3.2 功能需求

#### REQ-F-001 提交订单

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源 | 业务方访谈记录（示例） |
| 描述 | 操作员提交合法金额的订单，系统生成唯一订单号并落库 |
| 输入 | 金额（数值）、业务日期 |
| 处理 | 校验金额合法性 → 生成订单号 → 落库 |
| 输出 | 成功标志、订单号、提示信息 |
| 异常与边界 | 金额为空/为零/为负 → 拒绝并给出明确提示 |
| 验收准则 | 合法金额提交后返回 `success=true`，订单号符合 `ORD-YYYYMMDD-NNNN`，且可被查询到 |
| 关联设计模块 | M01、M20 |
| 关联测试用例 | TC-001、TC-101、TC-201、TC-301 |

#### REQ-F-012 单笔订单金额上限校验

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 来源 | 风控要求（示例） |
| 描述 | 单笔订单金额不得超过 100000.00 |
| 输入 | 金额 |
| 处理 | 与上限比较 |
| 输出 | 超限则拒绝，提示"单笔金额不得超过 100000.00" |
| 异常与边界 | 金额 == 上限 → 通过；上限 + 0.01 → 拒绝；拒绝时不得落库 |
| 验收准则 | 超限请求返回失败且订单表记录数不变 |
| 关联设计模块 | M20 |
| 关联测试用例 | TC-003、TC-103、TC-203、TC-303 |

#### REQ-F-019 订单查询

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 来源 | 业务方访谈记录（示例） |
| 描述 | 按订单号查询订单详情 |
| 输入 | 订单号 |
| 处理 | 按订单号检索 |
| 输出 | 订单详情或空 |
| 异常与边界 | 不存在的订单号 → 返回空，不抛异常 |
| 验收准则 | 已落库订单可查回且金额一致；不存在的订单号返回空 |
| 关联设计模块 | M20、M40 |
| 关联测试用例 | TC-005、TC-105、TC-205 |

### 3.3 性能需求

#### REQ-N-004 单笔订单响应时间

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 在基准负载下，提交订单接口响应时间 P95 不超过 200ms |
| 度量方法 | 连续 1000 次提交，取 P95 分位 |
| 验收准则 | P95 ≤ 200ms，且错误率为 0 |
| 关联设计模块 | M01、M20、M80 |
| 关联测试用例 | TC-110、TC-210、TC-310 |
