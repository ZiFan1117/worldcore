## 三、★★ 融完之后：我们这一层的位置（一句话）

> **六路参考合起来是一条链**（定名 → 链 → 交互 → 插头 → 底座 → 词表），
> **但它们六个都不提供「这一层」**：那条链需要一个**各方共同依赖、在所有参与者之下**的语义权威。
> **那个位置就是我们。**

★ 而这件事**拿到了标准侧的最强支持**：RFC9315 的**原则 1** 逐字说「那组『被验证过的意图表达式』**就是该系统的单一真相源**」，并把它与运行状态一起用来**判漂移**、用来**可追溯** —— 这正是我们书里「共同依赖的那一层」的说法。**别人是在网络管理里发现这个必要的；我们是在机器整体上把它立成一层。**

## 四、★ 一条警示，直接对我们适用：**intent-washing**

RFC9315 末尾逐字警告：「**光给旧概念换个『意图』的说法，就把它粉饰成新的**」（这正是它要把「意图」与**策略**、**服务模型**划开的原因）。

⇒ **翻成我们的四条自查**：

1. **不许**把「给旧接口包一层」叫成**本体**；
2. **不许**把「提示词里多写几个动作名」叫成**能力暴露**；
3. **不许**把「界面换皮」叫成**语义面板**；
4. **不许**把「账本里记了一条、但谁都没读」叫成**已落位**（本仓旧读数就是这么翻绿的：`UndeclaredEntity` 实现之前，那条记录确实落笔了）。

**提议**：把这四条落成一条**会红的判据**（查「换名不换物」）—— 但这是**产品活**，进方案，不夹在本件里。

## 五、★ 十四条「不能借」（照清单 §六 原样保留，接缝一多最容易顺手借错）

| # | 不能借的 | 为什么（我们的口径） |
|---|---|---|
| 1 | JSON Schema「缺关键字 ＝ 通过」 | 与我们 `default = deny`、`DeadCapability` **方向相反**；借进来会把「没声明」变成「合法」 |
| 2 | JSON Schema「类型不符 ＝ 视为通过」 | 同上：判据要求类型也对 |
| 3 | AG-UI 的「预留位」 | 本仓口径：**今天没装智能体 ⇒ 不许为智能化预留格** |
| 4 | MCP 的 `tools`／`prompts`／`resources`／`sampling` 四格 | 主体是**语言模型** |
| 5 | A2A 的 `AgentCard`／`TaskState` | 同上；**只借**「状态要标终点／中断」的形状 |
| 6 | WoT 的协议绑定表（HTTP 方法＋URL） | 我们**今天没有对外网络面**；只借「每个可调用单元必须写清怎么调」 |
| 7 | Solid 的 HTTP 动词→权限映射 | 我们的入口是**信封与账本**，不是 HTTP 动词 |
| 8 | DID／VC 的密码学面 | **今天没有任何签名设施**；借了就是「没做到写成做到了」 |
| 9 | openEHR 的两层建模全体系 | 太重；我们是「**一份世界本体＋实例声明**」，不引第二层语言 |
| 10 | Sparkplug 的 Birth／Death 依赖 MQTT Will | 我们没有 MQTT；只借「出生时一次列全」 |
| 11 | Nostr 的 kind 号段约定 | 那是**社区约定**不是判据；只借「同刻取 id 最小」 |
| 12 | AsyncAPI 的 channel／operation 模型 | 我们的「通道」是**信封＋账本**；只借「声明即承诺＋例外池」 |
| 13 | A2UI 的「由 agent 生成界面」那一层 | 主体是 agent；只借「目录白名单＋没相容目录就不发」 |
| 14 | WoT 的「实例可以不实现可选项」 | 我们口径是**声明了就必须有实现** |

**★ 这 14 条要原样带进 AIOS 那一边**（缝进去的东西一多，最容易顺手把不该借的一起借过来）。
