# Design

## Context

断言缺口的来源、以及"为什么它们必须与规格同批存在"，见 `fc-2026-002-spec-revisions/design.md`
（那份 change 已把每条的 `audit.md` 编号与规格落点写全）。本件只做"把断言写出来"。

## Goals / Non-Goals

**Goals**：**34 条**逐条落地（★ 2026-09-28 订正：原写"37 条"**无出处**。复算＝`fc-002` 的组 2–6 逐组计数：组 2＝7／组 3＝5／组 4＝8／组 5＝6／组 6＝8 ⇒ **34**；仓内另有 35／37 两个数，均与账不符），每条都能用**变异**证明会红（改坏实现的一行 ⇒ 该断言红）。
**Non-Goals**：不改规格条文、不改产品行为、不新增能力。

### **两处**让路登记（2026-09-28 补，独立评审席判「不通过」后的整改；**★ 首版只登记了一处、实际是两处**）

本 change 动了主规格的**两处能力**（`ledger-integrity`／`read-model`；★ 首版只写了 `0a77d26` 那一处，第二轮改成"两次"——**而"两次"在第三轮的提交里又过期了**）⇒ **逐提交清单以 `git log --all -- specs`（**限本 change 的提交**）为准，本处不复述次数**：
① `0a77d26` → `ninedim/01-意图环/04-规格/ledger-integrity.spec.md`；
② `3ba916f` → `ninedim/01-意图环/04-规格/read-model.spec.md`。
两处都是**同一种改动**（把**行号引用**改成**步骤名**）。以 ① 为例，`ninedim/01-意图环/04-规格/ledger-integrity.spec.md` 里
「（`check.sh.new:145` 执行）」⇒「（由 `check.sh.new` **第 ⑥ 步**执行——**写步骤名、不写行号**：行号会烂）」。
按本仓口径（skill §一），**让路必须写全三要素**，故照办：

| 让路三要素 | 内容 |
|---|---|
| **让的是哪一条** | 上面那句**把引用写成行号**的口径——它属"**引用写命令 ＋ 步骤名、不写行号**"这条规则的**例外**；让的**不是**任何 Requirement 条文本身（那一条 Requirement 的字句未改） |
| **为什么让** | 行号是**会烂的坐标**：`check.sh:145` 在写下后已被 `check.sh` 自己的增补（`①b` 格式检查／`⑤b` RTM）**挪位**，读者照它去会扑空。改成步骤名后**加了步骤也不烂**（步骤名由脚本自己打印） |
| **谁批的** | 作者 **ZiFan** 于 2026-09-28 **追认**（追认登记＝`review.md` §7.1 的两行"追认"；**这是一次独立的、记在本档里的批准行为**）。★ 留痕：首版这里填的是**执行者自己的推断**（引作者上位指示「有问题直接改」），那属"**把未批写成已批**"，曾由评审席第二轮指出（判例引文原样保留在下方）；**在追认之前**，本处不得被引用为"已批"——**该口径已被上面的追认取代**。（判例：`archive/2026-09-28-fc-2026-002-spec-revisions/review.md` 逐字「这次"先并后归"**不满足** H-14 第 6(ii) 条…属**未授权变更**」；`cover-remaining-capabilities/tasks.md` 逐字「要让路就要写清"谁让、为什么、谁批的"」） |

**★ 第 5 例（执行者自己的假话，留痕）**：执行者在 2026-09-28 的进度报告里说"判据⑭ 已提交、读数 15/0"，而**那一笔 `git commit` 的返回码是 1**（`Your branch is up to date`／`no changes added to commit`）——**什么都没进仓**；`15/0` 是**工作区**的读数、**不是已提交状态的读数**。⇒ 教训与前面四处同源：**"跑通了"不等于"提交了"**，**提交后必须核 `git log -1` 与远端 sha**。
⇒ 本件 `tasks.md` 的 6.3 自称**已按双坐标改写**（原写「`ninedim/01-意图环/04-规格/**` 零改动」**是假话**，只对"当时"成立——见该条的「★ 订正」，那里写明"不许被引用为『本 change 未越界』"）。

## Decisions

1. **每条断言必须配一个变异点**（"改坏哪一行 ⇒ 它变红"）——否则它可能是恒绿的装饰。
2. **方向已变的两条先重写再补**（`3.3`／`3.4`）：照搬原措辞会写出与实现相反的断言。
3. **归属**：本件是"断言账"，不与 `cover-unimplemented-capabilities`（能力缺口账）混同——
   前者是"规格写了、没测试"，后者是"书要求了、没实现"。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 为了把断言写绿而放宽断言 | 决策 1（变异证明）＋ 评审席抽查 |
| 与 `cover-*` 的条目重复 | 决策 3：两边各写"归属"，重复时以"书要求／规格要求"为界 |

## 排除清单

- 不改 `src/**` 的行为（只允许为了让断言可写而补**测试**）。
- 不动书、不动规格条文。

## Migration Plan

逐组补断言 ⇒ 每组跑 `cargo test --locked` ＋ 变异证明 ⇒ 全绿后归档。
