# Design

## Context

项目走到今天，文档**长成了两套**：一套是"现在是什么"（规范、正文），一套是"我曾经写错什么、谁让我这么改的"（修订记录、改因块、评审判词）。
两套混在一起以后出了三个具体后果：

1. **读者找不到规矩**——`WC-SRS-001` 一条需求的判据格里，前半是规范、后半是"原写…现改为…"；
2. **形态门禁报警**——六份主规格判出 **28 条** `Requirement text is very long`，因为改因块与证据行一起被算进 requirement text；
3. **文档散开**——`WC-IC-M01`–`M10` 十一册 ＋ 总则册，同一件事有 12 个说法。

作者对此下了明确指示（见 proposal 的逐字引文），并要求把这套工作方式**固化成 skill**：`.agents/skills/worldcore-sdd/SKILL.md`（已立）。

## Goals / Non-Goals

**Goals**：① 流程文档里**没有**修订记录节；② 规格正文里**没有**改因块；③ 接口契约**一册**；④ 检查**并进既有门禁**、不另立探针；⑤ 上面四条**都有机器项**，不靠自觉。

**Non-Goals**：不改产品代码；不改任何 Requirement 的 SHALL/SHALL NOT；不新增阶段文档（S5/S6/S7 的正文**不在本 change**——写它们要有真的测试与验收数据，编不出来）；不动书（`docs/理论/语义世界-理论书-第一版-合订.md`）。

## 影响分析

| 面 | 影响 |
|---|---|
| 规格树 | 正文变短（删过程证据）；**Requirement 标题、Scenario、`- **证据**：` 行逐字不动** ⇒ 守卫判据②④ 与 delta 的标题匹配**不受影响** |
| 流程文档 | 26 处节被删；**其中有当前有效值（批准人／批准日期之类）的，搬进该文档正文对应位置** |
| 门禁工具 | `module_graph.py` 判据③ 的"契约落点"从"分册存在"改为"在 `WC-IC-001` 里找得到该模块节"；**判据①②不许动** |
| 可追溯性 | 修订史由 **git 提交历史**承担（`git log -p -- <path>`）；change 的来龙去脉在该 change 的 `design.md`／`audit.md` |
| 风险面 | 删多了 ⇒ 用"每块先在别处找到同一事实"来挡（见 Decisions 2） |

## 方案对比

### 方案甲 · 就地删＋必要时搬

删掉过程证据；**删之前先在别处（该 change 的 `design.md`／`audit.md`）确认同一事实存在**；找不到的**搬**过去，不丢。

### 方案乙 · 不改（或最小改）

只加一句"本件含历史记录，读者请只看规范句"。**否决**：那正是"让读者自己分辨"——他要的是规矩，不是考古；而且形态门禁的 28 条 INFO 不会消失。

## Decisions

1. **修订记录的唯一去处＝git 提交历史**。理由：它天生是"按时间发生的一串事"，`git log` 就是干这个的；把它复制进正文等于**两个权威载体**（skill §八）。
2. **删之前先证明"别处有"**。每一块被删的过程证据，都要在对应 change 的 `design.md`／`audit.md` 里给出 `path:line`。**找不到就不许删**，改成搬。
3. **契约并册但工具判据不削弱**：判据③ 今天有两条**真红**（M10 测试缺、`src/error.rs` 无模块号认领）——并册**不许**让它们消失。判据是"缺口可见"，不是"文档整齐"。
4. **探针归位**：检查并进既有门禁脚本；数据用已声明实体。理由：探针是"为了检查而另造的东西"，它自己就要被维护、被声明、被评审；而它写未声明实体时**本身就违法**——这不是探针的错，是"另造"这个做法把检查与被检查拆成了两套。
5. **两条机器项先立**（守卫判据⑧⑨，`ae57fb7` 已落）：纸面规矩不算数，**规矩要有执行者**。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| **删掉了唯一的解释** | 决策 2（先在别处找到同一事实；找不到就搬）＋ 改前改后逐能力 Requirement/Scenario 计数必须相等 |
| **并册把判据③ 弄成永远绿** | 决策 3：并册前后 offender 清单必须一致，且**逐条列出** |
| **有人把"删修订记录"理解成"删历史"** | 本件写明：历史在 git 里，`git log -p -- <path>` 随时可查；并给一条命令示例 |
| **改动期间三工区并发** | 每个工区**独占文件**；跨了就是事故（skill §十四） |

## 排除清单

- **书**（`docs/理论/语义世界-理论书-第一版-合订.md`）：一个字不动。它的附录体例由作者定，不受本 skill §三 约束。
- **S5／S6／S7 的正文**：不写。它们要有真的测试与验收数据；编不出来就不写（"不许把没做到写成做到了"）。
- **`REQ-` 编号体系**：不动。
- **产品代码**：不动（本 change 零代码改动）。

## Migration Plan

1. 先落**机器项**（判据⑧⑨）⇒ 让违规可见、可复算；
2. 再清**规格正文**（面最大、最可机械核对：Requirement/Scenario 计数必须不变）；
3. 再清**流程文档 ＋ 并册**（要动 `module_graph.py` 判据③，故放在规格之后）；
4. 最后**探针归位**（要动门禁脚本，且必须在 VM 上跑通 `check.sh`）。

**回退点**：每一步一次提交；回退＝`git revert <该步提交>`。
