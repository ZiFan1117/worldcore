## §三 ★★★ 但跑链时暴露一个竞态（★ 如实）

### 三.1 ★ 现象（★ 逐字）

```
[执行体] ★ 本体没回话（StorageUnavailable：<超时：请求发出去了，回话没回来>）⇒ 注册不上；★ 本体要先起
[执行体] ★ 注册完成：发出 5 条，本体收下 4 条
注册表：4 行
```

★★ **上一笔（T-278）是 11/11 全成功；★ 这一笔是 4/5** ⇒ ★ **不是稳定成功** ✗

### 三.2 ★★★ 根因（★ 是【口】的问题，不是本体或执行体写错）

```
★ 本体侧的登记循环：
    loop {
        let msg = t.take("world/register", 30s);   ← ★ 每次 take 才 declare_subscriber
        ... 处理 ... 回话
    }
★★ 而 take 返回一条之后，★ 下一个 take 才【重新订阅】 ⇒
    在这个「返回 ⇒ 重新订阅」的空窗里，★ 执行体的下一条请求就丢了 ✗
```

★★★ **这与我 T-278 修的那个是同一类错**（★ 那次是**请求-应答**的次序）★ —— ★ **这次是【订阅生命周期】**：★ **`take` 每次新建订阅 ⇒ 有空窗** ✓

### 三.3 ★★ 修法（★ 下一笔做，或你定优先）

```rust
// ★★ 把「订阅」也收进口里（与 request 同族）：
pub trait Transport {
    fn subscribe(&self, topic: &str) -> Admit<Box<dyn Subscription>>;
}
pub trait Subscription {
    fn recv(&self, timeout: Duration) -> Admit<String>;
}
// ★ 订阅【一次声明、长期持有】⇒ 没有空窗。
```

★★ **一句**：★ **「订阅的寿命」和「请求-应答的次序」一样，★ 都不能交给调用方 —— ★ 要由口保证。**
