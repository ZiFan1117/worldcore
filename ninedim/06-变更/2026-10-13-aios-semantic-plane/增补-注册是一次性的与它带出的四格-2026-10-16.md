# 增补：**注册是一次性的（持久）** —— 以及它带出的四个格子（2026-10-16）

> ★ **作者话（逐字）**：「**注册是直接注册，上一次就不用注册了，对吧，对，然后需要人来点推送的界面人来点对吧**」。
> ★ **两句答**：★★★ **① 对 —— 注册是一次性的、持久的**（★ 注册过就在本体里，★ 下次启动不用重注册）；★★ **② 对 —— 要人批的时候推给界面，人点**。

---

## §一 ★★★ 为什么「注册必须持久」（三条理由）

| # | 理由 |
|---|---|
| **1** | ★★ **本体是一份 JSON 文本** —— ★ 注册**写进它**，★ 下次启动读回来就有 ⇒ ★ **不需要重注册** |
| **2** | ★★ **「不注册 ＝ 不存在」的反面**：★ **注册过就一直在** |
| **3** | ★★★ **如果每次启动都要重注册 ⇒ 本体就不是权威了** —— ★ 「**谁先启动、谁说了算**」，★ 而且★ **没人启动时那 9 条也不算数** ⇒ ★ 这与「本体是唯一权威」直接冲突 |

★ 所以：★ **注册是一次性的动作**；★ 平时只是**读**本体（★ 这正是「不持副本、要问」那条）。

---

## §二 ★★★ 但「持久」带出四个新格子（★ 我该主动指出）

| # | 格子 | ★ 为什么必须有 |
|---|---|---|
| **1** | ★★★ **注销 / 失效** | ★ **软件卸载了、或者不在了**，★ 它的动作**不能还假装能调** —— ★★ 否则「**在册**」变成一句**假话**（★ 在册的东西叫不动） |
| **2** | ★★ **更新（重注册）** | ★ 同一个软件**升级**了、★ 参数形状变了 ⇒ ★ **要能更新** —— ★ 而★ 今天的规则是「**重名就拒**」⇒ ★★ **拒得对（防冒充），但升级这条路要有**（★ 例如：★ 同一个 `registered_by` 可以替换自己的条目，★ 别人不行） |
| **3** | ★★ **在册 ≠ 活着** | ★★ **最要紧的一格**：★ 「走总线调它」时 ★ **对方可能不在**（★ 没启动、★ 崩了）⇒ ★ **调用会失败** ⇒ ★★ **本体必须分得清两件事**：★ **在册**（这个名字**存在**）／★ **活着**（现在**叫得动**） |
| **4** | ★ **报到（心跳）** | ★ 实现第 3 格的办法：★ **软件启动时向本体报一声「我起来了」**，★ 退出时报一声（或让它过期）⇒ ★ 于是「活着」这件事**有读数** |

★★★ **一句话**：★ **注册是一次性的；但「它还在不在」是每次都要问的。**

## §三 ★★ 举例子：装、升级、卸载 三件事怎么办

### ① 装了一个下载器

```
★ downloader 启动 ⇒ 它向本体注册：
     download.start { url: string }   谁注册的=downloader   类别=app
     endpoint = bus:world.fn.download.start
★ 本体把它【写进本体那份 JSON】（★ 只增）⇒ ★★ 从此【一直在】
★ 它再启动（第二次、第三次…）⇒ ★★ 【不用再注册】—— ★ 只要【报个到】：「我起来了」
```

### ② 它升级了（参数变了）

```
★ 原来的 download.start { url: string }
★ 升级后想变成  download.start { url: string, quality: enum(low,high) }
★ 它再来注册 ⇒ ★ 今天规则「重名即拒」⇒ ★ 【拒】
★★ 但它【是同一个 registered_by】⇒ ★ 应允许它【替换自己的条目】；
     ★★ 若是【别的软件】想占这个名字 ⇒ ★ 【必须拒】（★ 防冒充）
```

### ③ 它被卸载了

```
★ 它走了 ⇒ ★ 本体里那条【还在】⇒ ★ 有人调 download.start
★ 走总线过去 ⇒ ★★ 【没人接】⇒ ★ 调用失败（FAILED，★ 不是 REFUSED —— ★ 不是「不许」，是「没人」）
★★ 所以：★ 「在册」照旧（★ 名字还是它的），★ 但「活着」是【否】
★ 若它【永久】不回来了 ⇒ ★ 由人【注销】它（★ 注销是人的动作，★ 与注册不同）
```

## §四 ★★ 方案里「注册面」那一件要补什么

| # | 原（主文 §三·三） | ★★ 补 |
| **1** | ★ 「运行时注册：谁交／交什么／怎么校验；注册落进本体（只增）」 | ★★ 加一句：★ **注册是【一次性、持久】的** —— ★ 第二次启动**不重注册** |
| **2** | ★ 「重名注册 ⇒ 拒」 | ★★ 细分：★ **同 `registered_by` 替换自己的** ⇒ 允许（★ 升级）；★ **别人** ⇒ **拒**（防冒充） |
| **3** | ★（无） | ★★ 加**「报到」**：★ 启动时报一声；★ 于是「**在册 ≠ 活着**」有读数 |
| **4** | ★（无） | ★★ 加**「注销」**：★ **它是人的动作**（★ 不是软件自己说走就走 —— ★ 那会成为「谁能悄悄抹掉别人的名字」的洞） |

★★ **落成的判据**（★ 形状，★ 先写会红的反例）：

| # | 判据 | 会红例 |
| **1** | ★ **在册 ≠ 活着**：★ 本体必须能分别回答这两个问题 | ★ 一个没启动的软件的动作 ⇒ 查「在册」＝**是**、查「活着」＝**否** ⇒ ★ 若两者给出同一个答案 ⇒ **红** |
| **2** | ★ **升级不算冒充** | ★ 同一个 `registered_by` 提交同名动作 ⇒ **允许替换**；★ 不同 `registered_by` ⇒ **拒** |
| **3** | ★ **注销只能人做** | ★ 软件自己发一条注销 ⇒ **拒** |
