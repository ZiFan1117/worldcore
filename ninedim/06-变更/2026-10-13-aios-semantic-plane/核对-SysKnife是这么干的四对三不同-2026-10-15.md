> ★ **本件是去它代码里核的**（料：`D:\Code\_scratch\_refs-sysknife`，143 件／87,033 行）。

## §一 ★★★ 现取：它代码里的四条事实

### 1. ★★ `ActionSpec` 五格 —— **没有参数那一格**

```rust
pub struct ActionSpec {
    pub action_name: &'static str,      // ★ 名字
    pub mechanism: ActionMechanism,     // ★ 怎么干（★ program + args）
    pub risk_level: RiskLevel,          // ★ 危险度
    pub reboot_required: bool,          // ★ 要不要重启
    pub rollback_available: bool,       // ★ 能不能回滚
}
```
★ 出处：`crates/sysknife-daemon/src/actions/mod.rs`（现取）⇒ ★★ **五格里没有「参数」**。

### 2. ★★★ 参数在**函数签名**里（现取 `actions/services.rs`）

```rust
pub fn start_service(unit: &str) -> ActionSpec
pub fn set_service_enabled(unit: &str, enabled: bool) -> ActionSpec
pub fn set_service_resource_limits(unit: &str, assignments: &[String]) -> ActionSpec
pub fn create_scheduled_job(name: &str, command: &str, schedule: &str) -> ActionSpec
```
⇒ ★★★ **参数是 Rust 的编译期类型** —— ★ **不在任何「表」里**。

### 3. ★★ 它给模型的那张表是 **`(名字, 一句话描述)`**

★ `KNOWN_ACTIONS` 的逐字注释（现取）：
> 「Each entry is **`(action_name, one-line description)`**. ★ The description is surfaced in the `action_name` field of the `propose_plan` tool schema so the model can reason about which action to pick from its *purpose* rather than just its name.」
⇒ ★★ **模型看到的：名字 ＋ 一句话**（★ **没有参数形状**）。

### 4. ★★ 它**没有独立的「函数」层**

★ `sysknife-types` 里的类型（现取）：`DistroHint`／`ActionName`／`UnknownActionName`／`RequestHash`／`TransactionId`／`ApprovalReceipt`／`CallerRole`／`RiskLevel`／`JobState`／`FailureCategory`／`BridgeError`／`RequestEnvelope`／`PreviewEnvelope`／`ResultEnvelope`／`TransactionRecord`
⇒ ★★ **没有 `Function` 这一类** —— ★ **动作就是动作**（★ 我方有 `actions.*` ＋ `functions.entries` **两层**）。

## §二 ★★ 所以「是这么干的」—— ★ 对四条 ＋ 不同三条

| | 事 | ★ 它 | ★★ 我们（现取） |
|---|---|---|---|
| **对 1** | ★ **一张动作表** | ★ `KNOWN_ACTIONS`（**189 条**：名字＋描述） | ★ `actions` 表（**9 条**） |
| **对 2** | ★ **每个动作一个机制** | ★ `ActionMechanism::Command{ program, args }`（★ **结构化**，不是字符串） | ★ **没有这一栏**（★ 且**明令不许写进本体**：`_no_command_literal` ⇒ 红） |
| **对 3** | ★ **按域分** | ★ **40 个模块文件** | ★ **5 个名字前缀**（notice/job/ledger/world/presence） |
| **对 4** | ★ **模型只选名字，命令由下面拼** | ★ 逐字：「**The model selects the action; the daemon builds the command**」 | ★ 同一件事（★ T-187：本体给名字，那个进程拼命令） |
| ★★ **不同 1** | ★★ **参数放哪** | ★★ **在 Rust 函数签名里**（编译期） | ★★ **在本体**（`functions.entries.<fn>.inputs` ＋ `output_type`） |
| ★★ **不同 2** | ★ **有没有「函数」层** | ★ **没有** | ★ **有**（`actions.*` 一个动作 ↔ `fn.*` 一个入口名，★ 且 `actions.<名>.function` 指针 **9/9**） |
| ★★ **不同 3** | ★ **机制那栏** | ★ **写死在表里**（`program` ＋ `args`） | ★★ **不在本体**（★ 要放**运行时装的表**；★ 进本体 ⇒ 判据红） |

## §三 ★★★ 最要紧的一条差别：**参数在哪**

| | ★ SysKnife | ★★ 我们要的 |
|---|---|---|
| 参数形状的所在 | ★ **Rust 函数签名**（★ **编译期**） | ★★ **本体 `inputs`**（★ **数据**） |
| 谁知道「要什么参数」 | ★★ **只有编译过它的代码** —— ★ 模型只拿到「名字＋一句话」 | ★★ **任何一方读本体就知道** |
| 猜错的后果 | ★ 由 daemon 的参数校验兜住（★ 它有 2,521 行的 `validate.rs`） | ★ **根本不用猜**（★ 形状是公开的） |

⇒ ★★★ **一句话**：★ **它是「名字公开、参数藏在代码里」；我们要求「名字和参数形状都公开」。**
★ 这正是「本体」这两个字的意思 —— ★ **不然「要什么参数」就只有编译过的人知道**。

## §四 ★ 仿它的正确姿势（三条）

| # | 仿什么 | 不仿什么 |
|---|---|---|
| **1** | ★★ **一张表，一个动作一个机制**（★ 它的「一览」形态） | ★ **它的动作名**（★ 实现驱动；★ 它分了 Fedora／Ubuntu 两套） |
| **2** | ★ **按域分文件/分区** | ★ **它的 40 个域清单**（★ 从**我们的对象类**长） |
| **3** | ★★ **「模型只选名字，命令由下面拼」** | ★★ **「参数藏在代码里」** —— ★ **我们的参数形状要在本体里** |

★ 另：★ **它的机制那栏（`program+args`）我们不照搬进本体** —— ★ 放**运行时装的表**（★ 照 08 `cap.d`），★ 本体只收**入口名**。
