# 说明（走一遍）：**「查看文件夹」这件事，现在该怎么办** —— 参数放哪、怎么干、逻辑是什么（2026-10-15）

> ★ **作者问（逐字）**：「**现在就实现，比如说查看文件夹这个功能……以前的命令还是 `ls` 什么什么，那现在我们该怎么办呢？参数应该放在哪里呢？你是怎么个实现逻辑呢**」。
> ★ **本件就干一件事**：★ **拿 `ls` 这个例子，从头到尾走一遍**，并把「哪些今天有、哪些今天缺」逐格标出。

## §一 ★ 先看「以前」是怎么走的（对照用）

```
人敲：ls -l /home
  ├ 名字：ls              ← ★ shell 靠 PATH 找可执行文件
  ├ 开关：-l              ← ★ 参数
  ├ 对象：/home           ← ★ 参数
  └ 谁解析：shell（★ 一个字符串，靠约定拆）
⇒ 内核 syscall ⇒ 列目录 ⇒ 打印
★ 问题：★ 这条命令**没有任何地方登记过**「ls 是什么、能干什么、谁能用」
```

## §二 ★★★ 现在（语义世界）：把它**拆成五样东西**

| # | 样东西 | ★ 本例的值 | ★ 放哪 | 今天有没有 |
|---|---|---|---|---|
| **1** | ★ **在册的名字** | ★ `fs.list`（★ 域＝`fs`） | ★ **本体**（动作表） | ★ 有机制（★ 但 `fs.list` 没登记） |
| **2** | ★ **函数的入口名** | ★ `fn.fs.list` | ★ **本体**（`functions.entries`） | ★ 有机制 |
| **3** | ★★ **参数的形状** | ★ `{ path: string, long: bool }` | ★★ **本体**（该动作/函数的 `inputs`） | ★ **有格**（★ 现取：`inputs` 就在） |
| **4** | ★★★ **怎么干**（实现） | ★ provider ＝ `fs`（★ 至于 `opendir/readdir` 还是 `ls`——★ **在代码里**） | ★★★ **运行时装的表**（照 08 `cap.d`）＋ **代码** | ★★ **没有**（★ 这一栏今天不存在） |
| **5** | ★★★ **这一次的参数值** | ★ `path = "/home"`、`long = true` | ★★★ **那一次的消息里**（★ 不进本体） | ★ 有（★ 帧里就是） |

⇒ ★★★ **一句话回答「参数放哪里」**：

> ★★ **参数的【形状】放本体（法律）；★ 参数的【值】放那一次的消息（事件）。**
> ★★ **「怎么干」放运行时装的表 ＋ 代码；★ 它【不进本体】。**

## §三 ★★★ 实现逻辑（六步，可复述）

```
① 谁在说话           ⇒ ★ 身份（不许自填）                      【今天缺】
② 这个名字算不算数   ⇒ fs.list 在册吗？不在册直接拒              【★ 今天有机制（未登记即拒）】
③ 参数对不对         ⇒ path 非空吗？类型对吗？                  【今天缺】
④ 谁有权             ⇒ 只读动作要不要权（★ 通常不查权）          【今天缺】
⑤ 怎么干             ⇒ 查表：provider=fs ⇒ 代码执行 ⇒ 拿回结果   【今天缺（没有那一栏）】
⑥ 记账               ⇒ 谁、何时、要了什么                       【★ 今天缺（账未落地）】
```

★ **只读这一类的一个特别之处**：★ 它**不是「变更」**（★ 世界不变）⇒ ★ 它属于书里**三类话的「请求与结果」**（★ 书逐字：「**请你做什么、做完了还是做不到**」）；★ 但★ **书第 3 条线「接入唯一入口」照样管它** —— ★ **连只读也不许从旁边偷偷走**。

## §四 ★★ 把 `ls -l /home` 逐段对上（★ 这张表能一次说清）

| 以前 | ★★ 现在 | 说明 |
|---|---|---|
| ★ `ls` | ★★ **`fs.list`**（在册名） | ★ 名字进本体 |
| ★ `-l` | ★★ **参数 `long: true`** | ★ **形状**（`bool`）进本体；★ **值**在那次消息里 |
| ★ `/home` | ★★ **参数 `path: "/home"`** | ★ 同上 |
| ★ ★ **命令本身在哪**（★ `ls` 这个二进制、它的路径） | ★★★ **不在本体** —— ★ 它在**运行时装的表**（`provider=fs`）＋ **代码**里 | ★ 这就是「实现能在本体之外」 |
| ★ 谁解析 | ★★ **本体**（名字门＋参数形状） | ★ 不再靠 shell 的约定拆字符串 |
| ★ 结果在哪 | ★★ **账上一笔**（谁、何时、要了什么） | ★ 不是只打印一下 |

★ 那份**运行时装的表**长这样（照 08 `cap.d`，10 行一件）：

```json
{ "capability": "fs.list", "provider": "fs", "verbs": ["list"],
  "risk": "low", "undo": "never", "confirm": "never", "preview": true }
```
★ **注意**：★ **这张表里也没有命令** —— ★ 它只说「**这件事交给 `fs` 这个执行器**」；★ **`fs` 到底怎么干，在代码里**。
（★ 这也是为什么它**违反不了**那条判据：★ 本体里连这张表都没有，★ **本体只有 `fs.list` 这个名字**。）
