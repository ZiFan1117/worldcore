# 引擎和本体什么关系 ＋ **本体进程该实现什么框架**（2026-10-17）

## §一 ★★★ 引擎和本体什么关系（★ P 的现取）

### §一·1 ★★★ P 的目录划分（现取）

```
foundry_ontology/
├── core/           ← ★★ 本体的【声明面】（名词）
│   ├── ontology.py        （Ontology：5 个 register_*）
│   ├── object_type.py／link_type.py／action_type.py／function.py／interface.py
│   └── data_types.py
├── engine/         ← ★★ 【运行面】（动词）
│   ├── object_store.py    （存对象实例）
│   ├── action_executor.py （执行动作）
│   ├── audit_log.py       （记账）

├── export/         ← 导出（json／owl／shacl）
```

### §一·2 ★★★ 依赖方向（★ 逐字 import）

| ★ 文件 | ★ import |
|---|---|
| ★ `engine/action_executor.py` | ★ `from foundry_ontology.core import ActionType, Ontology` |
| ★ `engine/object_store.py` | ★ `from foundry_ontology.core import Ontology` |
| ★ `engine/query_engine.py` | ★ 只依赖 engine 内部 |
| ★★ **`core/*` 有没有 import engine？** | ★★ **没有**（★ core 是纯声明） |

★★★ **⇒ 依赖【单向】：★ `engine → core`**

### §一·3 ★★★ 所以「是不是调用整个本体」—— ★ **是**

★ 逐字：★ `def __init__(self, ontology: Ontology, store: ObjectStore, audit: AuditLog)`
★★ **⇒ 引擎【持有一个本体实例】**，★ 每次干活前**向本体查**（★ 查类型、查动作、查校验规则）；
★★★ **而本体【不知道】引擎存在** —— ★ 它是**纯声明**，★ **不执行任何东西** ✓

★★ **一句话**：★ **本体是【名词的权威】，引擎是【动词的执行】；引擎调用本体，本体不认识引擎。**

## §四 ★★★★ 本体进程该实现什么框架（★ 答案：**六件 ＋ 三不做**）

### §四·1 ★★★ 该有的六件

| # | ★ 件 | ★ 它干什么 | ★ 我们代码里有没有 | ★ 本体进程今天接了吗 |
|---|---|---|---|---|
| **1** | ★ **装载** | ★ 读 `ontology.json`（★ 装不上不许启动） | ★ `core/registry.rs` ✓ | ★★ **接了** ✓ |
| **2** | ★ **声明查询** | ★ 类／动作／关系／函数／接口的形状 | ★ `core/registry.rs` ＋ `aios-ontology` crate ✓ | ★★ **接了** ✓ |
| **3** | ★ **注册** | ★ 收名、校验、落盘（★ 在册表） | ★ `core/registration.rs` ＋ `command_bridge.rs` ✓ | ★★ **接了** ✓ |
| **4** | ★ **个体** | ★ 谁活着、谁是什么（★ 个体表） | ★ `core/registration.rs::Individuals` ✓ | ★★ **接了** ✓ |
| **5** | ★★ **许可／门禁** | ★ 「谁能做什么」—— ★ **本体是唯一耦合点** | ★ `governance/permit.rs` ✓ | ★★ **没接** ✗ |
| **6** | ★★ **账** | ★ 只追加记录 | ★ `engine/ledger.rs` ✓ | ★★ **没接** ✗ |
| (7) | ★ **总线口** | ★ 收发消息 | ★ `engine/transport.rs` ✓ | ★ 接了（★ 但收不到）◐ |

★★★ **⇒ 六件 ＋ 一个口；★ 今天接了 4 件半**（★ 缺 **许可** 和 **账**）✗

### §四·2 ★★★ 三不做（★ 这是「本体不许变成业务系统」的落法）

| # | ★ 不做 | ★ 归谁 |
|---|---|---|
| **1** | ★★ **不执行动作**（★ 查映射表、起进程） | ★ `engine/execute.rs` ⇒ ★ **载体进程** |
| **2** | ★★ **不渲染**（★ 投成 A2UI 帧） | ★ `engine/project.rs` ⇒ ★ **GUI 进程** |
| **3** | ★★ **不碰机器**（★ 读 `/proc`／写 `/sys`） | ★ **载体进程**（★ 载甲／载乙） |

## §五 ★★★ 那「引擎」在我们这里【碎成了三份】（★ 这才是关键）

★ P 的 `engine`（★ object_store／action_executor／audit_log／query_engine）★ —— ★ 我们**拆成三个进程**：

| ★ P 的 engine 模块 | ★ 我们的 | ★ 归哪个进程 |
|---|---|---|
| ★ `action_executor`（★ 执行动作） | ★ `engine/execute.rs` | ★★ **载体** |
| ★ `audit_log`（★ 记账） | ★ `engine/ledger.rs` | ★★ **本体**（★ 因为「账只有一处」，★ 而本体是唯一权威） |
| ★ `object_store`（★ 存对象） | ★ `core/registration.rs::Individuals`（★ 个体表） | ★★ **本体** |
| ★ `query_engine`（★ 查询） | ★ `engine/query.rs` | ★★ **本体**（★ 查在册／查个体） |

★★★ **⇒ 所以「引擎」这个词在我们这里【不是一个进程】** —— ★ 它是**一组运行面模块**，★ 按职责**分到不同进程**：

```
★ 本体进程：  声明查询 ＋ 注册 ＋ 个体 ＋ 许可 ＋ 账 ＋ 总线口
★ 载体进程：  执行动作（查映射表 ⇒ 起进程）＋ 碰机器
★ GUI 进程：  投影（投成 A2UI 帧）＋ 落帧 ＋ 回话
```

## §六 ★★ 一句话总结（★ 你要的那个框架）

> ★★★ **本体进程 ＝ 「安装 ＋ 名册 ＋ 个体 ＋ 许可 ＋ 账 ＋ 总线口」六件；它【不执行、不渲染、不碰机器】。**
> ★★ **引擎不是进程 —— 引擎是【运行面】那组模块，★ 在我们这里【碎成三份】：执行给载体、投影给 GUI、查询与账给本体。**
> ★★★ **依赖方向永远单向：★ 谁要干活，谁就【问本体】；★ 本体不问任何人。**
