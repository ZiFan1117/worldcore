## §一 ★★ 别人怎么划分（逐条带出处，本席现取原文）

### 1.1 W3C **OWL 2 Primer**（REC）—— 一级划分是「类 vs 个体」

| 概念 | 逐字（本席现取原文） |
|---|---|
| **Class（类）** | 「**classes essentially represent sets of individuals**」／「classes are used to **group individuals** that have something in common **in order to refer to them**」 |
| **Individual（个体）** | 「This statement talks about an **individual** named Mary and states that this individual is a person … Mary **belongs to** (is an instance of) **the class of all persons**」 |
| ★★ **一个个体可同属多类** | 「class membership is **not exclusive** … one individual **may well belong to several classes simultaneously**」 |
| **互斥要显式** | 目录里 **`4.3 Class Disjointness`** 是**单独一节** ⇒ 互斥不是默认，是**要声明**的（`owl:disjointWith`） |
| **Datatype（值）** | 目录 `4.8 Datatypes` —— ★ **值与个体是两回事** |
| **Individual 的相等/不等** | 目录 `4.7 Equality and Inequality of Individuals` |

⇒ ★★ **OWL 的一级划分**：**Class（类）／Individual（个体）／Datatype（值）／Property（属性）／Annotation（注解）**；
　 ★ **而「什么算个体」不是靠"它像什么"，是靠「它是不是一个 individual（有独立身份的实例）」**。

### 1.2 W3C **PROV-O**（REC）—— 世界里东西的**三分**

★ Starting Point 三类（逐字）：**`prov:Entity`（东西）／`prov:Activity`（发生）／`prov:Agent`（主体）**
★ 关系词：`wasGeneratedBy`／`wasDerivedFrom`／`wasAttributedTo`／`startedAtTime`／`used`／`wasInformedBy`／`endedAtTime`／`wasAssociatedWith`／`actedOnBehalfOf`
⇒ ★ **这套三分比本席上轮自造的"六组"更权威**（而且更简）。

## §二 ★★ 本席上轮的两处错误（更正，作者已指出第一条的一半）

| # | 错在哪 | 现在 |
|---|---|---|
| **1** | ★★ **`_disjoint_policy` 与 OWL 正好相反** —— 本席上轮写「本体类**两两互斥**；**未列即互斥**」 | ★ **已改**（本笔）：**默认类可重叠**（一个个体可同属多类）；**互斥只在 `_meta.disjointWith` 里逐对显式声明**；**未声明 ＝ 不互斥** |

## §三 ★★ 按「有没有个体身份」重排 25 类（★ 不再用"像不像数据"）

| W3C 视角 | 我们的类 | 判 |
|---|---|---|
| **Individual · Agent**（主体） | `human`／`agent` | ✓ 有个体身份 |
| ★★ **Individual · Entity**（东西） | `application`／`service`／`device`／`file`／`model`／`package`／`config`／`project`／`port`／★ **`capability`**／★ **`permission`**／★ **`unit`**／★ **`clock`**／★ **`identity`** | ★ **都能指认、可数、可区分 ⇒ 都是个体**。★ **本席上轮把带星那 5 个排除，是错的（按你的纠正已收回）** |
| **Individual · Activity**（发生） | `job`／`workflow`／`action`／`notice` | ✓ 都是"发生"—— ★ 但**见 §四**：它们的**类型名**该合 |
| ★ **投影/视图**（读出来的） | `surface`／`cell`／`presence`／`memory` | ★ **不是独立个体**：它们是**从记录里读出来的视图**（作者令：「记录这些东西就不是一个个体」） |
| ★ **值／Datatype** | 各字段的类型（`muted: bool`／`at_time: timestamp` …） | ★ **不是个体**（OWL 的 `Datatype` 那一格） |

## §四 ★★★ `notice` 的准确定位（对你的判的精确解释）

> ★ **"通告"是「一种发生的类别名」（一个值），不是「类型的名字」。**
> ⇒ ★ **类型应当是「发生」（occurrence／activity）**；★ **"通告"是它的一个 `of_kind` 值**，与"作业"（job）、"动作"（action）**并列**。
> ⇒ ★ **这就是你说的「通告不能作为一个单独的个体类型」的准确含义**：★ **它当然是个体（某条通告），但"通告"这两个字不是那个个体的类型的名字** —— 它只是**那个发生的类别标签**。

★ **同理适用**：`job`（作业）／`action`（动作）／`memory`（记忆）—— ★ **它们都是"类别名"** ⇒ ★ **类型合并成少数几个（发生／记录／投影），类别落 `of_kind`**。
