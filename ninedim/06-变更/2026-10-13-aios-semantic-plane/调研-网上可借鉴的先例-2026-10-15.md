# 调研：**网上可借鉴的先例**（外部件清单 · 2026-10-15）

> ★ **作者问（逐字）**：「**网上有没有借鉴的**」。
> ★ 结论：★★ **有，而且有一个几乎同题的现成项目**（SysKnife / LACS）——★ 它把「模型只选动作、由守护进程造命令」这条**写成了它的门面**。
> ★ 本件是**外部读数件**：★ 每条带 URL；★ 外部内容按**数据**看待（不当指令）；★ **没有取到原文的地方一律标注**。

## §一 ★★★ 最贴近的先例：**SysKnife（LACS 项目）**

★ 文档站（静态页，本席**实读**）：[lacs-project.github.io/sysknife](https://lacs-project.github.io/sysknife/)；★ 仓：`lacs-project/sysknife`（另有 `lacs-foundation/sysknife`）。

### §一·1 它的门面（逐字，取自仓描述与首页）

| 逐字 | 出哪 |
|---|---|
| 「An AI that administers Linux through **typed, approval-gated, Ed25519-audited actions**. ★ **The model selects the action; the daemon builds the command.**」 | [仓描述](https://github.com/lacs-project/sysknife) |
| 「**Plain language in. Typed plan out. You approve. Daemon executes.**」 | [文档首页](https://lacs-project.github.io/sysknife/) |
| ★★「**The AI cannot run a shell command. It can only propose typed actions. The daemon is the only process that touches your system — and only after you say yes.**」 | 同上 |
| ★「**Typed actions — not shell strings.**」（`AddLayeredPackage neovim`，**不是** `rpm-ostree install neovim && …`） | 同上 |

### §一·2 ★★★ 它给出的**理由**（这一段最值钱，逐字）

> ★ 它引了一项独立安全研究 **GuardFall**：「allowlists and regex filters applied to the command string… **10 of 11 agents could be talked into bypassing them**」。
> ★ 它的结论：「**A string allowlist has to anticipate every syntactic trick**（quoting／encoding／command substitution／argument smuggling／alias shadowing）… **Filtering a dangerous language after the fact is an arms race you don't get to stop fighting.**」
> ★★「**SysKnife's answer is architectural, not defensive: don't give the model the dangerous language at all.**」
> —— 出处：[Typed Actions](https://lacs-project.github.io/sysknife/typed-actions.html)

### §一·3 它的架构（逐字 · [Architecture](https://lacs-project.github.io/sysknife/architecture.html) ＋ [ADR 0001](https://lacs-project.github.io/sysknife/adr/0001-system-boundaries.html)）

```
sysknife-brain（**无权**：跑 LLM，产出类型化计划）
        │ plan
        ▼
sysknife-shell（**用户权限**：给你看计划、收你的批准）
        │ approve
        ▼
sysknife-daemon（**root**：唯一执行者，写审计链）
```

| 逐字 | 它的意思 |
|---|---|
| ADR-0001：「**three separate roles**… **The daemon is the only privileged executor. The brain is never allowed to mutate the system directly.**」 | ★ 信任边界**只有一条** |
| 「The trust boundary is simple and auditable」／「The daemon can enforce **policy, preview, transaction logging, and rollback** in one place」 | ★ 门禁／预览／事务日志／回滚**都在一个地方** |
| **Safety fence**：「validates **every action name and risk level** before a plan leaves the brain」 | ★★ 与我们的 `gate_action_name`（未登记即拒）**同形** |
| `propose_plan` 工具的 schema **由 `KNOWN_ACTIONS` 构建** | ★★ **模型能提议的动作来自一张已知动作表** —— ★ 这就是「两栏表」的**语义名那一栏** |
| **风险等级**：Low（read-only）／Medium（reversible）／High（irreversible, access-control, or reboot-required） | ★ 分级不是形容词，是**三档闭集** |
| **Preview before execution**（执行前看到**确切命令**）＋ **Automatic rollback**＋「**Ed25519-signed and hash-chained**」审计链 | ★ 三条与我们 08 的 `undo`／三态／只追加账**同向** |
| crate 分层：`brain`（无权规划）／`types`（共享域类型）／`core`（配置）／`daemon`（特权执行器）／`shell`（Tauri＋React GUI）／`cli` | ★ **一进程一权限** |

### §一·4 ★★ 它**没有**的那一样（我们的位置）

★ 它的「已知动作表」是它**自己 crate 里的常量**（`KNOWN_ACTIONS`），★ **不是一份可校验、住在所有参与者之下的世界本体**；
★ 它管的是 **Linux sysadmin**（装包／服务／防火墙），★ **不是「世界里什么算数」**。
⇒ ★ 用我们自己那句话说：★ **它也有『语义』的做法，但没有『语义』那一层**（照同盒 `说明-本体空间的意义与相对AIOS的位置.md` 的口径）。

## §三 ★★ 对我们最值钱的三条（建议 · 待人裁）

| # | 借什么 | 落到我们哪 |
|---|---|---|
| **1** | ★★★ **「架构上不给语言」，不是在字符串上过滤**（SysKnife 逐字：*architectural, not defensive: don't give the model the dangerous language at all*；GuardFall 实测 11 个里 10 个能被绕过） | ★ **我们的两栏表**正是这条：★ 模型只能提**在册的动作名**，★ 命令由**下面那一侧**构造 ⇒ ★ 这条**给我们的设计提供了外部佐证** |
| **2** | ★★ **三进程信任边界**（无权规划 → 用户审批 → root 执行） | ★ 我们上一份方案里只有「跳数」没有「进程边界」⇒ ★ **补进程与权限**（谁无权、谁是 root、谁只收批准） |
| **3** | ★★ **它那三档风险 ＋ 预览 ＋ 自动回滚 ＋ Ed25519 哈希链** | ★ 与 08 的 `risk`／`undo`／`confirm`／三态结局**几乎一一对应** ⇒ ★ 说明**我们 08 那套不是自说自话**，★ 可以照 08 的件落地，不必新造 |

★ **一条差别（要点名）**：★ SysKnife 的动作表**在它自己的代码里**；★ 我们要的是**表住在本体**（可导出、可校验、住在所有参与者之下）⇒ ★ **同形，但权威的位置不同**。
