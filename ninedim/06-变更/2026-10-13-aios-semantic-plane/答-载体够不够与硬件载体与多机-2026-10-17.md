# 载体够不够：**不够 —— 要多个；硬件是【另一类】载体；而且系统里【不止一台】**（2026-10-17）

> ★ **作者问（逐字整理）**：「**这一个载体够吗？是不是还得分门别类的载体**？而且有一个问题就是说还有一个**硬件的抽象能力**……**整个计算机系统里头不一定只有一个吧**」。
> ★★★ **两问的答案都是「不止一个」** —— ★ 而且★ **第二问牵出一个【真缺口】**（★ 见 §四）。

## §二 ★★★ 第二问：硬件抽象 —— **是另一类，而且必须单独**

### §二·1 ★★ 本体里【已经有】这一类

★ **现取**：★ `ontology.json` 的 `objects.device` ——

```
id:        wc:ont00000011
label:     设备 / Device
definition: 设备——本批（2026-10-12）按 objects._declared_gaps 点名的缺口补立的类。
anchor:    http://purl.obolibrary.org/obo/BFO_0000040
anchor_note: 照形状取自 BFO 2020：material entity —— **设备是硬件**。
disjointWith: [human, agent, application, service, workflow]
```

★★ **⇒ 硬件这一层，★ 本体里【有位置】** ✓

### §二·2 ★★★ 但它和命令行载体【不是一种东西】

| | ★ 命令行载体 | ★★ 硬件载体 |
|---|---|---|
| ★ 怎么碰底层 | ★ `execve`（★ 起进程，★ `program + args`） | ★★ **设备节点／`sysfs`／`ioctl`／`dbus`／`udev`** |
| ★ 「命令」是什么 | ★ 一行 `program + args` | ★★ **不是一个程序** —— ★ 是**读／写一个寄存器值**那种 |
| ★ 权限 | ★ 普通用户／少数要 root | ★★ **`CAP_SYS_RAWIO`／`CAP_NET_ADMIN`／root** 一类 |
| ★ 失败模式 | ★ 命令非零退出 | ★★ **可能把设备搞死**（★ 不可逆） |
| ★ 现取先例 | ★ 08 的 `package`／`job` | ★★ 08 的 **`backlight`** |

★★★ **⇒ 判据第 1 条（特权不同）直接命中** ⇒ ★ **硬件载体【必须】单独**（★ 单独二进制／单独单元／单独加固）✓

## §三 ★★★ 第三句：「系统里不止一个」—— ★ 两级乘起来

```
★ 载体实例数 ＝ 【台数】 × 【域数】

     机器 A                     机器 B
  ┌─────────────┐            ┌─────────────┐
  │ fs 载体      │            │ fs 载体      │
  │ service 载体 │            │ service 载体 │
  │ pkg 载体     │            │ pkg 载体     │
  │ device 载体  │            │ device 载体  │
  │ …            │            │ …            │
  └─────────────┘            └─────────────┘
        └──────────┬──────────────┘
                   ▼
            ★ 一根总线 ＋ 一个本体
```

★★★ **本体那一侧只看到【名字】** —— ★ 它**不知道有几个载体**、★ **也不需要知道**（★ 这正是「本体是唯一耦合点」的意思）✓

## §四 ★★★ 但这里牵出一个【真缺口】：个体表**没有「哪台机器」**

### §四·1 ★ 现取的个体结构

```rust
pub struct Individual {
    pub class: String,      // 哪一类
    pub local_id: String,   // 本地 id（★ 逐字：同一类可以有多个个体：两张网卡、三个服务、两个执行体）
    pub state: String,      // 状态
}
```

★★ **⇒ 「同一台机器上多个」已经能表达**（★ `local_id` 不同）✓
★★★ **⇒ 「多台机器上各有一个」【表达不了】** ✗ —— ★ 因为★ **没有「哪台机器」这一格**；★ 两台机器上都报 `service/fs` ⇒ ★ **个体表会当成【同一个】**（★ 或者撞「同一个名字已经是个体 ⇒ 拒」）

### §四·2 ★★ 三个可选补法（★ 要你裁）

| # | ★ 补法 | ★ 好处 | ★ 代价 |
|---|---|---|---|
| **A** | ★★ **`local_id` 里带机器**：★ `hostA/fs` | ★ **不改结构** | ★ 名字变长；★ 谁保证格式 |
| **B** | ★★ **加一格 `host: String`** | ★ 结构清楚 | ★ 动 `Individuals` ＋ 判据；★ 改上游文件要登记 |
| **C** | ★★ **个体表按「机器」分表**（★ 每台机器一张个体表） | ★ 最干净 | ★ 改动最大 |

★★ **我倾向 B**（★ 加一格），★ 但**这是要你裁的**。
