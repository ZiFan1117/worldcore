# 提案：**人确认＋委托「四格」**（待裁，2026-10-20）

> ★ 作者（逐字整理）：「我不想点这个确认按钮，你帮我点？」＋「Agent 不能替人签字」＋「做个委托四格」。
> ★ 本件是**提案**，不改法；法只有人能签。你批/改完，我再按法落地。

## 一、要解决的两个问题

1. **人不想每步都点确认**：变更类动作如果每次都弹窗，人会被烦死；
2. **Agent 不能替人签字**：授权必须是**人**给的、**有范围**、**可撤销**、**可审计**的，而不是 Agent 自己说「我能做」。

⇒ 两者合起来＝**委托（delegation）**：人签一次「四格」，Agent 在四格里自主执行；出格就停、就等人。

## 二、「四格」是什么（人一次签完）

| 格 | 字段 | 含义 |
|---|---|---|
| ① 范围 | `action` | 允许 Agent 做**哪一个**动作（一个委托一个动作；要多个就多张） |
| ② 期限 | `expires` | 到什么时候失效（ISO 时间；过期自动无效） |
| ③ 次数 | `max_uses` | 最多用几次（用完自动无效；防止无限期放权） |
| ④ 可撤 | `revoke` | 人随时能撤（撤了立即失效，账里留证） |

★ 四格是**法里的对象**（不是提示词里的字符串）：能查、能撤、能审计、能过期。

## 三、拟加的法（草稿，**待你签**）

### 3.1 对象类型 `delegation`

```json
{
  "id": "delegation",
  "label": "委托",
  "primary_key": "name",
  "interfaces": ["Identifiable", "Owned", "Retirable"],
  "provider": "world",
  "authority": {"kind": "reported", "reporters": ["world://human"]},
  "properties": [
    {"name": "name",     "type": "STRING", "required": true, "primary": true},
    {"name": "from",     "type": "OBJECT_REFERENCE", "required": true},   // 授权人（human）
    {"name": "to",       "type": "OBJECT_REFERENCE", "required": true},   // 被授权者（agent）
    {"name": "action",   "type": "STRING", "required": true},             // ① 范围
    {"name": "expires",  "type": "STRING", "required": true},             // ② 期限
    {"name": "max_uses", "type": "INT",    "required": true},             // ③ 次数
    {"name": "used",     "type": "INT",    "required": false},            // 用了几次（记账驱动）
    {"name": "revoked",  "type": "BOOLEAN","required": false}             // ④ 撤没撤
  ]
}
```

### 3.2 动作（草稿）

| 动作 | 参数 | 谁可做 | 效果 |
|---|---|---|---|
| `delegate.grant` | `to`、`action`、`expires`、`max_uses` | **只有人**（凭票） | 建委托对象＋记账 |
| `delegate.revoke` | `name`、`reason`（必） | 授权人 | `revoked=true`＋记账（凡撤必留证） |
| `delegate.list` | `to?` | 人/agent（只读） | 列有效委托 |

### 3.3 询路规则（接在现有闸上）

Agent 请求变更类动作时：

1. 先看本体许可（scope）——原有闸不动；
2. 若 actor 是 agent 且动作属变更类：查**有效委托**（`to=actor`、`action` 匹配、未过期、未撤销、`used < max_uses`）；
3. 没有 ⇒ 拒 `HUMAN_CONFIRM_REQUIRED`（并可顺带发一条「请人确认」的 A2UI 请求）；有 ⇒ 放行，`used += 1`，记账记「哪张委托放行的」。

★ **Agent 永远不能签委托**（`delegate.grant` 的 scope 只含 human）；这条是底线。

## 四、人确认（保留但少用）

- 没有有效委托的变更动作 ⇒ 走**人确认**：本体发 `confirm.request`（A2UI Modal：做什么/为什么/影响），人的呈现（Flutter 或语音浏览器）弹窗；
- 人点「允许一次」⇒ 放行一次（不建委托）＋记账；点「拒绝」⇒ 拒＋记账；
- **Agent 不能替人点**；确认的「点」必须来自人的会话（票）。

## 五、界面（四格怎么给人看）

- 呈现层出一张 A2UI `Card`：四行（范围/期限/次数/可撤）＋「签」「撤」按钮；
- 语音浏览器可直接念：「允许 Agent 做 sys.GetMemoryInfo，到明天 6 点，最多 3 次，随时可撤。签吗？」→ 人说「签」；
- 人签的是一次「委托」，不是每步确认。
