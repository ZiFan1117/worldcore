# 梳理稿：三层分开 —— 种类（类）／预值（取值域）／状态与事件

| 阶段 | 环 | 维 | 版本 |
|---|---|---|---|
| S2 | 意图 | 二 框架 ／ 六 规格 | **0.1（待两位评审席挑错）** |

> **作者令（逐字）**：「**我感觉你这个分得也太细了吧**，像什么**发布者**这些东西，这能分为单独的类吗？**上架下架这个不是状态吗**？一个东西的这个是有这个东西吗？对，**我们再补一层**，对，**补一层预值／设备种类**。**你好好给我梳理梳理**，不行的话，**找两个人评审，评审分出来以后**。」
> **本件性质**：**梳理稿**（待审）—— ★ 只给分层与判据；**结论待人签**。

## §一 ★★ 本席先认两处错（作者已指出）

| # | 错 | 更正 |
|---|---|---|
| **1** | ★ **分得太细**：把 `publisher`（发布者）／`repository`／`mirror`／`rollout`／`takedown`／`rotation`／`downgrade`／`deplatform` 等**当成并列的"类"** | ★ **它们不是同一层的东西** —— 见 §二：★ 有的是**主体的一种**、有的是**位置/端点**、★ **上架/下架/轮换/降级/去平台是「状态迁移」（值/事件），不是类** |
| **2** | ★ **漏了一层**：把"取值清单"（如 `DeviceClass` 15+）与"类"混在一起谈 | ★ **补一层「预值（取值域）」** —— 见 §二 第二层 |

## §二 ★★ 三层（本席的梳理）

| 层 | 是什么 | 判据（三问） | 例（现取） |
|---|---|---|---|
| ★★ **第一层：种类（Class）** | **世界里的"东西"** | ① 能**指认**（有名字/身份）② 能**数**（有几个）③ **一对怎么区分** | `human`／`agent`／`application`／`service`／`device`／`file`／`model`／`package`／`project`／`config`／`capability`／`permission`／`unit`／`clock`／`identity` ＋ ★ **候选：`repository`（仓库）／`adapter`（适配器）／`capsule`（胶囊）／`driver`（驱动）／`connection`（连接）** |
| ★★★ **第二层：预值（取值域／Concept）** | **某一格能取哪些值**（★ 作者令要补的就是这一层） | 它**是"某一格的值"**，不是"一个东西" | ★ `DeviceClass`（**15+**，`Cpu`／`Memory`／`NetworkWifi`／`StorageNvme`…）／★ `RecordType`（**428**）／`AdapterDispatchKind`（4）／`RetentionClass`／`RedactionProfile`／`CompactionPolicy`／`PrivacyClass`（5）／`DeviceClass`… |
| ★ **第三层：状态与事件** | 一个东西的**当前状态**，或**发生过的事** | 它是"某东西在某一刻的处境"或"一次发生" | ★ **上架（`rollout`）／下架（`takedown`）／轮换（`rotation`）／降级（`downgrade`）／去平台（`deplatform`）＝状态迁移**；★ **审批（approval）＝一次发生**；★ **启动完整性（`BootIntegrityState`）＝状态**；★ 我们的 `job.status`／`presence.state`／`agent.state` |

⇒ ★★ **由此看本席上一件（`完备性-16类够不够.md`）的问题**：★ **它把三层混成了一层** ——
　 ★ `publisher`／`rollout`／`takedown`／`BootIntegrityState`／`RetentionClass` **都不该按"新类"来处理**（★ 它们是主体的一种／状态迁移／状态／预值）。

## §三 ★ 逐条重判本席上件列的 13 项（★ 这才是"好好梳理"）

| 上件列的"缺的种类" | 本席重判 | 它实际属于 |
|---|---|---|
| `publisher`（发布者） | ★ **不该是独立类** | ★ **主体的一种**（`agent`／`human` 的角色或种类值） |
| `repository`（仓库） | ★ **可能是类**（能被指认、可数、可区分） | ★ **第一层**（候选） |
| `mirror`（镜像） | ★ **可能是类**（与仓库同类，是它的一个实例/副本） | ★ **第一层**（候选）或★ **仓库的一个属性** |
| `mirror_blacklist`（黑名单） | ★ **是规则/值** | ★ **第二层**（取值/清单） |
| ★ `rollout`（上架） | ★★ **是状态迁移** | ★ **第三层** |
| ★ `takedown`（下架） | ★★ **是状态迁移** | ★ **第三层** |
| ★ `rotation`（轮换） | ★★ **是状态迁移/一次发生** | ★ **第三层** |
| ★ `downgrade`（降级） | ★★ **是状态迁移** | ★ **第三层** |
| ★ `deplatform`（去平台） | ★★ **是状态迁移** | ★ **第三层** |
| `manifest`（清单） | ★ **是"一份文件"还是"一次生成"**？ | ★ **待评审判**（本席倾向：★ 是**东西**（一份清单）） |
| `install_state`／`install_fsm` | ★ **状态与状态机** | ★ **第三层** |
| `adapter`（适配器） | ★ **是东西**（可注册、有状态、有生命周期） | ★ **第一层**（候选） |
| `capsule`（胶囊） | ★ **是东西**（有生命周期、可挂载） | ★ **第一层**（候选） |
| `ApprovalPolicy`／`ApprovalDecision` | ★ **规则与一次决定** | ★ **第二层（策略）＋第三层（发生）** |
| `driver`（驱动） | ★ **是东西**（有出处、版本） | ★ **第一层**（候选） |
| `bus`（总线） | ★ **是位置/通路**，不是种类 | ★ **待评审判**（本席倾向：★ 第一层（通路）＋第二层（总线种类 `BusKind`）） |
| `ConnectionDecision`／`DnsTransport`／`ResolverBackend`／`AllowlistEntryKind` | ★ **决策与取值** | ★ **第二层 ＋ 第三层** |
| `BootIntegrityState`／`BootAttestationError` | ★ **状态与错误** | ★ **第三层** |
| `RetentionClass`／`RedactionProfile`／`CompactionPolicy` | ★ **策略取值** | ★ **第二层** |
| `session`／`transaction` | ★ **是东西**（有身份、有起止） | ★ **第一层**（候选） |
