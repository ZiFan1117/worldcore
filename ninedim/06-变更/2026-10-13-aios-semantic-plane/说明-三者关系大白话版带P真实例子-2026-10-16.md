## §一 ★★★ 先看真实例子（`examples/energy_asset_maintenance/ontology_definition.py:121-126` 逐字）

```python
# Interface
iface = Interface("Inspectable", "Inspectable",
                  required_properties=[Property("inspection_date", "Inspection Date", PropertyType.DATE)])
o.register_interface(iface)

asset.interfaces = ["Inspectable"]        # ★ Asset 说：我实现它
pipeline.interfaces = ["Inspectable"]     # ★ Pipeline 说：我也实现它
asset.add_property(Property("inspection_date", "Inspection Date", PropertyType.DATE))   # ★ 为了达标，Asset 补上这个属性
```

★★★ **这一段在说什么（一句一句）**：

| 行 | ★ 它在做什么 |
|---|---|
| `Interface("Inspectable", …)` | ★★ **定义了一个「资格」叫 `Inspectable`（可检查的）**；★ 它只有一条要求：★ **「凡是有这个资格的，必须有一个 `inspection_date`（检查日期）属性」** |
| `asset.interfaces = ["Inspectable"]` | ★ **`Asset`（资产）声明：我有这个资格** |
| `pipeline.interfaces = ["Inspectable"]` | ★ **`Pipeline`（管线）声明：我也有这个资格** |
| `asset.add_property("inspection_date")` | ★★ **为了够格，`Asset` 补上了那条要求的属性** |

⇒ ★★★ **所以「定义了多个对象类型的形状」＝ 一句话**：

> ★★★ **「我不管你是资产还是管线，只要你满足『必须有检查日期』，你就算『可检查的』。」**

## §二 ★★★ 这个比方你在生活里天天见：**驾照**

| 现实 | ★★ P 里的对应 |
|---|---|
| ★ 「**驾照**」是一个资格 | ★ `Interface("Inspectable")` |
| ★ 拿驾照的**条件**：会开车、视力达标、考试过 | ★ `required_properties`：**必须有 `inspection_date`** |
| ★ **卡车司机**和**出租车司机**是两个不同的职业 | ★ **`Asset`（资产）**和 **`Pipeline`（管线）**是两个不同的 ObjectType |
| ★ 但**两个职业都有驾照** | ★ **两个类型都 `interfaces = ["Inspectable"]`** |
| ★ 你可以问「**谁有驾照**」⇒ 拿到一份**跨职业的名单** | ★ `iface.get_implementors(ontology)` ⇒ **返回 Asset 和 Pipeline** |
| ★ ★★ **驾照不规定你会干什么活** | ★★ **`Interface` 与「能做什么」（ActionType）完全无关** |

⇒ ★★ **一句话**：★ **`Interface` 管的是「你有哪个资格／你长什么样」；★ 它不说你能干什么。**

## §三 ★★ 三者各是什么（各配一个比方 ＋ P 里的一行）

| 件 | ★★ 一句话 | ★ 比方 | ★ P 里的一行（逐字） |
|---|---|---|---|
| ★★ **`Interface`** | ★ **一个资格**：要当我，必须有哪些属性 | ★ **驾照** | ★ `Interface("Inspectable", …, required_properties=[Property("inspection_date", …)])` |
| ★★ **`ActionType`** | ★ **一件能做的事**：要什么参数／什么条件下不许做／**做完世界怎么变**／谁能做 | ★ **一次操作**（如「升级这台资产」） | ★ `ActionType(action_id="EscalateAsset", parameters=[ActionParameter("asset_id", STRING), ActionParameter("priority", …, options=["LOW","MEDIUM","CRITICAL"])], effects=[ActionEffect("edit_object","MaintenanceEvent",{"status":"completed"})], required_roles=["Technician","Engineer"])` |
| ★★ **`OntologyFunction`** | ★ **一段算值的逻辑**：给输入、出输出，★ **不改世界** | ★ **一次计算／查询**（如「列出高风险资产」） | ★ `OntologyFunction(function_id="get_high_risk_assets", input_types={…}, output_type="list", implementation=get_high_risk_assets)` |

## §四 ★★★ 一趟真实流程把三者串起来（用同一段例子）

```
★ 第一步（语义层）：世界上有哪些东西
    定义 Asset（资产：asset_id/name/asset_type/location/status）
    定义 Pipeline（管线）                ← ★ 两个不同的东西
    定义 Inspectable（可检查的）          ← ★ 一个资格：必须有 inspection_date
    Asset 和 Pipeline 都声明实现它        ← ★ 于是「哪些可检查」有名单了
    定义 has_sensor_readings 等边          ← ★ 谁连着谁（带基数：一对多）

★ 第二步（动能层）：能做什么
    ActionType「EscalateAsset」：参数／校验规则／效果／谁能做
    OntologyFunction「get_high_risk_assets」：输入→输出
    ★★ 这两样【并列】：ActionType 里没有 function_id，Function 里没有 action_id

★ 第三步（动态层）：规矩与留痕
    Roles（Technician／Engineer）＋ Markings（公开／内部／机密）＋ AuditLog（不可变）

★ 第四步（真跑一趟 —— P 的 Data Flow 五步）
    ① 定义本体 → ② 在 ObjectStore 建实例（某个具体资产 A-1）
    → ③ 查询（沿 has_sensor_readings 找它的读数）
    → ④ ★★ **ActionExecutor 执行「EscalateAsset」**：先 validate（参数＋规则）⇒ 看 required_roles ⇒ 落 effects（把那个 MaintenanceEvent 改成 completed）⇒ 写一条审计
    → ⑤ 需要时导出 OWL／SHACL
```

★★ **注意第 ④ 步里没有 function** —— ★ **`ActionExecutor` 只跑 ActionType**（★ 我逐行 grep：0 处提到 function）⇒ ★ **函数那条路只有测试在调**。

## §五 ★ 三者关系图（谁引用谁、谁不引用谁）

```
★ 语义层（名词的世界）
   ObjectType ──(LinkType 连)──► ObjectType
        │
        └── Interface  ★ 一个资格：实现它的类型必须有某些属性
                 ★ Interface 不引用 Action、不引用 Function
                 ★ 反向也不引用（ActionType 里没有 interface_id）

★ 动能层（动词的世界）—— ★ 两件【并列】，互不引用
   ActionType        ★ 改世界（有 effects ＋ 走 ActionExecutor ＋ 落审计）
   OntologyFunction  ★ 算值（无 effects、无审计、只有测试在调）

★ 动态层（规矩与账）
   Roles／Markings／AuditLog  ★ ActionType 有 required_roles；Function 没有
```

⇒ ★★★ **三句话**：
1. ★★ **`Interface` 是「资格」** —— ★ 管「谁长这样」，★ **与「能做什么」无关**；
2. ★★ **`ActionType` 是「能改世界的事」**，★ **`OntologyFunction` 是「能算出来的值」**；★ **两者并列，谁也不引用谁**；
3. ★★★ **只有 `ActionType` 走执行器、落审计**；★ **`OntologyFunction` 两样都没有**。
