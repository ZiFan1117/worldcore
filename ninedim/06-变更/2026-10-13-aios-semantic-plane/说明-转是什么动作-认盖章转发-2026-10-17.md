# 「转」到底是什么动作 —— **认 → 盖章 → 转发**，★ 盖章就是记账（2026-10-17）

> ★ **作者问（逐字整理）**：「就是说，**我要执行另一个程序的接口或者什么的，这时候我就【转过去】就得了，对不对？** 我不知道是转过去还是咋地，**就是这个东西**。」
> ★★★ **答：★ 对，就是「转过去」。★ 但「转」不是简单转发 —— ★ 本体在转的过程里要做三步：★ 认 → 盖章 → 转发。★ 而【盖章就是记账】。**

---

## §一 ★★★★★ 「转」的完整动作（★ 三步）

```
★ 请求方（AI／应用／人）
     │  发「我要 fs.list」                 ← ★ 发到【入口话题】（★ 只有本体订阅）
     ▼
★★ 本体
     ① ★ 认     查注册表：在册吗？谁能用？（不在册 ⇒ 拒，且不转）
     ② ★★ 盖章   ★ 给这条请求【发一个序号 seq】                  ← ★★★ 关键
     ③ ★ 转发    把「盖章后的请求」发到【能做它的那一方】
     ▼
★ 执行方（载体／应用／别的进程）
     │  真干活 ⇒ 出结果
     ▼
★★ 本体   ④ 记：结果回来，记一笔
     ▼
★ 请求方   拿到结果
```

## §二 ★★★★★ 为什么说「盖章就是记账」

★ **本体里 `envelope.fields.seq` 逐字**：

> ★★★ **「`seq`: integer  # **在账本中的位置**，全局单增，**由世界分配**」**

★★★ **⇒ 两句话**：
1. ★★ **`seq` ＝ 这条东西【在账本里的位置】** ★ ⇒ ★ **盖了号 = 账上就有它了** ✓
2. ★★ **`seq` 【由世界分配】** ★ ⇒ ★ **只有本体能给号** ✓

★★★ **⇒ 所以「转」和「记」是【同一个动作的两面】**：★ **本体给这条请求盖号的那一刻，它就已经进账了** ✓
★★ **⇒ 这也解释了「唯一耦合点」为什么成立**：★ **唯一的【号源】就是本体** ★ ⇒ ★ **谁也不能绕过它自己编号** ✓

## §三 ★★★★★ 转给谁 —— **看 `registered_by_kind`**（★ 这一格已经在了）

★★ **「另一个程序的接口」有两种，转法不一样**：

| ★ 目标类型 | ★ 它在总线上吗 | ★ 转给谁 | ★ `registered_by_kind` |
|---|---|---|---|
| ★★ **应用／界面**（★ 另一个进程） | ★★ **在** ✓ | ★★ **转给它自己**（★ 它有自己的话题） | ★ `app` ／ `interface` |
| ★★ **裸程序**（`ls`／`systemctl`／`apt`） | ★★ **不在** ✗ | ★★ **转给【载体】**（★ 载体替它出场） | ★ `system` ／ `world` |

★★★ **⇒ 所以 `registered_by_kind` 【就是路由表】** ★ —— ★ 而★ **这一格我们【已经有了】**（★ `registry.jsonl` 五格里）✓
★★ **⇒ 一个 `registered_by` 后面如果有多个实例**（★ 多台机器／多个载体）★ ⇒ ★ **那一层再选**（★ 今天只有一个载体，★ 不用选）✓

## §五 ★★★★ 完整时序（★ 一张图）

```
★ 请求方                ★★ 本体                     ★ 载体／应用
   │                      │                            │
   │──世界/ask（fs.list）─▶│                            │
   │                      │ ① 认：在册吗？谁能用？      │
   │                      │ ② 盖章：seq = N            │
   │                      │    ★ 这一刻它就【进账了】   │
   │                      │ ③ 转发：world/exec(seq=N)  │
   │                      │───────────────────────────▶│
   │                      │                            │ ④ 起 ls -l
   │                      │◀───world/exec/result───────│

```

★★★ **⇒ 请求【过两手】：★ 进本体一次（盖章），出本体一次（转发）；★ 结果回来再过一次（记账 ＋ 回传）。**
★★ **⇒ 而本体【全程没动手】—— ★ 它只认、只盖章、只转、只记** ✓
