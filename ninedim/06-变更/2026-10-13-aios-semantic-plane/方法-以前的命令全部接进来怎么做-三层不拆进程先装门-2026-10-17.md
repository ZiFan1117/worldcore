# 方法：**要把「以前的计算机命令」全部接进来 —— 三层、不拆进程、先装门**（2026-10-17）

> ★ **作者问（逐字整理）**：「执行体只管以前的那些 system 命令，是不是其他应用的没关系，只要以前的命令都在执行器上能跑就行。本体里头动作名那就很多了——相当于要把以前计算机的这些命令全部注册到本体。**那执行体应该怎么办？再做一个进程嘛？做一个映射嘛？把之前那些命令行命令做成一个一个的动作吗？** 我有点糊了，你给我出个方法。」
> ★★ **本件是【发现与建议】，不是结论** —— 两位专家（甲：本体侧／乙：执行体侧）＋ 我，只出方案；**签字是你的**（硬约束 6）。

## §一 ★★★ 先直接答你三个问题

| ★ 你问 | ★ 答 | ★ 理由（逐字依据） |
|---|---|---|
| ★ **把以前的命令做成一个一个的动作吗？** | ★★ **不是** | ★ **全量登记是错的路**：★ 本体每条动作要 8 实质格＋3 说明格（≈34 行），★ 3000 条约 **10 万行**，★ 且每条要**人裁** `required_roles`／`reversible`／`capability` ＋ 一条授权 ⇒ ★ **数千次人裁**。★ 而且★ 「全部命令」本身**不可完备**（★ 档案逐字：「**不可能完备……不注册＝不存在**」） |
| ★ **做一个映射吗？** | ★★ **要，但不是一张大表** | ★ 照 08 的形态：★ **域一文件**（★ `command.d/<域>.jsonl`），★ 一域几十行 ⇒ ★ **审与冲突从几千行降到一域几十行**；★ 且★ **表由采集器生成**（★ 只改输入、重跑生成器），★ 人只审四处 |
| ★ **再做一个进程吗？** | ★★ **先不拆** | ★ 拆进程的判据**不是「域」**，★ 是：★ ① **加固类／特权不同**（08 逐字：★ high-risk 才给 `CapabilityBoundingSet=`）② **故障域不同** ③ **启动次序不同**。★ ⇒ ★ **一个执行体进程，内部按域分模块** |

## §二 ★★★ 方法：三层（★ 甲推荐「分层登记」）

```
┌─────────────────────────────────────────────────────────┐
│ L1  本体 ＝ 法   （★ 数十条，人审做得完）                  │
│     · 只放「人要能推理、要判权、要留痕」那一层             │
│     · 现有的 9 条世界动作 + 每域 1~2 个【族级】动作        │
│       （fs.* / pkg.* / proc.* / service.* / device.* …）   │
│     · ★ 命令字面量【绝不进这里】（判据 _no_command_literal）│
└─────────────────────────────────────────────────────────┘
                          ▲ 只认名字
┌─────────────────────────────────────────────────────────┐
│ L2  注册表 ＋ 执行清单 ＝ 机制  （★ 数千条，提供方注册）   │
│     · 一条命令一行（★ 域一文件，不是一张大表）             │
│     · 名字挂域前缀；★ 本体零改动                          │
│     · 现取代码已经支持两份分开（本体是本体、注册是注册）   │
└─────────────────────────────────────────────────────────┘
                          ▲ 只认「这个动作谁来干」
┌─────────────────────────────────────────────────────────┐
│ L3  执行体（provider）＝ 那只手  （★ 先一个进程，按域分模块）│
│     · ★ 真命令硬编码在这里（08 逐字：命令硬编码在 Rust 里）│
│     · 不裁决／不许写账／不持有身份（08 逐字）              │
└─────────────────────────────────────────────────────────┘
```

### §二·1 ★★ 三层的分工一句话

| ★ 层 | ★ 放什么 | ★ 谁写 | ★ 量 |
|---|---|---|---|
| **L1 本体** | ★★ **族级语义名**（★ 人要判权的那些） | ★ 人（★ 一条条审） | ★ **数十** |
| **L2 清单** | ★ **命令级名字 ⇒ 谁干 ＋ 风险 ＋ 要不要确认 ＋ 能不能撤销** | ★ 提供方／生成器 | ★ **数千** |
| **L3 执行体** | ★★ **真命令** | ★ 我们（★ 每域一个模块） | ★ 每域几十条 |

★★★ **关键**：★ **「注册」注册的是【名字】，★ 不是【命令】** —— ★ 命令永远在 L3；★ L1／L2 都只有名字（★ 这就是 `_no_command_literal` 那条禁令的意思）✓

★★★ **⇒ 结论：★ 铺几千条之前，★ 必须先给执行体装门** —— ★ 不然「未登记即拒」是**空的**，★ 几千条等于几千个没门的入口 ✗
