# 回答：**「都走总线」可以 —— 数据面慢不慢，我量了**（2026-10-17）

> ★ **作者话（逐字整理）**：「**这个我们就按照我们说好的总线都走，这个它数据面没办法很好的传输嘛，我是有一这疑问**」。
> ★★ **疑问是对的 —— 但【现在不用急着分】。★ 本件用【实测数字】回答（§一），并给出分阶段的处置（§三）。**

---

## §一 ★★★ 实测：zenoh 发不同大小的负载（★ 同机回环 · 真读数）

```
  发       1000 字节 ⇒ 收       1000 字节，往返 104.364µs
  发     100000 字节 ⇒ 收     100000 字节，往返 412.023µs
  发    1000000 字节 ⇒ 收    1000000 字节，往返 4.179462ms
  发   10000000 字节 ⇒ 收   10000000 字节，往返 44.008409ms
（★ 这是【同机回环】；★ 一次序列化＋一次拷贝都在里面）
```

### ★★ 折算（★ 我算的，不是测的）

| ★ 负载 | ★ 实测往返 | ★ 折算吞吐 | ★ 判断 |
|---|---|---|---|
| ★ **1 KB** | ★ **104 µs** | ★ 小消息看延迟 | ★★ **完全够**（★ 信封／小 JSON 就是这个量级） |
| ★ **100 KB** | ★ **412 µs** | ★ ≈ **243 MB/s** | ★★ **够** |
| ★ **1 MB** | ★ **4.18 ms** | ★ ≈ **239 MB/s** | ★ **能忍**（★ 图片／小表） |
| ★ **10 MB** | ★ **44.0 ms** | ★ ≈ **227 MB/s** | ★ **能忍**（★ 一次 44 ms） |
| ★ **1 GB** | ★ **≈ 4.4 s**（★ 线性外推，**没测**） | ★ 同上 | ★★ **该直搬** |

★★★ **一句话**：★ **同机回环下，zenoh 的吞吐稳定在 ~230–240 MB/s**；★ **100 KB 以下是亚毫秒**。

## §二 ★★★ 所以你的疑问怎么答

### ★★ 疑问成立的地方（★ 该承认）

| ★ 情况 | ★ 走总线的代价 |
|---|---|
| ★★ **大块数据（> 100 MB）** | ★ **每次多一次序列化 ＋ 一次拷贝** —— ★ 1 GB 要 4.4 秒；★ **直搬（零拷贝）能省掉其中一半以上** |
| ★★ **高频小块（每秒几千条）** | ★ 每条 ~0.1 ms 的固定开销 ⇒ ★ **累积起来可观**（★ 但★ 那可以用批量／合并解决，★ 不必上数据面） |

### ★★★ 但现在【不用急着分】的理由（★ 三条）

| # | ★ 理由 |
|---|---|
| **1** | ★★ **量级不对** —— ★ 我们今天的负载是**信封／小 JSON**（★ 1 KB 量级，★ **104 µs**）★ ⇒ ★ **数据面那条路现在【没有必须性】** |
| **2** | ★★★ **跨平台** —— ★ **`SCM_RIGHTS` 在 Windows 上没有**（★ 我们的宿主是 Windows）★ ⇒ ★ **直搬那条路要先解决 Windows 的对应物**（★ `DuplicateHandle` ＋ 命名共享内存）★ ⇒ ★ **不是一行的活** |
| **3** | ★★ **先跑通再分面** —— ★ **数据面可以后加**（★ 加的时候**不破坏总线那条规矩**：★ 语义面照旧发信封，★ 只是把「干货」换成取件码）★ ⇒ ★ **现在分 = 过早优化** |

## §三 ★★★ 分阶段的处置（★ 我的建议，★ 你定）

| 阶段 | ★ 做什么 | ★ 什么时候进 |
|---|---|---|
| ★★ **阶段一（现在）** | ★★ **都走 zenoh** —— ★ **数据也走** | ★ **现在**（★ 量级 < 100 KB ⇒ 亚毫秒） |
| ★ **阶段二** | ★ **加「取件码」**（★ 语义面发码 ＋ 数据面直搬） | ★★ **当出现 > 10 MB 的传输时**（★ 那时 44 ms/10MB 开始有感觉） |
| ★ **阶段三** | ★ **跨机**（★ 预签名 URL／Arrow Flight） | ★ 有多机时 |

★★★ **而「都走总线」这个决定现在是对的** —— ★ 因为：★ **① 简单（一条通道）② 跨平台（Windows 能跑）③ 先跑通** ✓

### ★★ 一条口径（★ 建议写进规格）

> ★★ **语义面：一切走总线（★ 包括现在的小块数据）。**
> ★★ **数据面：只在【真有大块】时才启用（★ 取件码 ＋ 直搬）；★ 它不替代总线，★ 只是给大数据一条近路。**

## §六 测量件（逐字 · 在载体 B，★ 不进 13）

```rust
//! 临时测量件（不进 13）：★ zenoh 发不同大小的负载，量【往返耗时】。
//! ★ 目的：回答「数据面能不能就走总线」这个疑问 —— 用数字，不用印象。
use std::time::{Duration, Instant};

fn payload(n: usize) -> String {
    let mut s = String::with_capacity(n);
    while s.len() < n { s.push('x'); }
    s
}

fn main() {
    let rt = tokio::runtime::Builder::new_multi_thread().enable_all().build().unwrap();
    rt.block_on(async {
        let s = zenoh::open(zenoh::Config::from_env().expect("cfg")).await.expect("open");
        for size in [1_000usize, 100_000, 1_000_000, 10_000_000] {
            let sub = s.declare_subscriber("world/bench").await.expect("sub");
            let p = payload(size);
            let t0 = Instant::now();
            s.put("world/bench", p.clone()).await.expect("put");
            let got = tokio::time::timeout(Duration::from_secs(20), sub.recv_async()).await;
            let dt = t0.elapsed();
            match got {
                Ok(Ok(sample)) => {
                    let n = sample.payload().to_bytes().len();
                    println!("  发 {:>10} 字节 ⇒ 收 {:>10} 字节，往返 {:?}", size, n, dt);
                }
                _ => println!("  发 {:>10} 字节 ⇒ 超时（{:?}）", size, dt),
            }
        }
        println!("（★ 这是【同机回环】；★ 一次序列化＋一次拷贝都在里面）");
    });
}

```
