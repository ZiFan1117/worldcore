# 调研：上游到底怎么执行 —— **原有命令行** 还是 **一套新东西**？（2026-10-15）

> ★ **作者问（逐字）**：「**他们实现的逻辑…是用原有的这个命令行吗？还是有一套新的东西在应用，就是你看一下它是怎么实现的**」。
> ★ 结论先给：★ **两种都在，而且是明文写死的三种模式**；★ **AI 那一侧走的是新东西**（类型化动作 ＋ 适配器）；★ **原有命令行没被替换，但被关进 `Lx` 模式**。
> ★ 本件是**读数件**：只读上游件，**没改代码、没跑构建**；每个结论都带 `文件:行`。

---

## §一 ★★ 终端面：**三种模式**（`crates/aios-terminal/src/enums.rs:10-24` 逐字）

| 模式 | 它自己怎么说的（逐字） | 读法 |
|---|---|---|
| **`Lx`** | 「Direct Linux/POSIX shell — **AI does not reinterpret commands**.」 | ★ **就是原有的命令行**；★ AI **不重新解释**它 |
| **`Mix`** | 「Natural language by default; **`LX:` prefix required for raw shell**.」 | ★ **默认自然语言**；要打原命令行**必须加 `LX:` 前缀** |
| **`Ai`** | 「AI intent mode only — **raw shell text is inert, not executed**.」 | ★★ **只收 AI 意图与类型化动作**；★ **裸 shell 文本是「惰性的」——不执行** |

★ **模式切换还受安全档位门控**（`aios-terminal/src/lib.rs:18-20` 逐字）：「mode switch … manages LX ↔ MIX ↔ AI transitions with **security profile gating**（**AIRGAP_HIGH = LX only**，**HIGH_RISK_READY = no AI mode**）」。

★ 同一 crate 里还有：**提案 7 态 FSM**（`Draft → Proposed → UnderReview → Approved → Executed`，另有 `Rejected`／`Revoked`）＋ **AI 标记**（`HumanWritten`／`AiProposed`／`AiGenerated`／`HumanReviewed`／`AiGeneratedHumanVerified`——「每一条 AI 产出必须**肉眼可辨**」）。

## §二 ★★ 执行面：**不是命令行，是「类型化动作 → 适配器」**（`crates/aios-capability-runtime`，37,129 行）

### §二·1 分发方式——**闭集四种**（`src/dispatch.rs:21-36` 逐字）

| 取值 | 它自己怎么说的 |
|---|---|
| `IN_PROCESS_RPC` | 适配器处理器**跑在运行时自己的进程里**（留给低延迟、不改状态的 `STABLE` 适配器） |
| **`SUBPROCESS_FORK`** | **每个动作一个子进程**；★ **文件系统改写／服务控制／包操作**这类「宿主侧适配器」的**默认** |
| **`ISOLATED_SANDBOX`** | **每个动作一个完整沙箱**（S3.2 `SandboxProfile`）；★ **AI 发起的动作强制走它**，★ 带特权标志的动作也强制 |
| `DRY_RUN` | 不改任何东西，**只出仿真记录** |

### §二·2 ★★ 最硬的一条：**自由形式的 shell 命令「不是一个取值」**（`src/dispatch.rs:38-55` 逐字）

> 「`AdapterIOMode` … **Free-form shell command input is not a value.** The L3 invariant (**adapters must not accept free-form shell commands as primary input**) and **INV-013 (AI cannot perform system admin operations)** preclude it.」

| 取值 | 它自己怎么说的 |
|---|---|
| `TYPED_PARAMETERS_ONLY` | **默认**：适配器只收 `request.target` 这个**类型化结构**，按清单里的 `target_schema` 校验 |
| `TEMPLATE_PARAMETERS` | **类型化模板**（也过 schema）＋**闭集替换变量**；逐字：「Used by adapters that legitimately need to **construct command lines without exposing free-form shell** to the caller」 |

★ 读法：★ **命令行没有消失，但它只能在适配器「内部」被构造**（模板那条口），★ **调用方（含 AI）拿不到自由形式的 shell**。

### §二·3 适配器要**登记 ＋ 签名 ＋ 会过期**（`src/adapter_manifest.rs` 逐字）

- `AdapterManifest`：`adapter_id`（`adapter:<vendor>:<name>:<version>`）／`declared_stability`／`io_mode`／`dispatch_kind`／`declared_actions[]`／`declared_invariants_supported`／`default_sandbox_profile_id`／**`adapter_signature`（Ed25519 over JCS）**／`signing_key_id`／**`manifest_expires_at`（强制）**
- 每条动作声明：`action_kind`（**点号名，取自 L5 能力目录**，例 `pkg.install`／`service.restart`／`fs.write`）／`target_schema`／`response_schema`／`rollback_strategy`（`NONE`／`IDEMPOTENT_REAPPLY`／`INVERSE_ACTION`／`SNAPSHOT_RESTORE`）／`timeout_seconds`
- ★ 注册**本身也是一个类型化动作**（`runtime.adapter.register`），且**不许自注册**（要 operator 类主体 ＋ 签名）；清单过期 ⇒ **自动注销**

### §二·4 八步流水线（`src/pipeline.rs:1-22` 逐字）

`submit_action(envelope, context)` 是运行时的**唯一热路径入口**，八步：

`① validate` → `② policy_evaluate` → `③ request_approval` → `④ queue` → `⑤ execute` → `⑥ verify` → `⑦ rollback` → `⑧ emit_evidence`

★ **如实（它自己写的）**：`pipeline.rs:24-30` 逐字——「**T-027 lands the driver skeleton, the §4.2 transition table, and the `apply_transition` enforcement gate. Step 1 … is real … Steps 2..8 are deliberately stubbed**」⇒ ★ **第 2–8 步今天是桩**，每步点名了落地它的任务号（T-028…T-035）。

★ 队列**四类**（`dispatch.rs:94-107`）：`INTERACTIVE`（人发起）／**`AGENT_PROPOSAL`（AI 发起，★ 封顶 50% 容量）**／`BACKGROUND`／`RECOVERY_PRIORITY`；★ 逐字：AI 想挤进 `INTERACTIVE` ⇒ **静默降到 `AGENT_PROPOSAL`** 并记一条证据。

### §二·5 安全面：把「绕过类型化动作」列为**禁用形状**（`aios-terminal/src/safety.rs`）

- 禁用形状枚举里有 **`TypedActionBypassAttempt`**，注释逐字：「Attempt to **bypass typed-action controls**」；★ 同段注释：「Block **raw shell execution**」（`safety.rs:167-197`）
- 它的测试里有两条对着这个：`raw_shell_exec_in_proposal_blocked`（喂 `"shell.exec"`／`"run shell"` ⇒ 必须命中）／`bypass_approval_blocked`
- 其它禁用形状：`AiSelfApprovalAttempt`（AI 自批）／`CovertOrDeceptiveAiIdentity`（AI 装人）／`VulnerableUserExploitation`

## §三 一句话把两条路画出来

```
【人】  Lx 模式 ──────────────► 原样 POSIX shell（AI 不重新解释）
        Mix 模式 ──「LX: xxx」──► 原样 shell；否则 ──┐
【AI】  Ai 模式（裸 shell 惰性）──────────────────┤
                                                  ▼
                        CognitiveIntent →（翻译器）→ ActionEnvelope（类型化）
                                                  ▼
                              Policy 门 → 审批门 → 队列（AI 只进 AGENT_PROPOSAL）
                                                  ▼
                              Capability Runtime 八步 → 适配器（**签名、会过期**）
                                                  ▼
                        IN_PROCESS_RPC ／ SUBPROCESS_FORK ／ **ISOLATED_SANDBOX（AI 强制）** ／ DRY_RUN
                                                  ▼
                                        宿主上真干活（子进程／沙箱内）→ 验证 → 回滚 → 证据
```

★ **准确的说法**：★ **原来的命令行没有「被替换」，而是被「关了门」**——只从 `Lx`（或 `LX:` 前缀）进；★ **AI 那条路是另起的一套**（类型化动作＋适配器＋沙箱＋审批＋证据）；★ 两条路**汇在同一个执行面**（Capability Runtime）；★ ★ **自由形式 shell 从来不是它的接口取值**。

## §四 对我们（worldcore 这一侧）意味着什么（★ 建议 · 待人裁）

| # | 上游这么干 ⇒ 我们该注意什么 |
|---|---|
| 1 | ★ 我们内核的 `gate_action_name`（**未登记即拒**）与它的设计**同向**：它的动作名也来自**登记的目录**（`AdapterActionDeclaration.action_kind` 取自 L5 能力目录）⇒ ★ 我们做的是**同一条纪律**，不是另起一套 |
| 2 | ★ 它的「自由形式 shell 不是一个取值」＝ 我们该有的**判据形状**：★ 我方代码里若出现「把自由字符串当命令执行」的口 ⇒ 应有一条会红的判据（★ 今天**没有**这条判据） |
