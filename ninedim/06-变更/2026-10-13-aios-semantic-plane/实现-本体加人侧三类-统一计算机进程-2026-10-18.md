# 实现：本体加人侧三类 ＋ 统一“计算机（computer）”进程（一个进程／一个类／一个个体）

> ★ **作者令（2026-10-18，逐字整理）**
> 1. 「反正是**先改本体**吧。**本体要兼容这么多东西**，先把本体改了。」
> 2. 「你想用 computer 就用 computer，想用载体就用载体。两个是弄的是一件事儿，是吧？**你就有一个就行**，而且**进程的整个名儿啥的全部改**，就都按统一的弄，**就一个进程，一个类，也是一个个体**。」
> 3. 「**不是改回去，是说所有的想变就变成了这个 computer，所有的东西，包括类啥的，全部换成 computer。**」（最终口径）
>
> ★ **本件是什么**：本轮在 13 仓落的两笔——**① 本体加人侧三类（space／presentation／computer）＋七关系＋许可条文；② 全体统一成 `computer`（类／个体／进程／单元／目录／crate／注释／环境变量全改）**。四要素读数见 §三。
> ★ **本件不是什么**：未部署 VM、未改 08 仓、未写 space/presentation 进程；许可条文是占位。
> ★ **命名沿革（如实）**：AIOS 旧名「载体/carrier」曾在 10-17 被采用；2026-10-18 作者最终定名 **computer（计算机）**，全部改从此名。同日中途的两次反复（先 computer、后 carrier、再 computer）以本件与 `改动对照.md` §一百四十五 为准；历史正文不改。

## §一 定了哪一件事：全部统一到 `computer`（计算机）

**口径**：**所有的东西，包括类，全部换成 computer**——世界里只有“计算机”这一个对象；不再另立/保留 `carrier` 类名。

| 项 | 统一后 |
|---|---|
| 类 | **`computer`**（display＝计算机） |
| 个体 | **`computer/<hostname>`**（默认 `socket.gethostname()`，可用 `AIOS_COMPUTER_NAME` 覆盖） |
| 进程 | **`py/computer_process.py`** |
| 单元 | **`distro/systemd/aios-computer.service`** |
| 环境变量 | `AIOS_COMPUTER_MAP` / `AIOS_COMPUTER_NAME` |
| 日志/注释 | `[计算机]`；代码/配置里不再出现 carrier/载体命名 |
| 上报字段 | `{"class":"computer","name":<host>,"hostname":<host>,"state":"in-service"}` |
| 数据目录 | **`distro/computer/`**（4 个数据文件：sysknife 三件 ＋ `command-map.jsonl`） |
| Rust crate | **已删除**（VM 运行时全 Python，Rust 侧 carrier/computer crate 退役；映射表移到 `distro/computer/command-map.jsonl`，Rust 测试与 C22 共用这一份） |
