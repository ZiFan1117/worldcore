## 一、★★★★★ 现取：Zenoh 的 `Sample` 已经给了我们要的全部头槽

★ **来源**：`docs.rs/zenoh/1.10.1/.../sample/struct.Sample.html`（**现取方法名列表**）

```
★ key_expr        名字（通配符 key expression）
★ payload         载荷（任意字节）      ｜ payload_mut
★ kind            Put / Delete（★ 是"发布"还是"撤回"）
★ encoding        载荷编码声明（如 application/json）
★ timestamp       时间戳（★ HLC 混合逻辑时钟）
★ source_info     来源信息
★ attachment      附加字节（★ 自定义元数据）  ｜ attachment_mut
★ priority        优先级
★ reliability     可靠性
★ congestion_control 拥塞控制
★ express         快速路径
★ timestamp_stack
```

### ★★★ 于是"我们的需求"逐条都有现成的槽

| ★ 我们要的 | ★ Zenoh 现成的槽 |
|---|---|
| ★★ **名字（在册吗）** | ★★ `key_expr` |
| ★★ **谁发的** | ★★ `source_info` |
| ★★ **什么时候** | ★★ `timestamp`（HLC） |
| ★★ **载荷** | ★★ `payload`（任意字节） |
| ★★ **载荷是什么格式** | ★★ `encoding` |
| ★★★ **我们自己的通行证（world／vocab_hash 等）** | ★★★ **`attachment`（自定义附加字节）** ✓ |
| ★★ **QoS（可靠／优先／拥塞／快速）** | ★★ `reliability`／`priority`／`congestion_control`／`express` |
| ★ 撤回（不是发） | ★★ `kind`（Put/Delete） |

⇒ ★★★ **"信封皮"一个槽都不用自己造** ✓

## 二、★★★ 那"载荷内容"借谁：CloudEvents

| ★ 候选 | ★ 它是什么 | ★ 借什么 |
|---|---|---|
| ★★★ **CloudEvents**（★ Rust SDK `cloudevents-sdk` v0.9.0，现取） | ★ **事件载荷的现成规范** | ★★ **事件该有哪些字段**：`id`／`source`／`type`／`subject`／`time`／`datacontenttype`／`data`；★ **关键是它的「扩展属性」** ⇒ ★★ **我们的词表版本等就往扩展属性里放** ✓ |
| ★★★ **Zenoh `Sample`** | ★ **总线自己的头** | ★★ 见上表（皮） |
| ★★ **W3C Trace Context**（OpenTelemetry 在用） | ★ **上下文传播头**（`traceparent`） | ★ 借它**"每一跳都带上下文"**的字段形状 |
| ★★ **JSON Schema** | ★ 载荷结构的校验规范 | ★★ **参数校验**照它（★ 我们已有 `FieldType`，可映射） |
| ★★ **AsyncAPI** | ★ 总线接口描述（不是载荷） | ★ 借它**描述主题与消息**（★ 出文档） |
| ★ **JWT／JWS** | ★ 签名载荷 | ★ 将来若要给信封签名 |

⇒ ★★★ **载荷也不用我们造**：★ **Zenoh 给皮、CloudEvents 给内容** ✓
