## §一 ★★★ 例子：装了一个「下载器」，它是怎么进来的、怎么被叫动的

### 场景

```
★ 老张在机器上装了一个下载器，叫 downloader。
★ 这个 downloader 【本来就有自己的对外接口】（比如它自己的 D-Bus 接口 / 命令行 / 本地端口）。
★ 它跟我们的世界没关系 —— 我们【不重造】它。
```

### 第一步：它把自己登记进来（★ 注册，不是我们替它编目）

```json
// 本体里因此多了这些（★ 示意，不是今天的实际内容）
"actions": {
  "download.start": {
    "parameters": [ { "name": "url", "param_type": "string", "required": true } ],
    "required_roles": ["human", "agent"],
    "registered_by": "downloader",          // ★★ 谁注册的（这条是【它】交上来的）
    "function": "fn.download.start"
  }
},
"functions": {
  "entries": {
    "fn.download.start": {
      "inputs": { "url": "string" },
      "output_type": "string",
      "transport": "bus",                                // ★★ 怎么叫它：走总线
      "endpoint": "bus:world.fn.download.start"          // ★★ 它自己的对外接口地址
    }
  }
}
```

★★ **注意三件事**：★ ① **名字是它交上来的**（不是我们替它起）；★ ② **`registered_by` 记着是谁**；★ ③ **`endpoint` 是【它的】接口地址** —— ★★ **我方【不复制它的接口】，只记那个地址**（★ 这就是「我没必要重新再造一套」）。

### 第二步：老张说「下载这个」（★ 走一遍）

```
★ 老张（或 GUI，或 Agent）只发一句：
    { action: "download.start", params: { url: "…" } }
        │
        ▼
★ 本体（唯一权威）过三道门：
    名字门：download.start 在册吗？           ⇒ 在 ✓（★ 它注册过）
    身份门：谁在说？                          ⇒ 老张（★ 系统认的，不是他自称）
    权利门：他配吗？                          ⇒ 配 ✓（human 在 required_roles 里）
        │
        ▼
★★ 关键一退：★ 本体【不自己去做】—— 它【不】去拼命令、也不去调函数；
        │
        ▼
★ 走总线发一条消息到那个 endpoint：
    → bus:world.fn.download.start  { url: … , 谁批的: 老张, 因果号: … }
        │
        ▼
★★ downloader 自己收下、自己干（★ 它怎么干，只有它知道 —— 我们既不问、也不记）
        │
        ▼
★ 它回一条：结果（OK／FAILED／REFUSED）＋ 因果号
        │
        ▼
★ 本体落一笔账：谁（老张）／何时／要了什么（url）／结果（前后值）
```

★★★ **这个例子里「谁是谁」一句话**：

| 东西 | ★ 在这个例子里 |
|---|---|
| ★ **Action** | ★ **`download.start`** —— ★ **downloader 注册进来的那件事**（★ 有副作用：它真会去下东西） |
| ★ **Function** | ★ **`fn.download.start`** —— ★ **它在本体里的那一格**；★ 而★ **真正的接口是 downloader 自己的**（★ `endpoint` 只是**它的地址**） |
| ★ **本体** | ★ **登记 ＋ 三道门 ＋ 传递（走总线）＋ 落账**；★ **它不动手** |
| ★ **执行者** | ★★ **就是 downloader 自己**（★ 不是我们另造的一个东西） |

## §二 ★★★ 你这个说法的好处（为什么它比我前面的说法对）
