# 方案（作者令）：执行完了就测 —— **用不同的用例好好测**

| 阶段 | 环 | 维 | 版本 |
|---|---|---|---|
| S3 | 执行 | 五 证据 | **1.0（作者令）** |

> **作者令（逐字）**：「然后你要是**执行完了，就测试**，就是**用不同的（用例）好好的测试测试**。」

---

## 一、★ 测试矩阵（六道门 ＋ 六个角度）

### 甲 · 六道门（命令层，每次必跑）

| # | 命令 | 判什么 |
|---|---|---|
| 1 | cargo test -p aios-worldcore | ★ 我们这一 crate 全部用例 |
| 2 | cargo test -p aios-worldcore -- --ignored | ★ 已知缺口的会红反例（★ 应为 0 ignored） |
| 3 | cargo test --workspace --tests --no-fail-fast | ★ 没弄坏上游 |
| 4 | cargo fmt --all -- --check | ★ 格式 |
| 5 | cargo clippy -p aios-worldcore -- -D warnings | ★ 我们这一 crate 的 lint |
| 6 | python verify/check.py | ★ 我方判据 C1–C7 |

### 乙 · 六个角度（用例层，逐条对着本体）

| 角度 | 怎么测 | 期望 |
|---|---|---|
| **① 本体逐条** | ★ **9 类** ×（注册／查询／存储／折现）；★ **9 动作** × 执行；★ **9 函数** × 调用；★ **4 族** × 账；★ **权限／治理** 各一条 | ★ 每一条都有一条用例；★ **没有"没用例的要素"** |
| **② 拒的每一档** | ★ 八个 Reason 各一条：UnknownKind／BadName／MissingField／BadValue／DanglingRef／OverInstanceLimit／NotPermitted／OntologyNotLoaded | ★ 每一档都**真能被触发**（不是写了不用） |
| **③ 边界与畸形** | ★ 空字段／空名／超长名／含空格斜杠引号的名字／同名重复／本体未装载／空本体／**缺五节之一**／非 JSON | ★ 全部**拒**，★ 且**拒的理由对** |
| **④ 顺序与幂等** | ★ 治理**先于**在册；★ **先记账再落表**；★ 重复登记**不重复记账**；★ 同一笔重放**结果相同** | ★ 顺序不可换；★ 幂等 |
| **⑤ 只追加与折现** | ★ 老账字节前缀不变；★ 序号**不复用**；★ 折现**后写覆盖前写**；★ 立碑**摘现状、不删历史** | ★ 篡改可发现 |
| **⑥ 五要素齐全** | ★ **对象／关系／接口能力／动作／函数** 各有一面、各有用例 | ★★ **函数面必须有**（作者点出的缺口） |

## 二、★ 报告的硬要求（每一格都要四要素）

★ 命令 ／ 原始输出 ／ 退出码 ／ 时点 —— **缺一栏视为未跑**。
★ **不绿不报"完成"**；★ 红了就**照实报红点**。

## 三、★ 若发现"没用例的要素"怎么办

★ **补用例**（★ 那本身就是发现）；★ 若某要素**接不上**（★ 例如某面根本无法实现）⇒ ★ **如实报"接不上 + 证据"**，★ 不许假装。

## 四、本件没做的事（如实）

1. ★ **还没跑**（★ 四席在重写中，跑的是中间态）；
2. ★ **没写**新的用例（★ 等四席交件后按矩阵补）。
