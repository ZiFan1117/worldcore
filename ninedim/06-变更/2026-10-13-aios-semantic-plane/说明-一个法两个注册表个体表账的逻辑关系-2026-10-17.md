## §二 ★★★★★ 现取出来的第二个发现：**`check()` 不查本体**

★ `core/command_bridge.rs` 的 `check()` **逐字**：

```rust
/// ★ 五格齐不齐（缺一 ⇒ 拒 —— 与「未登记即拒」同族）。
pub fn check(&self) -> Admit<()> {
    // ★ 界面类没有命令行 —— ★ 它注册的是**它自己的动作**
    let is_interface = self.registered_by_kind == "interface";
    let mut required = vec![("action"), ("function"), ("registered_by"), ("registered_by_kind")];
    if !is_interface { required.push(("program")); }
    // ★ 空 ⇒ MissingField
    // ★ registered_by_kind 必须是 world|system|app|interface
    // ★ required_roles 不能空
    Ok(())
}
```

★★★ **⇒ 它查三件：★ ① 五格齐不齐 ★ ② 枚举合法 ★ ③ `required_roles` 非空** ★ —— ★★ **它【不查】「这个名字本体认不认」** ✗

★★ **而 `as_registration()` 逐字**：★ 「它注册进注册表的**那五格**（**命令那两格不进**）」⇒ ★ **程序 `program`／`args` 不进注册表** ✓

## §三 ★★★★★ 所以我们这几个东西的【逻辑关系】（★ 答案）

```
★ ① 法（静态，人审）
   crates/aios-ontology/data/ontology.json
     ├─ objects 9 类
     ├─ actions 9 个（★ 世界自己的：world.rekey／ledger.compact／job.start…）
     ├─ families 四族（★ change／act／notice／job）
     └─ envelope 信封（★ world／kind／id／seq／at／actor／trace）
        │
        │ Registry::load
        ▼
★ ② 【注册表】＝ 法的运行时形态      ← ★★ **作者说的「真正的 registry」**
   Registry（内存五张表：objects／actions／links／functions／interfaces）
        │ 用在哪：个体化时查「这个类在册吗」
        │
★ ③ 载体的映射表（★ 私货，★ 不是注册表）
   crates/aios-carrier/data/command-map.jsonl（8 格，含 program／args）
        │ as_registration() 抽【5 格】（★ 命令那两格不进）
        │ check() 查五格齐不齐
        ▼

        ▼
★ ⑤ 注册表的内存形态  Register
        │ 用在哪：报到时查「这个名字装过吗」
        │
★ ⑥ 个体表（活）     Individuals（★ 内存，不落盘）
 ★ ⑦ 账（过程）       ledger（★ 只追加）
```
