## §〇 一句话：转换器是什么（先看这个，别的都可以不看）

★★ **它是一个单独的小进程，只干一件事：**

> **收到「语义动作」这条消息 → 查一张表 → 得出「这件事在系统里具体怎么做」→ 叫执行器去做 → 把结果写回账。**

★ 用你自己的那个类比（A2UI）对齐一下，两边是**同一个形状**：

| | ★ **屏幕上那一半**（已跑通） | ★★ **系统里那一半**（今天没有） |
|---|---|---|
| 上游出什么 | **一帧**（说「显示什么」） | **一个动作**（说「要世界怎么样」） |
| 中间是谁 | **渲染器**（把帧**画**出来） | ★★ **转换器**（把动作**翻**成系统里的做法） |
| 谁最后动手 | 屏幕（像素变了） | **执行器**（系统里真变了） |
| 能不能换 | ★ 渲染器**能换**（genui → 别的），**帧不变** | ★ 执行器**能换**（背光／包／任务），**动作不变** |

★ 一句话记住：**渲染器之于帧 ＝ 执行器之于动作；转换器就是把「动作」翻成「执行器认识的话」的那个中间件。**

## §一 它长什么样（进程 ／ 接口 ／ 权限 ／ 崩了怎么办）

```
        ┌───────────────┐   动作（语义名＋参数）   ┌──────────────────┐
        │  本体进程     │ ───────────────────────► │ ★ 转换器（本件） │
        │ （判在不在册）│                          │  单独一个进程     │
        └───────────────┘                          └────────┬─────────┘
                                                            │ 实现调用（含命令）
                                                            ▼
                                                   ┌──────────────────┐
                                                   │ 执行器（可换）    │
                                                   │ 背光／包／任务    │
                                                   └────────┬─────────┘
                                                            │ 结果（OK／FAILED／REFUSED）
                                                            ▼
                                                   ┌──────────────────┐
                                                   │ 账（只追加）      │
                                                   └──────────────────┘
```

| 项 | 现取口径（本方案定的） |
|---|---|
| **它是什么** | ★ **单独一个进程**（不是内核里的一个模块，也不是上游的一部分） |
| **它听什么** | ★ 一条**动作**消息：`{ 动作名（本体在册）, 参数, 谁发的, 何时, 因果号 }` |
| **它说什么** | ★ 给**执行器**一句「实现调用」；★ 给**账**一笔「结果」 |
| **它的权限** | ★★ **不给它 root** —— ★ **它只翻译，不碰系统**；★ 碰系统的是**执行器**那一侧 |
| **它不做什么** | ★ **不裁决**（有没有权 → 问门禁）、★ **不碰系统**、★ **不保存状态**（状态由账折出来） |
| **它崩了会怎样** | ★ 动作停在「**已受理、未执行**」—— ★ **账上看得出**（不是静默丢） |
| **它和谁住哪** | ★ 与本体进程、执行器同机；★ 今天那条闭环都住 VM（`/root/…`） |

## §二 ★★ 借鉴哪三处、怎么借（逐条：借什么 → 落成什么）

### 借鉴一：★ **我们自己 08 的 `carrier/`**（同一件事的上一代，1,700 行）

| 借它的什么 | 怎么落（本方案） |
|---|---|
| ★★ **`cap.d/*.json`（10 行一件的清单）** | ★ 我们的**表**照这个形状：`{ capability, provider, verbs, risk, undo, confirm, sandbox, preview }` |
| ★★ **`provider.rs` 的契约三词** | ★ 「**入参无歧义／返回结构化／失败类型化**」；★ 结局三态 `OK`／`FAILED`／**`REFUSED`** |
| ★★ **`execute.rs` 的八步顺序** | ★ 清单→动词→执行器→自报能力→确认→撤销点→执行→组装；★ **每步失败都不进下一步**；★ **只许拒、不许放行** |
| ★★ **`cross_check.rs`（对账判据）** | ★ **表里写的 `provider`，必须在执行器自报的能力里** —— ★ **对不上 ⇒ 红** |
| ★ **`run.rs`「先问、再做、再报」** | ★ 转换器**在门禁之后**才翻、才做；★ 结果带**因果号** |

### 借鉴二：★ **SysKnife 的三进程**（外部同题先例，MIT）

| 借它的什么 | 怎么落 |
|---|---|
| ★★ **三进程三角色**：`brain`（无权规划）→ `shell`（人批准）→ `daemon`（root 执行，唯一碰系统的） | ★★ **我们的转换器就是「独立成进程」的那一半**：★ **它自己不碰系统**（无 root），★ 执行器才是那只手；★ 批准那一格**今天我们不做**（先打通链路） |
| ★ **`ActionSpec.mechanism`（动作→命令那一栏）** | ★ 我们表的**右栏**（`provider` ＋ 参数形状）；★ **命令只在转换器→执行器这一跳出现** |
| ★ **它的经验：字符串白名单会被绕过**（引 GuardFall） | ★★ **我们不做命令字符串过滤**，★ 走「**模型/界面永远看不到命令**」这条路 |

### 借鉴三：★ **Home Assistant 的 entity ↔ integration**（成熟开源大件）

| 借它的什么 | 怎么落 |
|---|---|
| ★★ **语义名稳定、实现可换**：entity（语义）不动，换一个 integration（实现）名字照旧 | ★ 表的**左栏＝本体在册名**（稳定）；★ **右栏＝实现词**（可换）；★ 将来底层语义化，**左栏不改** |

## §三 要实现什么（五件东西 · 逐件给形状）

| # | 东西 | 形状（只给形状，不给代码） |
|---|---|---|
| **1** | **动作（消息）** | `{ action: "job.start", params: {...}, who: "wc_gui", at: …, trace: <上一笔的因果号> }`；★ **里面没有命令** |
| **2** | **表（一张，两栏）** | 一行一件：`{ capability: "job.start", provider: "job", verbs: [...], risk: "low", undo: "never", confirm: "never", preview: true }`；★ 放**运行时装的纯文本文件**（不进代码） |
| **3** | **执行器契约** | 入参：类型化的「实现调用」；出参：`Outcome { result: OK\|FAILED\|REFUSED, exit_code, detail, undo_ref }` |
| **4** | **顺序（写死）** | ★ **门禁 → 查表 → 执行器 → 回写**；★ 每步失败即停；★ **替换器只能拒、不能放行** |
| **5** | **留痕** | 结果那一笔带 `trace` ＝ 上游动作的因果号；★ `REFUSED`（根本没动）与 `FAILED`（试了没成）**分开记** |

## §四 三步走（每步：交什么 ／ 会红判据 ／ 过哪个闸）

| 步 | 交什么 | 会红判据（形状） | 过哪个闸 |
|---|---|---|---|
| **第一步**（最小可跑） | ★ **表 ＋ `job` 一个执行器 ＋ 转换器进程骨架**：把已跑通那条闭环里「**受理并记一笔**」那一格**真填上** | ★ **表里出现本体未登记的动作 ⇒ 红**；★ **表里的 `provider` 与执行器自报对不上 ⇒ 红** | 我方 `verify/check.py`（新判据）＋ VM 跑 |
| **第二步** | ★ **参数校验**（缺必填 ⇒ 拒）＋ ★ **「有权吗」那一格**接上 | ★ **缺一格参数却被放行 ⇒ 红** | 同上 |
| **第三步** | ★ **`preview`**（执行前给人看确切做法）＋ ★ **结果带因果号** | ★ **执行了而账上没有因果那一笔 ⇒ 红** | 同上 |

★ **第一步之外一律不动** —— ★ **要先把一条真链路跑通**（★ 作者口径：不许把「没做到」写成「做到了」）。

## §五 不做什么（写死）

| # | 不做 | 为什么 |
|---|---|---|
| 1 | ★ **不给转换器 root** | ★ 它只翻译；★ 碰系统的是执行器 |
| 2 | ★ **不做审批门**（人批准那一格） | ★ 第一版先打通链路；★ 要加是**另开一版** |
| 3 | ★ **不做命令字符串过滤** | ★ 已有外部证据说明这条路会被绕过；★ 我们**不给语言** |
| 4 | ★ **不引上游的执行面代码**（37,129 行那套） | ★ 口径：学理念、按我们的结构落 |
| 5 | ★ **不做「底层也语义化」** | ★ 那是**下一阶段**；★ 但表的左栏为它留好位置 |
