## 2. 能借鉴的机制（按对我们价值排序）

> 每条五格：**机制**／**他们怎么做（证据）**／**我们现状（落点）**／**怎么用**／**代价与注意**。

### 2.1 动作清单：前置条件 → 效果 → 副作用 → 回滚【最该借】

- **他们**：借书平台每个动作一份 YAML——`preconditions`（CEL 表达式＋人话错误）／`effects`（updateObject／createLink…）／`sideEffects`／`rollback.onSideEffectFailure`；执行八步 `Validate → Authorise → Consent → Preconditions → Execute → Side-effects → Audit → Emit`
  【事实】`open-foundry/examples/library-pack/actions/borrow-book.yaml`（本地已读）；流水线顺序逐字在 `open-foundry/packages/actions/src/executor/action-executor.ts:1-12`。
  订单样板同构但更「语义化」：`defineAction({objects, params, preconditions, effects, writeback})`，`effects` 只产出 **Edit 数据**（modify/create/link/unlink），不直接写库；`preconditions` 是纯函数，违规返回**机器可读拒绝码**【事实】`operational-ontology/src/core.ts:188-273`（另有 `_scratch/palantir-open-source/code-notes/01-gura105.md` §C、§D）。
- **我们**：`ontology_definition.py` 的 ActionType 只有 `parameters` ＋ 元数据；判定只有闸 ①②②.5③（认名/票/身份核验/许可），**没有「业务前置条件」与「效果清单」**；执行＝转发给计算机跑一条命令（`ontology_process._ask_and_forward` → `world/exec`）。
- **怎么用**：给我们的动作补**清单三件**——`preconditions`（受控谓词，不用 eval）／`effects`（对 ObjectStore 的变更：create/patch/link/retire）／`on_failure`（拒绝码＋是否补偿）。先在 `notice.*`／`space.*`／`identity.*` 这 19 个在册动作上落，`sys.*` 只补 `preconditions` 一层。
- **注意**：他们的 CEL 是 Go 边车，且实测 `has_link/count_links` 恒 false（`code-notes/03-syzygyhack.md` §D.5.2）；**别引 CEL/eval**。我们的定义是 Python 代码，直接用**纯函数谓词**最稳。

### 2.2 状态所有权三态 ＋ 权威线四类拒绝码【最该借】

- **他们**：订单样板把状态分成三态——`source-backed`（上游系统拥有）／`ontology-owned`（本体拥有）／`derived`（查询时算），**「没有声明主人的状态是禁止的」**；每条 edit 都要判成 `source|ontology|Violation`。越线四种码：`INVALID_EDITS`／`UNDECLARED_SOURCE_WRITE`／`MISDECLARED_WRITEBACK`／`MIXED_AUTHORITY`
  【事实】`operational-ontology/src/core.ts:67-90`（owned 声明）、`:738-776`（四类拒绝）、`:886-910`（逐 edit 分类）；`code-notes/01-gura105.md` §E.0、§E.3。
- **我们**：有「四归属」的说法（脸归提供者/摆放归个人空间/合成归呈现/口归身份）与 `registered_by_kind`，但**没有逐格的所有权声明与检查**：`on_appear` 只按类的必填/多塞校验；动作只判「谁能调」，不判「改的是谁的格」。
- **怎么用**：在 `ontology_definition.py` 给每个类的每个格标 `owner`（例：`human.last_seen` 归登录/呈现代报；`space.state` 归空间；`computer.state` 归计算机；`presentation.*` 归呈现）；闸③之后加**权威线**检查：写别人拥有的格 ⇒ 拒，带业务码（不落成普通「不许」）。这一条直接接上我们已有的硬约束「**手如果有写权限，世界就有了第二个权威**」。
- **注意**：他们的整份计划只能站一侧（`MIXED_AUTHORITY`），要跨界就拆动作——我们的动作本来就小（单动作单命令），这个限制对我们反而合适。

### 2.3 拒绝码分类 ＋ 每次尝试都审计【便宜且立刻有用】

- **他们**：订单样板**四类码**分明——有效性／未声明源写／空转写回／跨界混合；另加三个失败码（缺适配器/写回失败/本地提交失败）。审计覆盖 **applied＋rejected** 两侧，含未知动作、非法参数、崩溃（`EXECUTION_CRASHED`）【事实】`core.ts:295-311` 的审计写点表（notes §D.1）；主稿把「拒绝码是给机器看的，不是给人看的」列为四大细节之一（`04-research-ontology/Palantir开源版-详细解读.md` §5.6）。
- **我们**：账里有 `kind_of=reject / reject-ticket / reject-noid / reject-permit / reject-ident / result / ask`，**是自由字符串、没有闭集、没有分类**；`why` 是人话，无机器可读码。
- **怎么用**：给拒绝码建**闭集**（业务拒绝／权限拒绝／身份拒绝／系统错误四类＋码），账本统一落 `code` 字段；报告/智能体按码分流（改参数／找人授权／报警）。改动小（`ontology_process` 三处拒绝点＋判据），收益大（我们已有 28 条判据，正好加一条「拒绝码必须在闭集内」）。
- **注意**：这不只是「好看」——我们的 agent 与 DSH 插件都靠 `why` 解析失败原因，有码之后它们才能自动恢复。

### 2.4 审计与编辑同事务／写回先行／崩溃分叉留证【地面层，别忽视】

- **他们**：订单样板把**编辑与审计条目放进同一个 SQLite 事务**（要么都成要么都不成）；**写回先行**（先写源系统、再本地 commit），两个分叉方向各留一条带完整 plan 的审计（`WRITEBACK_FAILED`／`COMMIT_FAILED`）【事实】`core.ts:778-823`、`code-notes/01` §D.2/§E.4。借书平台则相反：审计在**事务提交之后**、失败只 warn（`code-notes/03` §D.10）——两种取向，各有代价。
- **我们**：世界状态在 **ObjectStore(SQLite)**，账在 **JSONL**，注册表又是 **另一份 JSONL**；三份载体，**没有跨载体事务**；崩溃窗口里可能「对象变了、账没记」或反过来。
- **怎么用**：二选一，别含糊：① **账先写**（append-only 账先落盘，ObjectStore 当投影，可从账重放）；② 或者把账做成 SQLite 同库表、与对象写在**同一事务**，再定期导出 JSONL。我建议 ①（与作者「账只增不改」的口径一致）。
- **注意**：别抄他们的「数据库事务」四个字；我们要的是**跨进程/跨载体的补偿语义**——他们的 `ROLLBACK_ALL` 连自己都承认补偿不逆序、删除不可恢复（`code-notes/03` §D.9）。

### 2.5 查历史：版本历史 ＋ 时间旅行查询【补我们一个明缺口】

- **他们**：借书平台有**版本历史/时间旅行**（`getObjectAtVersion/getObjectAtTime`，内存/PG 两套实现）【事实】`open-foundry/packages/spi/src/storage-provider.ts` 的 versioning 段；`code-notes/03` §F.5。订单样板没有（教学定位）。
- **我们**：作者早就要求「**查历史也要过本体**」；`ontology.json` 里 `families.act` 的注释还写着「请求→结果的因果边只有 `trace`，不做引用完整性」（`ontology_definition.py` 的 metadata 原文）。但 `world_query.py` 的 `kind` 只有 `world/actions/types/type/one/link`，**没有 history**。
- **怎么用**：加 `world/query kind="history"`：按 `subject/action/时间窗/reject码` 从**账**（不是从对象）翻；ObjectStore 每类加 `_version`＋变更历史投影（可从账重放得到）。判据：查历史必须能复现出「某一笔动作的 applied/rejected 两侧」。
- **注意**：账按时间标签、无 seq（作者裁过）⇒ 历史查询按 `at`＋`id` 排序，别把时间当唯一序（同一毫秒会撞）。

### 2.6 关系鉴权（ReBAC）＋ 分级/脱敏的执行面【我们只到声明面】

- **他们**：借书平台用 OpenFGA 关系（`user:<id> viewer <type>:<id>`）做对象级读/写鉴权；字段级脱敏要 `permissions/field-permissions.yaml`，**一旦配了就「没列出的字段全隐藏」**；同意（consent）挂在动作链路第 3 步【事实】`code-notes/03` §E.1-§E.3。小模型的 DYNAMIC 层（Roles/Markings/Permissions/Audit）是**声明齐、执行无**（`code-notes/02` §E、§0 第 8 条）。
- **我们**：`governance` 四格（`markings`／`roles`／`read_allow`／`tombstone`）**声明面全建**（`ontology_definition.py` metadata；`_source` 逐字引小模型的 `docs/architecture.md`），但 **Python 侧没有任何读者**（现取 grep：`src/` 里除定义文件外 0 处用 `governance|markings|read_allow|tombstone`）。许可只是 `grants` 的前缀列表（`can_execute`）。
- **怎么用**：先落**读侧**最小版：`read_allow.default` ＋ `roles.subject_to_role` ＋ `markings.by_class/ceiling_by_role` ⇒ `world/query` 按调用者角色过滤/脱敏；再落**写侧**：对象级关系（谁是这个 `space` 的 `owner`、谁是这个 `computer` 的 `operator`），替代「前缀匹配」。这同时能治我们的「自称 actor」缺口。
- **注意**：别引 OpenFGA 服务；借它的**形状**（关系元组＋关系图 check），实现成我们自己的小表。字段脱敏要**显式白名单**（借书平台的反转规则是个好设计：配了文件就默认全隐藏）。

### 2.7 工具面从模型派生（MCP），不是手写【给智能体那一侧】

- **他们**：订单样板一句设计句最值钱——「**因为模型是数据，agent 的工具面是派生的，不是手写的**」；没有 raw SQL、没有通用 update 工具，**「不存在」本身就是设计**：agent 拿到的操作空间恰好等于模型定义的空间；工具名冲突在构建期失败【事实】`operational-ontology/src/mcp.ts:1-23`、`:77-229`（notes §F.5）。借书平台的 GraphQL/REST 也是从 ODL **生成**的。
- **我们**：agent 侧是**手写**的 DSH 插件（`scripts/dsh-plugins/aios-world/index.js`，3 个工具 world_query/world_ask/world_ui）；换个 agent（Claude 等）就得再写一遍。
- **怎么用**：从**本体定义**（action_types ＋ parameters ＋ grants ＋ query kinds）生成一份 **MCP server**（工具＝在册动作＋查询＋读账），让任何 agent 直接接；DSH 插件退化成 MCP 客户端。判据：工具清单 ≡ 在册动作清单（多一个少一个都红）。
- **注意**：他们 dev 模式 allow-all 坑要避开——我们的工具必须**走本体闸**（票＋许可＋凭证），不能直连 ObjectStore。

### 2.8 接口／共享属性／值类型（TBox 补全）

- **他们**：小模型有 `Interface`（能力合同，带 `required_properties`）；OSDK Maker 有 **Interfaces / Shared Property Types / Value Types** 三种可复用定义（`_scratch/palantir-open-source/osdk-maker-README.md`）；借书平台的 ODL 有 `@interface` 与 `@actionType(permission:)`【事实】`code-notes/02` §C.3、`code-notes/03` §C.2。
- **我们**：**interfaces＝0**（现取：`o.interfaces` 长度 0）；`fields` 是自由记法串（`"string"`／`"ref(x)"`），`base_types` 只是张对照表；`value_types` 只有 1 条 `record_kind`。
- **怎么用**：先加 `interfaces`（例：`可执行`＝有 `run(action,params)` 的合同、`可呈现`＝有 `frame() -> a2ui`、`有身份`＝有 `who`），再把 `computer`／`presentation`／`space`／`agent` 挂上；`value_types` 补 `record_kind` 之外的枚举（`state` 已经是 enum 串，可以收编）。这是**纯声明面**改动＋判据，不动运行链。
- **注意**：别为了「像 Palantir」造空接口；每个接口必须至少有一个类实现，否则判据红。

### 2.9 OWL/SHACL 单向导出桥（接 08 的标准面）

- **他们**：小模型的真卖点之一：`OWLExporter`（ObjectType→`owl:Class`、Property→`owl:DatatypeProperty`、LinkType→`owl:ObjectProperty`、Interface→`rdfs:subClassOf`）＋ `SHACLGenerator`（required→`sh:minCount`）；但缺口也明摆着：无 `owl:Ontology` 头、不表达 required/基数、规则不转、不可回读【事实】`code-notes/02` §F.1-§F.2（`foundry-ontology-open/foundry_ontology/export/`）。**我们的 vendored 副本只带了 core+engine，export/mcp/governance 没带**（现取两个目录对比）。
- **我们**：08 仓在做 BFO/OWL 对齐；13 仓的硬约束是 **B-3：不接 RDF/OWL 运行时（只导出、不推理）**——正好与「导出桥」不冲突。
- **怎么用**：给 13 仓加一个**单向导出**：`ontology.json` → OWL(Turtle)＋SHACL Shapes，作为构建产物（不手改），吃 `04-research-ontology/foundry-ontology-open` 的 MIT 代码或自写；用途是**与 08 的语义层互核**（类/属性/关系的同一性）。判据：导出后 `pyshacl` 对导出实例能校验、且类/关系数与本体对得上。
- **注意**：别声称「符合 BFO」——形状取自不等于符合；这是**导出对照物**，不是语义对齐的证明。

### 2.10 域包形状 ＋ 动作八问 ＋ 场景测试（方法论）

## 3. 我们已经借过什么、以及借错了一处（必须说清）

### 3.1 已借（【事实】，可核）

- **小模型的代码**：`src/foundry_ontology/`（core＋engine 共 14 个 .py）就是 `cloudbadal007/foundry-ontology-open` 的同一棵树；`src/NOTICE.md` 有登记。
- **小模型的「三层切分」**：`ontology_definition.py` 的 `governance` 四格（markings/roles/read_allow/tombstone），其 `_source` 逐字引 `foundry-ontology-open/docs/architecture.md` 的「Roles • Markings • Permissions • Audit Trail」与「Data classification (PUBLIC, INTERNAL, CONFIDENTIAL)」——**这是 08 时代就借进来的**，不是这一轮。
- **08 的 BFO/OWL 线**：与本文件 §2.9 的「导出桥」同向；13 仓今天没有导出件。

### 3.2 ★ 借错了一处：`who` / `scope` 同词两义，且 Python 判定读错格

- **来源口径**（08 时代写进 `permissions` 的条文，现取）：`grants.<能力>.who` ＝「**谁能把某个能力授给谁**」（授权者）；`scope` ＝ 真正生效的**被授权主体**；条文里逐字有「`who` 无读者」「只动 `scope`，不动 `who`」等句子。
- **Python 现状**：`ontology_process.can_execute(actor, cap)` **读的是 `who`**（`g["who"]` 前缀匹配）。而 13 自己新加的人侧动作（`presentation.*`／`space.*`／`identity.*`）的行**只有 `who`、没有 `scope`**（它们把 `who` 当「被允许的主体」用）。
- **现取读数**（本机真跑 `can_execute`）：

```
notice.mute  => who=["world://user","world://agent/dsh"]  scope=[… , "world://presence/omarchy"]
can_execute("world://presence/omarchy", "notice.mute") => (False, "…不在许可里（谁可以：['world://user','world://agent/dsh']）")
```

  ⇒ **按 08 的 scope 语义，omarchy 本来是被允许的；按 Python 的 who 语义，它被拒。** 同一个字段名，两个意思。
- **处置建议**（小改动，先做）：二选一并配一条会红的判据——
  ① **判定改读 `scope`**，并给 13 自己新增的行补 `scope`（`who` 只留条文/授权者语义）；或
  ② **放弃 `scope`**，把 `who` 正式改名为 `allowed`（一次性迁移＋判据）。
  ★ 这是「一个事实两个载体／同词两义」的现场，不是文风问题——**判定读错格，会静默地把该放行的主体关在门外**。

## 4. 不要借的（【判断】）

| 别借 | 为什么 |
|---|---|
| 它们的**运行时/存储/API 形态**（PostgreSQL＋AGE、OpenFGA 服务、OIDC、CEL Go 边车、CDC、多租户） | 我们是**语义 OS 层**（总线＋进程＋本体），不是数据平台；引一个服务就多一个要养的东西 |
| 它们的**「事务」**（数据库 BEGIN/ROLLBACK） | 我们的事务跨进程/OS，答案应是**补偿＋账**（写清失败三种：业务拒绝/权限拒绝/系统错误） |
| **高星大而全**（u485349 / P2Enjoy 双胞胎） | 空 LICENSE／孤儿 fork／未验证（02-oss-landscape §2.3）；「星多 ≠ 可信」 |
| **`eval` 字符串规则**（小模型的 validation_rules、借书平台的 CEL 也有实测失效） | 我们宁可要**受控谓词**（Python 纯函数/JSON-logic），不要 eval；CEL 在他们那里 `has_link` 恒 false（code-notes/03 §D.5.2） |
| **「进程内库」的安全模型** | 他们自己承认「拿到 DB 句柄就能绕过」；我们刚用 permit 把**总线层**堵上，方向相反、别抄回去 |
| **把「三层图」当成绩** | 小模型的动态层是占位、借书平台 40% 是脚手架（code-notes/03 §K）；借的是**能跑的形状**，不是文档口径 |
