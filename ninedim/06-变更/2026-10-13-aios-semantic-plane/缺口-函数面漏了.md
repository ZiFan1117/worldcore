## 一、缺口：本体五要素只落了四个

★ 本体的五要素（逐字）：**对象／关系／接口能力／动作／函数**。

| 要素 | 本体现取 | ★ 我们的八面 |
|---|---|---|
| 对象 | objects 9 类 | ★ 面② 实例注册 ＋ 面④ 存储 ✓ |
| 关系 | links 3 条 | ★ 面④ 存储（links 字段）—— 部分 |
| 接口能力 | interfaces 9 条 | ★ 面⑧ 治理（授权对象）✓ |
| 动作 | actions 9 条 | ★ 面⑦ 执行 ✓ |
| ★★★ **函数** | ★ **functions 9 条** | ★★★ **一间都没有** ✗ |

## 二、functions 是什么（现取）

```
fn.notice.mute / fn.notice.unmute / fn.job.start / fn.job.finish / fn.job.cancel
fn.ledger.compact / fn.world.rekey / fn.world.migrate / fn.presence.report

每条的结构（逐字）：
{ function_id: fn.notice.mute,
  display_name: 把一条通告静音,
  description: ★ 动作 notice.mute 的实现面（照 P 的 OntologyFunction.describe 形状；不抄 implementation、不抄 effects）,
  inputs: { subject: enum(change,act,notice,job) },
  output_type: enum(change,act,notice,job) }
```

⇒ ★★★ **本体自己写着：functions 是「动作的实现面」** ⇒ ★★ **所以「执行」本该是**：

```
查动作在册  ➜  找它对应的函数（fn.<动作名>）  ➜  调这个函数  ➜  拿结果
```

★ 而我们今天的 Exec::execute **只查了动作在册**，★ 然后交给一个 DryRun（它自己都写着「别读成已经会做了」）⇒ ★★ **「函数执行」这一段整个是空的** ✓

## 三、顺带：Registry 也没把函数读出来

★ 我们的 Registry 有 kinds／actions／capabilities／families ⇒ ★ **没有 functions**。
★ 所以「函数在册吗」这件事，**今天无人可答** ✓
