# 方案（待签）：梳理本体 —— 去掉 `_` 那套私约，按"人家本体怎么设计的"来

| 阶段 | 环 | 维 | 版本 |
|---|---|---|---|
| S2 | 意图 | 二 框架 ／ 六 规格 | **0.1（方案·待签）** |

> **作者令（逐字）**：「**你梳理一下这个本体啊**，这个东西好好的要弄一下啊，**就不要存在什么下下划线啥的**，那个你**你不要有这种**，就是**老老实实的，有几个就是几个**，**按照人家本体怎么设计的就怎么来**。」
> **件性质**：方案件。★ 分步可验；★ **签字前不动本体结构**。

---

## §一 ★★ 现状（现取）

| 项 | 现取 |
|---|---|
| **`_` 开头的节** | ★ **40 个** |
| **非 `_` 键** | ★ **4 个**：`envelope`／`families`／`flags`／`world` |
| ★ 根子 | ★ 本体自己写着：★ `vocab_hash` **递归剔除 `_` 开头的键** ⇒ **在 `_` 键下加分节不换词表身份** ⇒ ★ **于是"说明、登记、留档、口径"全塞进 `_` 键** ⇒ ★ **40 个** |

⇒ ★★ **作者这句话点到了根子上**：★ **`_` 前缀成了一套"私约"** —— ★ 什么该装本体、什么该装说明，**靠"加不加下划线"区分** ⇒ ★ 结果是**本体文件里 40 个节，只有 5 个是真本体**。

## §二 ★★ "人家本体怎么设计的"（照 P 的 `core/`，逐字成员）

| P 的件 | 它是什么 |
|---|---|
| `object_type.py` | ★ `ObjectType`（＋`SharedProperty`／`ValidationResult`） |
| `link_type.py` | ★ `LinkType` |
| `action_type.py` | ★ `ActionType`（＋`ActionParameter`／`ValidationRule`） |
| `function.py` | ★ `OntologyFunction` |
| `interface.py` | ★ `Interface` |
| `data_types.py` | ★ `PropertyType`（13 值）＋ `ValueType` |
| `ontology.py` | ★ **`Ontology`** —— ★ **把上面这些装在一起的那个对象** |

⇒ ★★ **即：一个本体的成员就是那几样**（类／关系／动作／函数／接口／值类型），**外加一个把它们装起来的容器**；★ **没有"40 个下划线节"这种形态**。

```json
{
  "world":      { ... },   // 词表版本（非 _）
  "envelope":   { ... },   // 事件信封（非 _）
  "families":   { ... },   // 记录四族（非 _）
  "flags":      [ ... ],

  "objects":    { ... },   // ★ 原 `_objects`
  "links":      { ... },   // ★ 原 `_links`
  "interfaces": { ... },   // ★ 原 `_interfaces`
  "actions":    { ... },   // ★ 原 `_actions`
  "functions":  { ... },   // ★ 原 `_functions`
  "types":      { ... },   // ★ 原 `_types`
  "permissions":{ ... },   // ★ 原 `_permissions`
  "governance": { ... },   // ★ 原 `_governance`
  "presence":   { ... },   // ★ 原 `_presence`（状态面）
  "clock":      { ... },   // ★ 原 `_clock`
  "units":      { ... },   // ★ 原 `_units`
```

★ **判据**：★ **顶层键"有几个就是几个"** —— ★ 每个都是**有名字的本体成员或容器**，★ **不再有"靠加下划线来区分死活"** ✓

## §四 ★★ 40 个 `_` 节怎么分（本席的三档）

| 档 | 节 | 处置 |
|---|---|---|
| ★ **甲：真本体**（5） | `_objects`／`_links`／`_interfaces`／`_actions`／`_functions` | ★ **去 `_`，成顶层实体节** |
| ★ **乙：本体的一部分（口径/规则）**（约 10） | `_types`／`_permissions`／`_governance`／`_presence`／`_clock`／`_units`／`_identity`／`_anchor`／`_layers`／`_modules` | ★ **去 `_` 成顶层；或统一收进一个 `rules`／`notes` 节**（★ 待裁：★ 它们是"本体的规定"还是"注解"） |
| ★★ **丙：说明/登记/留档（不是本体）**（约 25） | `_comment`／`_source`／`_borrowed`／`_terms`／`_criteria`／`_decisions`／`_evidence_form`／`_five_elements`／`_section_map`／`_standards`／`_抄自P`／`_retired_objects`／`_retired_sections`／`_proposed_objects`／`_property_types`／`_storage_class_map`／`_public_cells`／`_shared_properties`／`_pending_tables`／`_declared_debt`／`_disjoint_policy`／`_seat_dispatch`／`_subscribe`／`_catalog`／`_meta_layers` | ★★ **移出本体** —— ★ 它们**不是本体，是"关于本体的话"** ⇒ ★ 按标准叫 **Annotation** ⇒ ★ **该进 `notes`，或干脆移去 `ninedim/`（档案面）** |

⇒ ★★ **一句话**：★ **40 个里只有 5 个（＋约 10 个"规定"）是真本体；其余 25 个是"关于本体的话"** —— ★ 它们**不该和本体挤在一个文件里**。
