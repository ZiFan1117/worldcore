## §一 ★ 模型（按第 7、8 句校正后的读法）

**读法**：
- **呈现（presentation）＝ 一块显示输出的设施**（渲染器＋合成器），**一块屏一个**；它**不记人、不记空间**，只做一件事：**把此刻“活着、且指向这块屏”的画布合在一起**。
- **换人时变的只有两样**：① **空间**（甲的空间 `inactive` → 乙的空间 `active`）；② **画布**（甲的画布全部 `retract` → 合成器自然“不合了”；乙的画布 `show` → 合成器合进来）。**呈现/合成器不动。**
- **个人化在空间（space）**：桌面、布局、壁纸、主题偏好都属于空间；呈现不承担个性化。

```
device / computer（屏与机器，共用）
   └─(hosted-on)── presentation（一块屏的呈现设施：渲染器＋合成器；★ 不记人、不记空间）
                      └─(has-surface, 1:N)─▶ surface（画布：每块“向人的表达”）
                                                  ├─(provided-by-*)─▶ agent / service / application / 本体
                                                  ├─(in-space, 可选)─▶ space（这块画布属于谁的空间）
                                                  └─ state: shown / retracted
human ──(has-space, 建议 1:1)──▶ space（个人空间：owner、state=inactive/active/closed；细节不进本体）

换人：甲 space → inactive；甲的 surface 全部 retract；乙 space → active；乙的 surface show；
      合成器只合“此刻 shown 的 surface” ⇒ 旧的自己消失、新的自己出现，呈现从头到尾没变。
登录屏：没有任何 shown 画布的状态（或由接入进程发一块 login 画布）——同样不新建“登录呈现”。
```

★★ **呈现的字段只有**：`name`、`host`、`state`、`compositor_kind`——**没有 `current_user`、没有 `current_space`**（那两格等于把“人”又塞回呈现）。
★ **世界怎么答“这块屏现在给谁看”**：查此刻 `shown` 的画布 → `in-space` → `space.owner` → 那个人；答案从**画布＋空间**折出来，不由呈现自己记。
★ **隐私/权限的落点**：**非 `active` 空间的画布不得 `show`**（谁的空间没激活，谁的画布就不能上屏）——这是一条会红的判据。
★ **合成器无状态**：界面不持状态、不裁决；它只按“当前集合”合成。
★ 依据（作者本轮第 8 句）：「把现有的画布、新的画布合在一起；之前那个人的就不合了，新的这个人的就合一下。」

## §一·补 ★ 数量与生命周期

| 东西 | 数量由什么决定 | 换登录 / 换人时 | 会不会不停加 |
|---|---|---|---|
| `presentation` | **显示输出数**（物理屏/虚拟屏/远端屏；**不按机器、不按人、不按 CPU**） | **不变**（呈现不记人） | 不会（除非加屏/加输出） |
| `space` | **人数**（一人一份） | 只改 `state`（甲 inactive、乙 active） | 人数增才增 |
| `surface` | **当前活跃表达数** | 甲的全部 `retract`、乙的出现 | 不会永久堆积（撤回制） |
| `compositor` | **实现/设施数**（不是人数；现为 `compositor_kind` 一格） | 不变（换人 ≠ 换合成器） | 不会按人加 |
| 账本 | 事件数 | 每次登录/切换/show/retract 一行 | 会增长——但那是**记录**，不是对象 |

★ **注册 ≠ 运行（两层面）**：`space` 的**类**在定义面注册一次；每个**个体**在册（每人一个、持久化）；**运行/激活是另一层**——登录只把当前人的空间置 `active`，其余 `inactive`，**不需要全部激活**。
★ **画布是瞬时的**：**不注册**（不进定义面/注册表），只走 `show → retract`；新建/删除是常态，账本留痕，ABox 里可移除。

## §二 类与字段（提案）

| 类 | 字段（格） | 说明 |
|---|---|---|
| **`presentation`（新）** | `name`*（按屏，如 `screen0`、`screen-remote/1`）、`host → device/computer`、`state`（awaiting-human／active／locked）、`compositor_kind`（browser／gtk3／flutter／none） | **一块显示输出的呈现设施**；**不记人、不记空间**；**不含内容/布局/像素** |
| **`surface`（已有，改定义）** | `name`*、`role`（login／desktop／workspace／confirm）、`state`（shown／retracted）、`digest`、`size` | 定义从“屏幕那一面”改成“**一块向人的表达，可指向、可撤回**”；**瞬时** |
| **`space`（新）** | `name`*、`owner → human`、`state`（**inactive／active／closed**） | 个人空间，一人一份；**在册 ≠ 激活**；**不并入呈现** |
| **`human`（已有）** | name／did／last_seen | 主体 |
| **`agent`（已有）** | name／did／manifest／state | **无画面**；对外发布 action |
| **`computer`（10-17 裁）** | name／hostname／owner→human／bound_to→human／state | 机器 |
| **`device`（已有）** | name／cert／bound_to→human | 屏等设备（见 §八·G） |

★ 引擎现取约束：`Property` 类型只有标量/引用（STRING／INTEGER／BOOLEAN／OBJECT_REFERENCE），**没有嵌套对象**；`surface.cells` 那种“`array(object)`”其实是 STRING 里塞 JSON（不可核）。⇒ **字段用平字段。**

## §三 链接（提案）

| 链接 | 从 → 到 | 基数 | 说明 |
|---|---|---|---|
| `human-has-space` | human → space | 1:1（建议） | 一人一份空间 |
| `presentation-hosted-on-device`（或 `-computer`） | presentation → device/computer | N:1 | 呈现跑在哪块屏/哪台机器 |
| **`presentation-has-surface`** | **presentation → surface** | **1:N** | ★ 画布挂在呈现下（组合/附属；**“当前有哪些画布”就查这里**） |
| `surface-provided-by-agent` | surface → agent | N:1 | 画布是谁给的（按提供者类型分开；见 §八·C） |
| `surface-provided-by-service` | surface → service | N:1 | 同上（载体/服务） |
| （可选）`surface-in-space` | surface → space | N:1 | 这块画布属于谁的空间（“这块屏给谁看”由 `shown` 画布折出） |
| （可选）`device-has-presentation` | device → presentation | 1:1 | 一块屏对应一个呈现设施（也可只由 `presentation.host` 反向表达；见 §八·F） |

★ **人与呈现：不建“人拥有呈现”的链接**；呈现也**不记** `current_user`/`current_space`——人的上下文在 `space` 与 `surface` 上。
★ 现取：引擎 `LinkType` 两端类型**固定**、支持 `Cardinality.ONE_TO_MANY`（见 `py/ontology_definition.py:128-134`）。

## §四 动作（提案，均过门禁）

| 动作 | 目标 | 说明 |
|---|---|---|
| `presentation.show` | presentation | 把一块 surface 放上去（params：surface 名、内容句柄或内联、布局提示可选）；**占人的注意力，值得许可** |
| `presentation.retract` | presentation | 撤下一块 surface（换人时由会话/空间侧撤） |
| `presentation.notify` | presentation | 向人通知（原 `interface.notify` 那条线的重立；**现取 13 代码零命中**） |
| `presentation.confirm` | presentation | 向人要确认 |
| `space.activate` / `space.deactivate` | space | 登录/登出、换人时由接入触发（或显式动作）；改 `state` 落 change |
| `space.set_wallpaper` 等 | space | 人的地盘动作；目标记 space，谁改的记账 |

★ 内容大时走**旁道/句柄**，本体/账本只留 `digest`/`size`（书 §4.5）；13 已有先例：`{"kind_of":"notice","notice_kind":"a2ui.frame","by":…,"about":"界面","size":1956}`。

- A2UI 组件树、像素、**布局/层叠/焦点/可见性**、壁纸、主题、渲染器缓存、输入法状态；

## §六 登录 / 换人 / 登出（呈现不动）

| 阶段 | 空间 | 画布 | 呈现 |
|---|---|---|---|
| 开机 | 全部 `inactive` | 无 shown（或接入进程发一块 login 画布） | `state=awaiting-human`，**不变** |
| 登录成功（甲） | `space/甲.state：inactive→active`（其他空间保持 inactive） | 甲的画布逐个 `show` | **不变** |
| 登出 / 锁屏 | `space/甲.state：active→inactive` | 甲的画布全部 `retract` | **不变** |
| 换人（甲→乙） | 甲 → inactive、乙 → active | 甲的 `retract`、乙的 `show` | **不变** |
| 多屏 | 每块屏各自一套空间/画布；空间可同时在多块屏 active（镜像） | 各屏各自 shown 集合 | 每屏一个，各自不变 |

★ 依据：书 §4.3「身份由入口给出，请求说了不算」；系统用户名/uid ≠ 世界身份（`world://user`）。**不为“还没出现的人”编造身份。**

## §七 合成器何时升成类（触发条件，先写死）

| 触发 | 做法 |
|---|---|
| 一个合成器服务多块屏/多个人 | 加 `compositor` 类（name/host/kind/state）＋链接 `compositor-renders-presentation`（1:N）；`presentation` 去掉 `compositor_kind` 格 |
| 远端渲染（别的机器/客户端来画） | 同上（它要被按 id 找到、授权、记账） |
| 要按合成器查询/追责（“谁在画”“换回来”） | 同上 |

★ 现在**先用 `compositor_kind` 一格**；换它落一条 `change` 即可追溯。依据：书 §总则八“本体只收已被重复使用的东西”。

### §七·补 术语与归属（作者本轮问）

| 问 | 答 |
|---|---|
| **合成器归谁？** | **不归人**。它是“呈现”的实现：呈现有 `host→device/computer`；合成器跟着呈现走，改它落 change（`compositor_kind` before→after）。只有升成共享设施时才需要记“谁拥有/谁运行”（可能归机器/管理员）。 |
| **个人爱好/布局放哪？** | **放个人空间（space）**。依据：书 §4.4「读法可以有自己的显示偏好……这些偏好不影响它摆出来的内容」＝偏好≠内容；换合成器（浏览器→GTK）时偏好不能丢 ⇒ 偏好跟人（space）。合成器**只执行** layout。 |
| **渲染器是什么？** | 把 **A2UI 描述**翻成**原生控件**的那一层（DOM／GTK／Flutter widget）——“解释描述”。 |
| **合成器是什么？** | 把**多块画面**按 layout 叠成**一张屏**的那一层——“拼版”。 |
| **必须分开吗？能合吗？** | **不必分开；可以合，而且现在就合着**：`render/a2ui-live.html`＋`a2ui-renderer.mjs` 里浏览器既翻控件又合成页面（10-18 结论“GUI＝合成器＝浏览器里的渲染器”）。概念上分两个角色，实现上可合一个进程；将来“一器多屏/多人、远端、多后端”再拆模块（仍不必拆成两个本体类）。 |
| **本体里要几个类？** | **一个都不新增**：现在只留 `presentation.compositor_kind` 一格；要升只升“合成器/呈现实现”一个类（见 §七）。 |
