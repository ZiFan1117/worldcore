## 一、★★★ I2BA：**"语义的意图 → 受限动作"架构**（原文现取）

★ **题目逐字**：★ 「**I2BA: A Semantic Intent-to-Bounded-Action Architecture for Agentic Systems**」（★ Aleksandar Bakalov，★ 2026-09-19）

### 摘要要点（逐字还原）

> ★ "**reconciles those goals with a machine-readable bounded action space**, produces a **typed ActionPlan**, and **hands only validated operations across a host-owned authority boundary to closed effectors**."
> ★ "Results return through **the target system normal state model** rather than remaining isolated in an agent transcript."
> ★ "Its contribution is their **integration into a single semantic control plane** with first-class **goal accounting (planned, needs-input, unsupported)**, dialogue …, **exact revision binding** for capability…"

### 结论段（逐字，★ 这一段最关键）

> ★★ "I2BA does **not replace** MCP, AICP, AG-UI, A2UI, A2A, OpenAPI, WoT descriptions, or native application APIs. **It provides the semantic control plane in which those mechanisms can serve as capability sources, execution bindings, transports, coordination layers, or renderers.**"

### ★★★ 与我们逐条对

| ★ I2BA | ★ 我们 |
|---|---|
| ★★★ **the semantic control plane**（语义控制面） | ★★★ **本体 ＋ 总线** —— ★ **同一个词** |
| ★★ **machine-readable bounded action space** | ★★ **本体里的 `actions`（9 个在册动作）** |
| ★★★ **hands only validated operations across a host-owned authority boundary to closed effectors** | ★★★ **执行面：先问治理 ⇒ 查动作在册 ⇒ 找函数 ⇒ 调函数 ⇒ 才交效应器** |
| ★★ **preserves missing or unsupported goals rather than silently dropping them** | ★★ **我们的"拒的每一档"** ⇒ ★ **不许静默放行**（★ 与本仓 C6 那条同旨） |
| ★★★ **separates interpretation from execution authority** | ★★★ **解释面与执行面分开；执行必须自己问治理** |
| ★★ **exact revision binding** | ★★★ **我们的 `vocab_hash`（词表版本绑定）** |
| ★★ **goal accounting（planned／needs-input／unsupported）** | ★★ **我们 `Reason` 的八档** |
| ★★ **intent 可来自 human／agent／workflow／event／controller** | ★★ **我们的"谁"（`Who`）** |
| ★★★ **不替代 MCP／AG-UI／A2UI／A2A／OpenAPI…，而是让它当能力来源／执行绑定／传输／渲染器** | ★★★ **正是作者"能借的尽量借"的口径** —— ★ **有学术依据了** ✓ |

## 二、★★★ AIM：**"意图怎么写"的语言**（仓内逐字）

★ **它现在的全名**：★ 「**Agentic Intent Model (AIM) v5.9**」
★ **逐字**：★ "**Formerly Application Intent Model — renamed when the language generalized beyond software.**"

### 要点（逐字）

| ★ 条 | ★ 逐字 |
|---|---|
| ★★ 定位 | ★ "AIM is a **specification language for humans and AI agents**. It captures the **intent** of a system" |
| ★★ 为什么要 | ★ "Ground agents in **explicit, versioned intent** instead of loose chat context that **evaporates between sessions**" |
| ★★ 图 | ★ "A **relation graph, not just a tree**. AIM treats every `.aim` file as a **projection of a node-and-edge graph**" |
| ★★ 漂移 | ★ "**Drift as graph-diff**… review becomes a **diff** between the declared…" |
| ★★★ 权威 | ★ "**Behavioral truth lives in `.aim` files** … These are the **only files that define what the system**…" ＋ "`.md` files (including this one) are **explanatory, never authoritative**" |
| ★★★ 拒启 | ★ "Try the **local cache first** … Fall back to the **canonical URL** … **If neither resolves, refuse to proceed — operating against an unknown specification is unsafe.**" |
| ★★ 绑定 | ★ "**Intent↔realization binding layer**"（★ 每个节点有 `### Bindings` 属性，带 **provenance**） |

### ★★★ 与我们逐条对

| ★ AIM | ★ 我们 |
|---|---|
| ★★★ **explicit, versioned intent** | ★★★ **本体 ＋ `vocab_hash`** |
| ★★★ **对不上规格就拒（refuse to proceed）** | ★★★ **"词表版本对不上即拒"** —— ★ **同一个模式** |
| ★★★ **只有行为真相文件是权威，解释性文件永远不是** | ★★★ **"本体是唯一权威；正文里不许写结论"** |
| ★★ **每个 `.aim` 是图的投影** | ★★ **界面／总线消息是本体的投影** |
| ★★ **intent↔realization Bindings（带 provenance）** | ★★ **声明↔实现绑定（改动对照 ＋ 逐笔登记）** |
| ★★ **Drift as graph-diff** | ★★ **C1 上游一致性差分** |
| ★★ **先本地缓存 → 再权威 URL → 都不行就拒** | ★★ **启动即装载；装不上不许启动** |

| ★ 项 | ★ 现取 |
|---|---|
| ★ 定位 | ★ **Agent to UI**（`a2ui.org`，★ 规范 v0.9.1（当前）／v1.0（候选）） |
| ★★ 形状 | ★★ **一段 JSON**：`createSurface` ＋ `updateComponents`（★ 组件树） |

### ★★★ 与我们的接法

```
★★★ 我们的本体（objects／actions／interfaces／functions）
        ↓ ★★★ 投影／生成   ← 【这是我们的活】
★★ A2UI 消息（createSurface ＋ updateComponents，一串 JSON）
        ↓ 渲染   ← 【用 A2UI 现成 renderers】
★ 屏幕上的界面
```

| ★ 我们的本体 | ★ 投影成什么界面 |
|---|---|
| ★ `objects` 的每一类 | ★ 列表／详情视图 |
| ★ `actions` 的每个动作 | ★ 一组按钮／一个表单 |
| ★ 动作的 `inputs`（含取值域） | ★ 表单字段（★ **取值域就是校验**） |
| ★ `interfaces`（能力） | ★ 权限相关的可见性（★ 没权就不出现） |

## 四、★★★★★ 三件合起来（这就是作者要的"统一"）

| ★ 件 | ★ 管什么 |
|---|---|
| ★★★ **AIM** | ★ **意图怎么写**（显式／带版本／图／权威只在行为真相文件／**对不上就拒**） |
| ★★★ **I2BA** | ★ **意图怎么变成受限动作**（受限动作空间／权威边界／目标记账／**语义控制面**） |
| ★★★ **A2UI** | ★ **界面怎么由数据描述**（界面即数据 ⇒ **界面可投影**） |
| ★★ A2B（Agent to Business）／AG-UI／MCP／A2A | ★ 到业务／交互／工具／Agent |
| ★★★ **我们的本体（`aios-worldcore`）** | ★★★ **"这个世界里有哪些类／动作／能力／函数／权限"** ⇒ ★ **上面所有的语义底** |

### ★★★ 一句话

> ★★★ **它们管「怎么写、怎么变、怎么画」；★ 我们管「这个世界里什么算数」。**
> ★★ 而★ **I2BA 的原文替作者的口径写了背书**：★ **它不替代那几件，而是**提供语义控制面**，让它们当能力来源／执行绑定／传输／渲染器** ✓
