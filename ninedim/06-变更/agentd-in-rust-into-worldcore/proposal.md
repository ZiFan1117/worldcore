## Why

**不改的后果（可观察的事实）**：作者已下三句裁定（2026-09-28，逐字）——

1. 「**world-core 应该有 agentd**」
2. 「**agentd 属世界核心**」
3. 「**这个 Agent 必须使用 rust 写，而且它必须属于这个 world core**」＋「**agentd 和其他内容一样归纳到相应代码位置**」

而不改的后果是**两条同时成立**：

- **能力面缺席**：`ninedim/01-意图环/04-规格/` 下**零条**承诺覆盖 Agent 的那一层（能力声明即授权、
  风险分级处置顺序、完工铃、结构化审计字段、动手前快照、结构化请求/应答通道）。
  实测：规格树下 `### Requirement` 共 **49** 条（`generated/BRIDGE.md` §七 第 7 行现算），
  其中提到 Agent／job／完工铃／审计字段的**一条也没有**。
- **实现面缺席**：`**` 下 **0 个 `.go`**、**0 个** Agent 运行时模块。
  那一层能力今天的唯一实现是**仓根 `agentd/`（Go，8 个包）**——而按裁定三，
  仓根那套**不再作为独立组件**（其能力面归入相应模块，旧件随 git 历史留存）。

⇒ 不改，就是把作者已经裁定的两件事（**Rust 实现** ＋ **归入 world-core 的相应代码位置**）
停在"已登记、待立件"的状态上，而世界上没有任何一条承诺或一行实现。

## What Changes

**分四笔，逐笔可核**：

1. **规格面**：新增能力 `agent-runtime`（delta 落在本 change 的
   `specs/agent-runtime/spec.md`），把 Agent 那一层**今天就能成立的行为**写成
   `### Requirement` ＋ `#### Scenario` ＋ **真实存在的**证据行。
   新能力的 Requirement 按本项目现行规矩逐条登记为「**无号·待流程侧增补**」
   （不造号、不拿相近号硬凑），并进 `generated/BRIDGE.md` 的在册面。
2. **实现面（Rust）**：在 `src/agent/` 下逐模块实现，
   **与原 Go 8 个包的能力面一一对应**（落位表见 `design.md`）；每条能力面**带会红的判据**。
3. **仓根 Go 退场**：`agentd/`（Go，8 包）不再作独立组件；**连带归位**：
   仓根 `check.sh`、`README.md`、`.gitignore`（里面的 `agentd/` 那条）、
   `.scope-declaration.json`、`REF-07-02` 登记、CI 的 `working-directory`。
4. **文档口径改写**：`WC-FSR-001`／`WC-SDP-001`／`WC-SCMP-001`／`WC-IRS-001`／`WC-SQAP-001`
   五件里**被裁定推翻的措辞**逐条改写，每条留**让路三要素**（让的是哪一条／为什么让／
   **谁批的＝作者**）。

**BREAKING**：对本仓的使用方而言，`agentd` 的**入口形态**从「仓根一个独立 Go 程序」
变为「`world-core` 内的 Rust 模块」⇒ 调用方式改变。**使用方只有本仓自己**
（仓根 `README.md`／`check.sh` 与 CI 是全部引用点），故通知面＝这三处，随本件一并改。

## Capabilities

### New Capabilities

- `agent-runtime`: Agent 运行时的**对外可核行为**——①能力声明即授权（白名单外的能力/动词一律拒绝，
  且拒绝可判）②风险与确认决定处置顺序（先审计意图 → 需确认则确认 → 高危动手前快照 → 转发 →
  审计动作）③完工铃不丢（活儿在订阅之前干完，铃也必须补发）④审计记录字段固定且**一条记录占一行**
  ⑤登记簿落盘且重启后把未跑完的记为 lost ⑥结构化请求/结构化应答，一行一问一答
  ⑦快照是"动手前"的，失败即不执行且留痕。

### Modified Capabilities

无——本件不改既有 9 个能力的规格级行为（它们是账本/门禁/读模型/投影/通道身份等**世界**那一层；
本件加的是**Agent 运行时**那一层，两层各自成立）。
