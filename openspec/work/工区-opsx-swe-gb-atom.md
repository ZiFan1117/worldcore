# 工区登记 · `wt/opsx-swe-gb-atom`（本档的独立工作树）

> **本件是工区登记，不是规格、不是流程交付物、不是 change 产物。**
> 它**不进规格树**（`openspec/specs/**`）、**不进任何 change**、`spec_bridge.py` 不读它。
> 挂在 `world-core/docs/理论/` 下是因为该目录已是本册的**派生工作件**落脚处（`理念条目.md`／`冲突总账.md` 同在）。

## 一、为什么建这棵树（**两次事故长出来的**）

**事故（两次同形态，2026-09-28）**：我在**共享主工作区**里 `git add` 自己的件之后、`git commit` 之前，
**另一条线在同一段窗口里 `commit`** ⇒ **我的暂存被它的提交卷走**：
- 第一次：我那批（`opsx-swe-gb-atom/**` ＋ `冲突总账.md`）被 **`72c0269`** 卷走；
- 第二次：被 **`74dc9bc`** 卷走。
两次 `git commit` 都因此输出 **「no changes added to commit」**。**事故台账见 `冲突总账.md` §7.18。**

**根因（一条）**：**两条线共用同一棵树 ＋ 共享同一个 index（暂存区）**，
而 `git add` 与 `git commit` 之间**不是原子的**。

**⇒ 已证伪的办法**：`冲突总账.md` §7.18 原提的「提交前两步核 ＋ 提交后数文件」
**只能事后发现，不能预防** ✗（两次都没拦住）。

**⇒ 结构性解法（作者已批）**：**每条线各自独占一棵工作树**——
`git worktree` 给每棵树**自己的 index** ⇒ 不存在"别人 commit 我的暂存"这件事。

## 三、本树里的提交纪律（作者裁定，立即生效）

1. `git add` **一次一条命令、只写自己的声明路径** ✗ 禁止 `-A`／`-u`／`.`；
2. **提交前**看 `git diff --cached --name-only`；**提交后**才核 `git show --name-only HEAD`；
3. **推送**：先 `git fetch` ⇒ 核 `origin/main` 是否已前进 ⇒ **`git pull --rebase`** ⇒ 再推；
4. **禁止** `--amend` 已推送的历史 ✗；**禁止**改写别人的提交 ✗；
5. 别人的件里发现问题：**只登记、不动手**（skill §十四）。

## 四、本件不能证明的事

- 它**不能**证明"以后再也不会发生暂存被卷走"——**它只把发生条件去掉**（不再共享 index）；
  若有人**同时在这棵树里干活**，问题会以别的形态回来。
- 它**不是**"工区已隔离"的机器判据：**没有任何门禁会读本件**（`spec_bridge.py` 不读 `world-core/docs/理论/**`）。
