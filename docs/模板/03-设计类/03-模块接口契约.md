# 模块接口契约（IC）

> **文档编号规则**：`<项目代号>-IC-<顺序号>-v<主版本>.<次版本>`；单模块可拆分为 `<项目代号>-IC-<模块号>-v<主版本>.<次版本>`，示例 `<项目代号>-IC-M20-v0.1`（规则见 §0.3）
> **适用阶段**：**S2 框架设计**逐模块定义（**R2 框架评审**准出材料）；**S3 骨架跑通**按契约装配 Mock；**S4 模块实现**以契约为验收基准；**每次契约变更**走 **R5 框架变更评审**

## 零、使用说明（填完全文后请删除本章）

### 0.1 🔒 契约的地位（先读这一条）

> **契约是框架与模块之间的唯一法定接口。**
>
> **改契约 = 框架变更，必须走 R5 变更评审。**
>
> 这意味着：
> - 契约**不是**模块实现者的私有文档，**不得**在编码过程中"顺手改一下"；
> - 未经 R5 批准的契约偏差，即使代码能跑通，**R4 模块评审也不得通过**；
> - 契约变更必须在**同一次提交**里同步更新：本文件 + `01-软件概要设计说明.md` + `02-模块清单与模块号登记表.md` + `../02-需求类/03-需求追溯矩阵.csv`。

**为什么这么严**：框架的健康度取决于契约的稳定性。契约一旦可以随意改，
"框架—模块共演化"立刻退化为"人人各自改框架"，集成成本指数上升
（见 `docs/01-流程与阶段/框架与模块共演化.md` §七「静默改框架」反模式）。

### 0.2 什么时候必须提 R5（契约变更触发条件）

| 触发条件编号 | 场景 | 是否必须走 R5 |
|---|---|---|
| `FC-1` | **契约不足**：现有接口无法表达真实数据流，只能靠 hack 传递 | ✅ 必须 |
| `FC-2` | **职责错位**：某功能在现有模块划分下无处安放，或必然造成双向依赖 | ✅ 必须 |
| `FC-3` | **假设被推翻**：契约中声明的假设（同步/幂等/线程模型）被实现证伪 | ✅ 必须 |
| `FC-4` | **重复实现**：第 3 个模块出现同一段逻辑的第 3 次复制 | ✅ 应该（抽取到框架层） |
| `FC-5` | **测试不可达**：模块无法被独立测试（依赖写死、不可注入） | ✅ 应该 |
| `FC-6` | **个人偏好**："我觉得这样更优雅" | ❌ **一律驳回**，记入技术债清单 |

**变更动作（七步，不可跳）**：提申请 → 影响分析 → 技术评审（≥ 2 案对比）→ 批准/驳回 →
实施（改代码 + 同步改本文件与 HLD）→ 回归验证 → 新基线冻结（`framework/vN+1`）。

## 一、契约通则（适用于全部模块契约）

| 编号 | 通则 | 说明 |
|---|---|---|
| CT-01 | **契约唯一** | 模块之间**只允许通过契约通信**，禁止直接访问对方内部数据结构、内部类、内部表 |
| CT-02 | **异常成对** | 契约中的每个接口必须定义**成功路径 + 异常路径**；只有成功路径的契约视为未完成 |
| CT-03 | **错误码稳定** | 错误码一经发布不得改语义、不得复用；废弃错误码保留行并标注替代码 |
| CT-04 | **输入必校验** | 契约必须声明对输入的前置校验责任方（调用方 or 提供方），**不得双方都不校验** |
| CT-05 | **显式幂等** | 每个接口必须显式声明幂等性（是/否）；非幂等接口必须给出"禁止自动重试"的约束 |
| CT-06 | **线程假设显式** | 必须声明模块的线程安全级别与调用方并发约束；**默认不安全**，安全必须显式声明 |
| CT-07 | **性能可测** | 必须给出可度量的性能约束（指标 + 度量条件），否则无法验证 |
| CT-08 | **可 Mock** | 契约必须支持以桩/Mock 实现（S3 骨架用），即依赖必须可注入 |
| CT-09 | **变更受控** | 任何契约变更 = 框架变更，必须走 R5（见 §0.1、§0.2） |
| CT-10 | **文档同版** | 契约与代码**同一次提交**更新；文档滞后提交数必须为 0 |

#### 2. 职责（负责什么）

用一句话 + 要点清单说明该模块**负责**的事。职责必须可判定：一条职责若无法判断"是否属于本模块"，就不是合格的职责描述。

| 编号 | 职责 | 可判定说明 |
|---|---|---|
| R-01 | 例如：校验账号口令并建立会话 | 输入账号口令，输出会话令牌或错误码 |
| R-02 | 例如：维护登录失败计数与锁定策略 | 失败计数与锁定状态的唯一写入方 |

#### 3. 非职责（明确不负责什么）⚠️ 必填

> **这一节比上一节更重要。** 不写清"不负责什么"，模块边界会在实现阶段被不断侵蚀，
> 最终演变成"什么都在这个模块里"的上帝模块，或者两个模块互相以为对方做了校验。

| 编号 | 不负责的事项 | 由谁负责 | 若误放在本模块的后果 |
|---|---|---|---|
| N-01 | 例如：不负责终端用户的权限判定（仅认证身份，不判权） | `<M21>` 授权服务 | 认证与授权耦合，权限变更需改认证模块 |
| N-02 | 例如：不负责口令强度策略校验（由注册/改密流程负责） | `<M22>` 用户管理 | 策略变更引发认证模块回归 |
| N-03 | 例如：不负责发送通知短信/邮件 | `<M70>` 通知服务 | 引入外部依赖，违反分层 |
| N-04 | 例如：不直接访问数据库表，一律经 `<M40>` | `<M40>` 仓储 | 破坏分层，数据访问逻辑分散 |

#### 4. 输入

| 接口编号 | 入参 | 类型 | 必填 | 取值范围/约束 | 校验责任方 | 说明 |
|---|---|---|---|---|---|---|

| `<IF-001>` | `password` | string | 是 | 8–64 | 提供方 | 日志必须掩码 |
| `<IF-001>` | `client_ip` | string | 否 | IPv4/IPv6 | 调用方 | 用于风控 |

#### 5. 输出

| 接口编号 | 出参 | 类型 | 必返 | 说明 |
|---|---|---|---|---|
| `<IF-001>` | `token` | string | 成功时是 | 会话令牌（JWT） |
| `<IF-001>` | `expires_in` | integer | 成功时是 | 有效期（秒） |
| `<IF-001>` | `user.roles` | array[string] | 成功时是 | 角色码列表，可为空数组 |
| `<IF-001>` | `code` / `message` / `trace_id` | string | 失败时是 | 业务错误码 / 可读消息 / 链路 ID |

#### 6. 异常与错误码

| 错误码 | 触发条件 | HTTP/返回形态 | 调用方期望处置 | 可重试 | 是否记审计 |
|---|---|---|---|---|---|
| `AUTH-4001` | 入参格式不合规 | 400 | 修正入参 | 否 | 否 |
| `AUTH-4011` | 账号不存在**或**口令错误（不区分） | 401 | 提示"账号或口令错误" | 否 | 是（WARN） |
| `AUTH-4231` | 连续 5 次失败锁定 15min | 423 + `retry_after` | 等待后重试 | 是（延时） | 是 |
| `AUTH-5001` | 下游认证服务不可用 | 503 | 重试 ≤ 1 次 | 是 | 是（ERROR） |
| `AUTH-5002` | 未预期内部异常 | 500 | 记录 `trace_id` 报障 | 否 | 是（ERROR） |

**异常处理约定**

| 项 | 约定 |
|---|---|
| 异常传播 | 本模块内部异常**不得**原样抛出跨模块；必须映射为契约错误码 |
| 兜底 | 未映射异常统一转 `AUTH-5002`，并记录完整堆栈到日志（不返回给调用方） |
| 空值语义 | `null` 与"空字符串"必须区分并显式定义 |

#### 8. 幂等性

| 接口编号 | 是否幂等 | 幂等键 | 重复调用影响 | 调用方约束 |
|---|---|---|---|---|
| `<IF-001>` | **否** | 不适用 | 成功则刷新令牌；失败则失败计数继续累加（有意设计） | **禁止盲目自动重试**；仅 `AUTH-5001` 重试 ≤ 1 次 |

#### 9. 线程与并发假设

| 项 | 声明 |
|---|---|
| **线程安全级别** | 不安全 / 条件安全 / 线程安全（**必须显式声明，默认不安全**） |
| 可变共享状态 | 例如：无实例级可变状态；失败计数存于外部存储 |
| 并发调用约束 | 允许并发调用；同一账号的并发登录互不影响 |

| 顺序假设 | 不假设调用顺序；状态判定以外部存储为准 |

## 三、契约符合性验证（模块如何被判定"守约"）

> **R4 模块评审的准出项**：模块行为符合其接口契约。

| 编号 | 验证项 | 方法 | 通过判据 | 阶段 |
|---|---|---|---|---|
| CV-01 | 接口签名一致 | 契约测试 / 编译期检查 | 入参、出参、类型、必填性与契约完全一致 | S4 / CI |
| CV-02 | 错误码覆盖 | 单元 + 集成测试逐码注入 | 契约错误码表中每一码都有对应用例 | S4 / S5 |
| CV-03 | 非职责未被侵入 | 代码走查 + 依赖检查 | 非职责清单中的事项未在本模块实现 | R4 |
| CV-04 | 幂等性 | 重复调用 N 次 | 结果与声明一致 | S5 |
| CV-05 | 线程与并发假设 | 并发测试 / 静态检查 | 与声明一致；无数据竞争 | S4 / S5 |
| CV-06 | 性能约束 | 基准测试 | 满足 §10 指标 | S5 |
| CV-07 | 可 Mock | 骨架中以 Mock 装配 | S3 一条命令跑通 | R3 |
| CV-08 | 文档与代码一致 | 契约 diff | 契约与本文件版本一致，无未登记偏差 | R4 |

> **未通过 CV-01 / CV-03 的模块不得通过 R4。** 契约偏差即使"功能正常"也是缺陷——
> 它会让所有消费方基于错误假设开发。

## 五、填写指引

1. **最常见错误：跳过「非职责」一节。** 这是本模板最重要的一节。只写"负责什么"，模块边界必然在实现阶段膨胀。每条非职责都要写清"由谁负责"和"误放在本模块的后果"。
2. **最常见错误：契约只有成功路径。** 每个接口必须定义错误码表，且覆盖入参错误、认证/权限、依赖故障、限流四类。**没有错误码表的接口 = 未定义的接口。**
3. **最常见错误：把契约当私有文档，随手改。** 改契约 = 框架变更，**必须走 R5**。未经 R5 的契约偏差，R4 模块评审不得通过——**哪怕代码跑得很好**。
4. **最常见错误：不写线程与并发假设。** 默认必须声明为"不安全"。不声明线程模型，会在生产环境以最难复现的方式爆炸（并发丢更新、脏读、死锁）。
5. **最常见错误：幂等性含糊。** 必须二选一：**是 / 否**。非幂等接口要明确"禁止自动重试"或给出幂等键字段。含糊表述会引发重复下单、重复扣款这类事故。
6. **最常见错误：改了契约不改 HLD、模块登记表与 RTM。** 四处必须同一次提交对齐；文档滞后提交数必须为 0，否则追溯链断裂、CI 门禁失败。
